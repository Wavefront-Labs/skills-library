# From ideation to a selected concept — diverge wide, converge on evidence

**Goal:** go from a brief to one or two concepts that solve the real use problem,
fit the internal package, and carry a clear design language, with a selection the
team can defend.

## 1. Frame the problem (before any form)
- Write the **user scenario**: who, where, doing what, with which hand, in what
  conditions (gloves, wet, one-handed, low light). One paragraph per key scenario.
- Turn pains into **"How might we..."** questions (one need per question).
- List hard constraints: package (internal components with dimensions), cost target,
  process (moulded, sheet, machined), standards, brand.
- Build a **package block model** (CAD or foam) of the internals; every concept must
  wrap it.

## 2. Diverge: volume over polish
- **Thumbnails first**: 50-100 small (~5 cm) sketches per question, 1-2 minutes each.
  Silhouette and architecture only, no shading.
- Vary the *architecture*, not just the styling: where the user's hand goes, which way
  it opens, what moves, where the screen sits.
- Use a **morphological chart**: rows = sub-functions (hold, open, charge, display),
  columns = solutions; combine one per row to force new combinations.
- Rough **sketch models** in foam, card or quick prints at 1:1 for anything held,
  worn or reached; scale drawings lie about size.

## 3. Cluster and develop
- Pin everything up; cluster by architecture. Name each cluster.
- Develop the 6-10 strongest into **concept sketches**: perspective with an
  orthographic side view, a section through the package, and a use sketch in context.
- Line weight: heavy for silhouette, medium for parting lines, light for construction;
  use one ellipse/perspective set so concepts are comparable.

## 4. Converge: select with a matrix
**Pugh screening:** choose a datum (current product or the most obvious concept).
Score each concept against each criterion as +, 0, -. Combine strengths, drop
the weak, iterate.

**Weighted scoring** for the shortlist:

| Criterion | Weight | Concept A (1-5) | Concept B (1-5) |
|---|---|---|---|
| Fits use scenario | 30% | 4 | 3 |
| Fits package / feasibility | 25% | 3 | 5 |
| Cost and manufacture | 20% | 3 | 4 |
| Brand / design language | 15% | 5 | 3 |
| Differentiation | 10% | 4 | 2 |
| **Weighted total** | | **3.70** | **3.60** |

A 0.1 difference is a tie: test both with users or a sketch model instead of picking
on the number. Agree weights **before** scoring.

## 5. Define the design language
- **Proportion and stance:** the main ratio and where the visual mass sits.
- **Key lines:** 2-3 lines that define the product; everything else is subordinate.
- **Radius family:** a small set of radii (e.g. large/medium/small in a consistent
  ratio) used everywhere.
- **Surface character:** taut, soft, faceted; consistent across parts.
- **Split and detail strategy:** parting lines, reveals and fasteners treated as design
  features (see enclosure-design).
- **CMF intent:** primary/secondary colour and finish zones (see cmf-design).
Capture it on one sheet so it extends to accessories and future variants.

## Gotchas
- Styling variants of one architecture feel like ideation but aren't.
- Polished renders early make the team defend the render, not the idea.
- Concepts that ignore the package die at engineering review; check section views.
- Matrix scores give false precision; record the reasoning behind each score.
- The person who sketched it shouldn't be the only one scoring it.

## Verify
- [ ] Each concept addresses a written user scenario and "How might we" question.
- [ ] Ideation shows genuinely different architectures, not only styling.
- [ ] Shortlisted concepts wrap the package in a section view.
- [ ] Selection used weights agreed before scoring, with reasons noted.
- [ ] The design language is on one sheet: proportions, key lines, radii, CMF intent.
