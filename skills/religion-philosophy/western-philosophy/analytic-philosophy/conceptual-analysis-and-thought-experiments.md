# Conceptual analysis and thought experiments

**Goal:** run the core working loop of analytic philosophy — state an analysis of a
concept, test it against cases, revise — and design thought experiments that test
what they claim to, so your argument survives a seminar or a referee.

## 1. The analysis–counterexample loop
1. **Pick the target:** "S knows that p", "A caused B", "x is a person", "an action is
   free". Fix the form you are analysing (a sentence schema, not a word).
2. **Propose conditions:** *S knows that p iff (i) p is true, (ii) S believes p,
   (iii) S is justified in believing p.* Each condition should be claimed
   **necessary**; together **sufficient**.
3. **Test necessity:** look for a case where the concept clearly applies but a
   condition fails. (Knowledge without belief? The unconfident examinee — Radford.)
4. **Test sufficiency:** look for a case where all conditions hold but the concept
   clearly does not apply. Gettier (1963): Smith has a justified true belief that
   "the man who will get the job has ten coins in his pocket", true only by luck.
5. **Revise:** add or modify a condition (no false lemmas; safety; sensitivity;
   reliability), then **re-run steps 3–4 on the new analysis**. Track each version in a
   numbered list so you can cite "analysis (A3)".
6. **Decide when to stop:** if every patch generates new counterexamples (the
   post-Gettier literature), consider that the concept may be primitive
   (Williamson: knowledge-first) or better treated by **explication**.

## 2. Designing a fair thought experiment
- **Isolate one variable.** Hold everything constant except the feature at issue
  (Twin Earth varies only the chemical make-up of "water").
- **Strip distracting features:** remove emotionally loaded details unless they are
  the point. Trolley cases change one feature at a time (switch vs footbridge).
- **State the verdict you expect and why** — and check whether a reasonable reader
  would share it. If the intuition is contested, say so; don't rest a premise on it.
- **Check possibility:** the scenario must be coherent (metaphysically or
  nomologically, depending on the claim).
- **Watch for the "intuition pump" objection** (Dennett): would a small, irrelevant
  change of framing flip the verdict? Try it.
- Name the case so it can be discussed ("Fake Barn", "Mary's Room").

## 3. Explication instead of analysis (Carnap)
When ordinary use is vague, replace the concept with a more precise one that:
(1) is **similar** to the original in clear cases, (2) is **exact**, (3) is
**fruitful** for theory, (4) is **simple**. State explicitly which uses you give up.

## 4. Reflective equilibrium
Adjust principles and case judgements against each other until they cohere (Rawls,
Goodman). In a paper: say which judgements you treat as fixed points and which you
are willing to revise.

## 5. Writing it up
- Put the analysis in displayed numbered form; define every technical term once.
- Present the counterexample as a short vignette, then the verdict, then which
  condition it targets.
- Anticipate the standard reply and answer it.
- Cite the canonical case if yours is a variant.

## Gotchas
- A counterexample must be **clear**; a borderline case is weak against a theory
  claiming to handle clear cases only.
- Analysing the word instead of the concept (dictionary definitions) misses the point.
- Experimental philosophy shows some "intuitions" vary across populations and
  framings; if your premise is an intuition, note whether it has been tested.
- Circularity: conditions that use the concept itself ("justified" defined via
  "knowledge") can be acceptable or fatal — flag it.

## Verify
- [ ] Analysis stated as numbered necessary and jointly sufficient conditions.
- [ ] Each condition tested for necessity and the set for sufficiency.
- [ ] Every thought experiment varies one feature and states its expected verdict.
- [ ] Contested intuitions flagged as such.
- [ ] Revisions tracked (A1, A2, …) and re-tested.
