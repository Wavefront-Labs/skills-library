# Using the 5x5 tap code with abbreviations

**Goal:** exchange messages by tapping when sound is the only channel and you can't control
signal length — through a wall, along a pipe, on a table, or with a trapped or non-speaking
person. Tap code only needs counts, which is why it beats Morse (long vs short taps blur
through walls).

## 1. The grid
Letters sit in a 5 × 5 square; **K is dropped and replaced by C**:
```
     1  2  3  4  5
 1   A  B  C  D  E
 2   F  G  H  I  J
 3   L  M  N  O  P
 4   Q  R  S  T  U
 5   V  W  X  Y  Z
```
Each letter = **row taps, short pause, column taps**. `H` = `•• •••` (row 2, column 3).
Memorise only the **first letter of each row: A F L Q V** — the rest is counting along.

## 2. Timing
- Taps within a group: quick and even.
- Between row and column: a **short pause** (about twice the tap interval).
- Between letters: a **longer pause**.
- Between words: longer still, or an agreed separator (historically `X` was often used
  as a sentence break).
- Send **slowly and evenly**; the receiver is counting, and a rushed group becomes a wrong
  letter. Rhythm consistency matters more than speed.

## 3. Starting, acknowledging, correcting
Agree these if you can; if not, these are common conventions (they vary by account):
- **Call:** a distinctive rhythm (e.g. the "shave and a haircut" knock); **answer** with the
  closing two taps so the caller knows someone is listening.
- **Acknowledge** a word or letter with two quick taps; **don't understand / repeat** with a
  rapid burst of many taps.
- **Error:** the sender sends a rapid burst, then restarts the word.

## 4. Abbreviate hard
Each letter costs up to ten taps, so cut letters ruthlessly:
- Drop vowels where the word stays guessable (`PLS`, `THX`, `TMRW`).
- Use agreed short forms: `GN` (good night), `GBU` (a farewell historically used), `Y/N`
  questions answered with a single letter.
- Ask yes/no questions rather than open ones when the other party is weak or the line is
  noisy: `C` (tapped as 1,3) for yes is quicker to agree than spelling YES.
- The receiver may **guess ahead** and acknowledge early; the sender then stops the word.

## 5. Uses beyond the classic story
- **Trapped persons:** rescuers commonly use counted taps for yes/no ("tap once for yes,
  twice for no") — the full grid comes later if the person knows it.
- **Locked-in or non-speaking communication:** a partner points through rows then columns
  (a partner-assisted scanning version of the same grid) and the person signals by blink or tap.
- Through pipes, metal carries far — expect others along the pipe to hear you.

## Gotchas
- Counting errors cluster at 4 vs 5: a learner should write each pair down as received.
- The C/K merge confuses newcomers — tell them up front.
- Echoing structures and machinery noise add phantom taps; repeat crucial words.
- Fatigue: knuckles bruise; tap with an object if available.

## Verify
- [ ] You can tap any letter without a chart using the A F L Q V row starts.
- [ ] A partner decodes a 10-letter message with no more than one error.
- [ ] You can demonstrate a call, an acknowledgement and an error correction.
- [ ] You can compress a 6-word message into abbreviations that the partner still decodes.
