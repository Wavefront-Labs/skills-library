# Linear codes, bounds and Reed-Solomon

**Goal:** design, analyse and decode linear error-correcting codes, and know which
bound says a code is good or impossible.

## 1. Linear codes [n, k, d]_q
A k-dimensional subspace of F_q^n. n = length, k = message symbols, rate R = k/n,
d = minimum Hamming distance = minimum weight of a non-zero codeword (because linear).
Corrects ⌊(d−1)/2⌋ errors **or** d−1 erasures (known-position losses).
- **Generator matrix** G (k × n): codeword = mG. Systematic form `G = [I_k | P]`.
- **Parity-check matrix** H ((n−k) × n): `H c^T = 0` for codewords. From systematic G over
  F_2: `H = [P^T | I_{n−k}]` (over F_q use −P^T).
- **d = smallest number of linearly dependent columns of H.** This is how you compute or
  prove d.

## 2. Syndrome decoding
Received r = c + e. Syndrome `s = H r^T = H e^T` depends only on the error.
Build a table syndrome → lowest-weight error (coset leader); subtract it.
Exponential in n − k: fine for small codes, hopeless for large ones (general decoding is
NP-hard — the hardness behind McEliece-type cryptosystems).

**Hamming [7,4,3] code:** H's columns are all 7 non-zero binary 3-vectors. The syndrome,
read as a binary number, is the position of a single-bit error (with columns ordered 1…7).
Perfect code: it meets the Hamming bound exactly.

## 3. Bounds — what is possible
- **Singleton:** `d ≤ n − k + 1`. Codes meeting it are **MDS** (Reed-Solomon is MDS).
- **Hamming (sphere-packing):** `q^k · Σ_{i=0}^{t} C(n,i)(q−1)^i ≤ q^n`, t = ⌊(d−1)/2⌋.
  Equality ⇒ perfect code (Hamming codes, Golay codes, trivial ones).
- **Gilbert-Varshamov:** good codes *exist* with rate ≈ `1 − H_q(d/n)` — a lower bound;
  random linear codes achieve it with high probability.
- **Shannon capacity** of a binary symmetric channel with flip probability p:
  `C = 1 − H_2(p)`, `H_2(p) = −p log₂ p − (1−p) log₂(1−p)`. Reliable communication is
  possible at any R < C, impossible above. Bounds on d are about worst-case errors;
  capacity is about random errors — don't mix the two.

## 4. Reed-Solomon codes
Over F_q with n ≤ q distinct evaluation points α_1…α_n:
- Message = polynomial m(x) of degree < k; codeword = (m(α_1), …, m(α_n)).
- Two distinct polynomials of degree < k agree on < k points ⇒ `d = n − k + 1` (MDS).
- Corrects up to (n−k)/2 symbol errors, or n − k erasures, or any mix with
  `2·errors + erasures ≤ n − k`.
- Decoding: syndromes → **Berlekamp-Massey** (or Euclid) finds the error-locator
  polynomial → Chien search finds roots → **Forney** gives magnitudes. Berlekamp-Welch is
  the simplest to implement from scratch for small cases.
- **Symbol** errors: over GF(256) one symbol = one byte, so a burst of 8 flipped bits in a
  byte costs one symbol. That's why RS is used for bursty media (CDs, QR codes, storage).
- Practical: Sage `codes.GeneralizedReedSolomonCode(F.list()[:n], k)`, `.decode_to_message()`;
  Python `reedsolo` for byte-level RS.

## 5. Cyclic and BCH codes
Cyclic codes are ideals in `F_q[x]/(x^n − 1)`, generated by g(x) | x^n − 1. BCH codes pick
g(x) with 2t consecutive powers of a primitive root as roots ⇒ d ≥ 2t + 1 (BCH bound).
Cyclic structure gives cheap shift-register encoders.

## Uncertainty notes
Run here: Hamming [7,4,3] (16 codewords, minimum weight 3, syndrome = error position, G H^T = 0,
2^4 x (1+7) = 2^7), RS(15,9) over GF(16) with d = 7 and t = 3 (galois), and `reedsolo` recovering 4
erasures plus 3 errors with 10 parity bytes. `GeneralizedReedSolomonCode(F.list()[:n], k)` and
`decode_to_message` are in the Sage reference (not run: Sage is not installed). Bounds and constructions are
standard textbook results.

## Verify
- [ ] `G H^T = 0` for your matrices.
- [ ] d verified as the minimum weight or minimum dependent columns of H.
- [ ] Parameters checked against Singleton and Hamming bounds.
- [ ] RS decoder corrects ⌊(n−k)/2⌋ injected errors. Beyond that it may raise an error or silently
      return a wrong message (a `galois` RS(15,9) decode of 4 errors, t = 3, returned the wrong message
      without raising), so add a checksum or CRC outside the code.
- [ ] Worst-case (distance) vs random-error (capacity) claims kept separate.
