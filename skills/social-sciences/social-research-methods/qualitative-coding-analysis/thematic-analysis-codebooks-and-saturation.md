# Qualitative coding — choosing an approach, coding in passes, defensible themes

**Goal:** turn transcripts or documents into themes a reader can trust, using an
approach whose assumptions match your question, with a trail someone else could audit.

## 1. Choose the approach before you code
| Approach | Use when | Key output | Reliability stats? |
|---|---|---|---|
| **Reflexive thematic analysis** (Braun & Clarke) | Interpretive question, one analyst or a team building shared interpretation | Themes as patterns of shared meaning | No — they reject kappa as a quality marker for this mode |
| **Codebook / framework analysis** | Applied or policy work, team coding, predefined questions, deadlines | Code × case matrix (framework) | Optional; often used |
| **Grounded theory** (Charmaz/Strauss–Corbin/Glaser variants) | Building a theory of a process; sampling can follow the analysis | Core category and theoretical model | No |
Mixing vocabularies ("we did reflexive TA and achieved kappa 0.8 and saturation") is the
most common reviewer complaint. Name the variant and follow its logic.

## 2. Coding in passes
1. **Familiarise:** read everything once without coding; write a one-paragraph memo per
   transcript (what is going on here?).
2. **First-pass codes:** short, close to the data, often gerunds in grounded theory
   ("managing stigma"). Code the segment that carries meaning — typically a sentence to a
   paragraph, with enough context to stand alone.
3. **Consolidate:** merge synonyms, split overloaded codes, write a definition for each
   (label, definition, include, exclude, example quote). That *is* the codebook.
4. **Constant comparison:** compare each new segment with existing ones in the same code
   and with negative cases. Memo every analytic decision with a date.
5. **Theme development:** cluster codes into candidate themes; draw a thematic map.

## 3. Themes, not topic summaries
A topic summary ("Participants talked about cost") is a bucket. A theme makes a claim
("Cost was framed as a moral test of being a good parent"). Test each theme: does it have
a central organising concept? Could it be stated as a sentence? Are its boundaries clear
against neighbouring themes? Does the data — including disconfirming cases — support it?

## 4. Framework matrix (codebook route)
Rows = cases (participants), columns = codes/subthemes, cells = summarised data with a
transcript reference. Read down columns (pattern across cases) and across rows (within-case
coherence). Keep verbatim quotes keyed to row/column so the report can cite them.

## 5. Team coding
- Double-code 10–20% of transcripts early, compare, discuss disagreements, revise
  definitions; repeat until stable. That proportion is convention, not a rule.
- If you report agreement, Krippendorff's alpha or Cohen's kappa *per code*, on segments
  defined the same way; an overall figure hides weak codes.

## 6. Saturation — say which kind
- **Code saturation** (no new codes) is often reached early — one widely cited study
  (Hennink et al., 2017) found around 9 interviews in a fairly homogeneous sample.
- **Meaning saturation** (understanding of codes stops deepening) took notably longer
  (around 16–24 in that study).
- Track it: a table of new codes per transcript in interview order. Reflexive TA authors
  argue saturation is a poor fit for their method; justify sample size by *information
  power* instead. Do not cite a magic number.

## Gotchas
- Coding interview questions instead of answers produces themes that mirror your guide.
- Counting code frequency and presenting it as prevalence misleads with purposive samples.
- Quotes from the most articulate two participants dominating the write-up — check spread.

## Verify
- [ ] Named approach and variant, with assumptions consistent throughout.
- [ ] Codebook with definitions, inclusion/exclusion and examples, versioned.
- [ ] Dated memo trail linking codes → themes.
- [ ] Each theme states a claim and includes considered negative cases.
- [ ] Saturation (type stated) or information power justified with evidence.
- [ ] Quotes spread across participants and tagged by ID.
