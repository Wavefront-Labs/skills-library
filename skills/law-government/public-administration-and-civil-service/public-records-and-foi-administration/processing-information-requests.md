# Processing information requests (FOI / public records)

**Goal:** answer each request lawfully, on time, with a search you can describe and
exemptions you can justify to a reviewer or commissioner.

Statutes differ (US FOIA and state open-records laws, UK FOIA and EIR, Australian, Canadian,
Indian RTI and many others) in deadlines, fee rules, exemption lists and whether a public
interest test applies. Personal data requests usually follow a separate data-protection
regime. The workflow below is common; the statute governs every detail.

## 1. Log and read the request
- Log on receipt; the statutory clock (often 20 working days, varies) usually starts then.
- Is it a valid request under the law (in writing, name, address for reply, describes the
  information)? Requesters don't need to cite the law or give reasons in most regimes.
- Is it really an FOI request, or a request for the requester's own personal data, or
  environmental information under a different regime? Route correctly.
- If unclear, **clarify promptly**; in many systems the clock pauses until clarified. Offer
  help to narrow (duty to advise and assist).

## 2. Search
- Identify likely holders: teams, systems, email, shared drives, messaging apps on official
  business, contractors holding information on your behalf.
- Record search terms, locations, dates, and who searched. A documented search is the main
  defence when a requester says "you must have more".
- Estimate cost/time against any cost limit early; if over, say so and help narrow rather
  than silently refusing.

## 3. Apply exemptions properly
For each withheld item:
1. Identify the specific exemption and subsection.
2. If it's **prejudice/harm-based**, explain the causal link between disclosure and the harm,
   and its likelihood. Not just "could be sensitive".
3. If **qualified**, run the **public interest test**: list factors for and against
   disclosure, weigh them, record the conclusion. Embarrassment to the agency is not a
   valid factor against.
4. **Neither confirm nor deny** only when confirming existence itself would cause the harm.
Withhold the minimum: redact parts rather than withholding whole documents.

## 4. Redact safely
- Use proper redaction tools that remove underlying text, then check: copy-paste the redacted
  area, search for redacted terms, strip metadata and tracked changes, check embedded
  spreadsheets and images.
- Black boxes over text in a PDF layer, without flattening, is the classic leak.
- Record the exemption against each redaction (some regimes require it on the face of the page).

## 5. Respond
State what is disclosed, what is withheld and under which exemption with reasons, and the
right to internal review and then to the regulator or court, with deadlines. Respond within
time or send any permitted extension notice before the deadline.

## 6. Internal review
Reviewer not involved in the original decision; reconsider search and exemptions afresh;
disclose more if warranted.

## Gotchas
- Treating "we don't hold it" as an answer without a documented search.
- Personal data of third parties: apply the data-protection-based exemption, not general secrecy.
- Records retention: destroying information after a request arrives can be an offence.

## Verify
- [ ] Logged, valid, correctly routed; clock and deadline recorded.
- [ ] Search documented (where, terms, who).
- [ ] Each exemption cited with harm and public-interest reasoning where required.
- [ ] Redaction verified as irreversible; metadata removed.
- [ ] Response includes review and appeal rights.
