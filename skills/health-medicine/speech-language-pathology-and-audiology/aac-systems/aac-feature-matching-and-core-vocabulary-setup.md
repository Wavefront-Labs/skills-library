# AAC feature matching and core vocabulary setup

> General clinical/professional reference, not a substitute for independent clinical judgement, current guidelines, or verified dosing references.

**Goal:** give the person a system they can physically access, that holds enough
language to grow into, and that their communication partners actually model and use.

## 1. Assessment (participation model)
- **Participation patterns and needs:** where, with whom, what for (requesting,
  commenting, protesting, social closeness, information) — now and in a year.
- **Current communication:** gestures, sounds, signs, low-tech — map on the
  Communication Matrix (for early communicators).
- **Capabilities:** language comprehension, literacy, vision (size, field, contrast),
  hearing, motor (most reliable body part), cognition/attention, positioning.
- **Barriers:** opportunity (policy, practice, partner skill, attitudes) as well as access.
- **No prerequisites:** AAC does not require a minimum cognitive level, and it does not
  stop speech developing (evidence suggests it can support it).

## 2. Feature matching
Match person's capabilities to system features:
| Feature | Options |
|---|---|
| **Access** | Direct touch (keyguard for accuracy), head pointer, **eye gaze** (calibration, lighting), **switch scanning** (row-column, partner-assisted auditory scanning) |
| Display | Grid size, symbol set (PCS, SymbolStix, Widgit), text-based for literate users |
| Organisation | Core-word pages, topic/visual scene displays, pragmatic organisation (PODD) |
| Output | Synthetic vs recorded speech, voice banking/message banking for degenerative conditions |
| Portability, mounting, durability, battery life | |

Include **low-tech backup** (core board, alphabet board, PODD book) for charging,
bathroom, pool, power failure.

## 3. Vocabulary setup
- **Core vocabulary** (~ 200–400 high-frequency words: I, want, more, stop, go, not,
  like, help, that, what…) makes up most of what people say; **fringe** words are
  topic-specific.
- **Stable motor plans:** keep word locations fixed as vocabulary grows — hide/reveal
  rather than move (LAMP Words for Life, TD Snap Core First, Proloquo2Go Crescendo,
  Grid 3 Super Core). Moving icons destroys automaticity.
- Start with a vocabulary set larger than the person can use now, with unused
  cells masked, so the layout doesn't change later.
- Include ways to say no/stop, ask for help, and comment — not only request.
- For literate users: keyboard + word prediction + quick phrases; for degenerative
  conditions (MND/ALS) plan for later access change (touch → eye gaze/switch) early.

## 4. Device trial
- Trial **2+ systems** over weeks in real settings with a goal list; collect data on
  spontaneous use, accuracy, partner reports. Funding bodies usually require trial
  evidence.

## 5. Implementation
- **Aided language modelling:** partners point to symbols while talking, without
  demanding imitation. Expect many models before spontaneous use.
- Partner training for family, school, care staff; post the core board everywhere.
- Device always available ("AAC is their voice — never removed as punishment, never in
  the bag").
- Assign a device owner for updates, backups (cloud backup of vocabulary file), and
  charging routine.

## Gotchas
- Choosing the device first, then fitting the person to it.
- Requests-only vocabulary → limited communication functions.
- Moving icons with each update → loss of motor automaticity.
- No low-tech backup; device on charge = no voice.
- Eye-gaze trials in bright window light (calibration failure).

## Verify
- [ ] Participation needs and capability profile documented.
- [ ] Feature-matching table completed; at least two systems trialled.
- [ ] Vocabulary has core + fringe, stable locations, multiple functions.
- [ ] Partner training and modelling plan in place; low-tech backup available.
- [ ] Backup of vocabulary file and charging routine assigned.
