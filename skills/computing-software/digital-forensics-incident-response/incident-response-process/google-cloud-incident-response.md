# Google Cloud incident response

**Goal:** investigate and contain GCP project or organisation compromise.

## Preparation
- Audit logs: Admin Activity and System Event logs are always written and cannot be disabled; they are stored in the
  `_Required` bucket. Policy Denied logs are generated by default (you can exclude them with sink filters). Data
  Access logs record reads of configuration and user data; except for BigQuery they are **disabled by default** and
  must be enabled explicitly (extra log charges may apply), then are stored in `_Default` unless routed elsewhere.
- Route audit logs to a protected destination with a sink; aggregated sinks cover an organisation or folder.
- Reading Data Access logs in `_Default` needs the Private Logs Viewer role (`roles/logging.privateLogViewer`);
  Logs Viewer alone cannot.
- Security Command Center is Google's centralised vulnerability and threat reporting service, with threat detection
  among its services.
- The organisation policy constraint `iam.disableServiceAccountKeyCreation` (legacy managed constraint; there is
  also a managed `iam.managed.disableServiceAccountKeyCreation`) blocks creation of new external service account
  keys and Cloud Storage HMAC keys.

## Investigate
Every audit log entry is a `LogEntry` whose `protoPayload` holds an `AuditLog`; the caller identity is in
`authenticationInfo` (`principalEmail`) and the called API is `methodName`.
```bash
gcloud logging read 'protoPayload.authenticationInfo.principalEmail="sa@proj.iam.gserviceaccount.com"' \
  --project=proj --freshness=30d --format=json > sa_activity.json
gcloud logging read 'protoPayload.methodName="google.iam.admin.v1.CreateServiceAccountKey"' --organization=ORG_ID --freshness=30d
```
Persistence to look for: new service account keys, IAM policy changes granting external principals, new projects,
new compute or serverless resources in unusual regions, project metadata changes. Check the exact `methodName`
strings in the log entries you find; do not assume them.

## Contain
- Disable service account keys and the service account (`gcloud iam service-accounts keys disable`, `gcloud iam
  service-accounts disable`); remove malicious IAM bindings; suspend users in the identity provider.
- VM: isolate with network tags and firewall rules, snapshot disks (`gcloud compute disks snapshot`), keep running
  for memory if possible.

## Gotchas
- Data Access logs are the only record of data reads; if they were off, data access is unknown.
- Resources that are publicly accessible (for example IAM policies with `allUsers` or `allAuthenticatedUsers`) do
  not generate audit logs.
- Admin Activity and System Event logs routed to another project do not pass through that project's `_Required` or
  `_Default` sinks: create a sink there to store them.
- For retention periods, see the Cloud Logging "Quotas and limits: Logs retention periods" page.

## Verify
Logs show no successful calls by contained principals; `gcloud projects get-iam-policy`
matches the approved baseline.
