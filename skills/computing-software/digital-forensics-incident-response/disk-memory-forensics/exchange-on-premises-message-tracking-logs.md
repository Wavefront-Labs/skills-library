# Exchange on-premises message tracking logs

**Goal:** find who sent or received a message, where it went and whether it was redirected, using the
message tracking log on on-premises Exchange (Mailbox and Edge Transport servers; the Learn article covers
Exchange Server 2016, 2019 and Subscription Edition).

## Query
```powershell
Get-MessageTrackingLog -Server Mailbox01 -Start "03/13/2024 09:00:00" -End "03/15/2024 17:00:00" -Sender "john@contoso.com" -ResultSize Unlimited |
  Select-Object Timestamp, EventId, Source, Sender, Recipients, MessageSubject, MessageId, ClientIp, ServerHostname, TotalBytes |
  ConvertTo-Csv > track.csv
Get-MessageTrackingLog -Server Mailbox01 -MessageId "<id@contoso.com>" -ResultSize Unlimited   # follow one message
```
- Without `-Server` the cmdlet runs on the local server only, so repeat it for each Mailbox and Edge server.
- `-Start`/`-End` use the short date format of the machine's regional settings; `-End` is exclusive.
- `-ResultSize` is limited by default (the page says 1000); use `Unlimited` for everything.
- Other filters: `-EventId`, `-Source`, `-Recipients` (array), `-InternalMessageId`, `-NetworkMessageId`,
  `-Reference`, `-MessageSubject` (partial match). Include the full `-MessageId` string, quoted.
- Output names drop the dashes of the raw fields; `date-time` shows as `Timestamp`, `recipient-address` as
  `Recipients`, `sender-address` as `Sender`.
- `internal-message-id` differs on every server a message crosses; `message-id` is the Message-Id header;
  `network-message-id` persists across copies made by bifurcation or group expansion.

## Event IDs (field `event-id`)
| EventId | Meaning |
|---|---|
| RECEIVE | Received by the SMTP receive component or Pickup/Replay (Source SMTP), or submitted from a mailbox to Mailbox Transport Submission (Source STOREDRIVER) |
| SUBMIT | Mailbox Transport Submission passed it to the Transport service |
| SEND | Sent by SMTP between transport services |
| DELIVER | Delivered to a local mailbox |
| REDIRECT / RESOLVE | Alternate recipient or address changed after an Active Directory lookup |
| EXPAND | Distribution group expanded |
| DROP | Dropped without a DSN (for example silently dropped spam) |
| FAIL / DSN | Delivery failed / a delivery status notification was generated |
| TRANSFER | Recipients moved to a forked message (content conversion, recipient limits, agents) |
| AGENTINFO | A transport agent logged custom data (the Transport Rule agent records the mail flow rule GUID in `custom-data`) |
| CLIENTSUBMISSION, DEFER, NOTIFYMAPI, THROTTLE, SUPPRESSED | Further event types are listed on the Learn page |

`source` values include SMTP, STOREDRIVER, AGENT, MAILBOXRULE (an Inbox rule), ROUTING, RESOLVER, ADMIN and QUEUE.

## Raw logs
`%ExchangeInstallPath%TransportRoles\Logs\MessageTracking`, named `MSGTRK<service>yyyyMMdd-nnnn.log`
(`MSGTRK` Transport service, `MSGTRKMD` Mailbox Transport Delivery, `MSGTRKMS` Mailbox Transport Submission,
`MSGTRKMA` moderation). CSV text with a header: `#Software`, `#Version`, `#Log-Type`, `#Date` (UTC) and `#Fields`;
parse with any CSV tool when PowerShell is unavailable (for example from an image).
Exchange uses circular logging by file size and age, so old files are deleted; collect early.

## Investigative patterns
- A message generated by an Inbox rule has `source` MAILBOXRULE and `reference` holding the internal message ID of
  the inbound message that triggered it.
- Look at `recipient-count`, `total-bytes` and `directionality` for bulk or outbound sends from one account.
- AGENTINFO rows with a rule GUID in `custom-data` identify mail flow rules that acted on a message.

## Gotchas
- No message content is stored; the subject is stored by default unless `MessageTrackingLogSubjectLoggingEnabled`
  (on `Set-TransportService`) is turned off, so it may be missing.
- Times in raw logs are UTC (ISO 8601).
