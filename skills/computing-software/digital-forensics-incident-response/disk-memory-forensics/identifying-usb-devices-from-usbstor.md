# Identifying USB devices from USBSTOR

**Goal:** build an inventory of mass storage devices ever connected, with unique identifiers
you can match to a physical device.

## Keys (SYSTEM hive, ControlSet00N)
- `Enum\USBSTOR\Disk&Ven_<vendor>&Prod_<product>&Rev_<rev>\<serial>&0` with values
  `FriendlyName`, `ContainerID`, and the `Properties` subkey for times.
- `Enum\USB\VID_xxxx&PID_yyyy\<serial>`: USB-level vendor/product IDs; the same serial links
  to USBSTOR.
- `Enum\SCSI` / `Enum\UASPStor` for UASP devices; `Enum\SWD\WPDBUSENUM` for portable devices.
- Software: `Microsoft\Windows Portable Devices\Devices` (friendly volume names).

## Serial numbers
- A serial like `AA0123456789&0` is the device's iSerialNumber: unique, matches the
  physical device (readable with `usbdeview` or Linux `lsusb -v` on the seized stick).
- If the **second character is `&`** (e.g. `7&2a3b4c5d&0`), the device has no serial and
  Windows generated one: unique per host/port only, cannot match across machines.

## Tools
Registry Explorer USB bookmarks, RegRipper `usbstor`, `usbdevices`; USB Detective
(commercial); for live systems USBDeview.

## Workflow
1. List USBSTOR entries with vendor, product, serial.
2. Link to `MountedDevices` (drive letter, volume GUID) via serial in the device path.
3. Get connection times (see the USB timestamps skill) and the user (MountPoints2).
4. Correlate with the `Microsoft-Windows-Partition/Diagnostic` log (Event 1006) for
   capacity and volume serial number.

## Verify
Physical device in evidence: its USB serial matches the registry, and its volume serial
matches LNK files referencing it.
