# File drop and SFTP ingestion

**Goal:** partner files (CSV/Excel/fixed-width over SFTP or buckets) are loaded once, completely, and bad files are caught before they pollute the warehouse.

## 1. Agree the interface in writing
File naming (`<feed>_<YYYYMMDD>_<seq>.csv`), encoding (UTF-8), delimiter/quoting, header, date and decimal formats, delivery schedule and cut-off, full vs incremental, how corrections are sent, and the **completeness signal**. Put it in a feed spec with an owner on each side.

## 2. Completeness signals (never load a half-written file)
- Manifest/trigger file written last: `orders_20261016.csv` + `orders_20261016.done` (or `.ok`), ideally with row count and checksum inside.
- Upload to a temp name then rename (`.part` to `.csv`) and only pick up final names; confirm with the partner's SFTP server that rename is supported before relying on it.
- Size-stable check (size unchanged for N minutes) only as a last resort.

## 3. Get the files
| Option | Notes |
|---|---|
| Partner pushes to managed SFTP (AWS Transfer Family, Azure Blob Storage SFTP) | no server to run; files land in S3 or EFS (Transfer Family) or Blob Storage (Azure); best default |
| You pull from partner SFTP | an Airflow job using the SFTP provider package (it ships sensors and a connection type) or `rclone`/`lftp` scripts; you own retries and host-key checks |
| Partner writes to your bucket | cross-account role / SAS token scoped to one prefix |

Managed-service facts:
- AWS Transfer Family transfers files in and out of Amazon S3 and Amazon EFS over SFTP (version 3), FTPS, FTP, AS2 and browser-based transfers, using any standard client (OpenSSH, WinSCP, Cyberduck, FileZilla). For servers you associate a hostname with the endpoint, add users and give them access. It also offers managed workflows for post-upload steps such as copying, tagging, scanning, compressing and decrypting.
- Azure Blob Storage SFTP requires the hierarchical namespace. Access uses local users with a password (generated by Azure) or SSH key pairs (up to 10 public keys per local user, up to 50,000 local users per account, access to up to 100 containers each). Local users do not interoperate with RBAC or ABAC, but ACLs are supported. Port 22 is open at platform level even when the option is disabled; SFTP support has an hourly cost, so enable it only while in use. Clients must use the documented algorithms (RSA keys at least 2,048 bits).

Security: key-based auth only, pin partner host keys, restrict source IPs, PGP-encrypt files if they contain personal data and decrypt in the pipeline.

## 4. Landing zone layout
```
landing/<partner>/<feed>/incoming/        # arrivals (append-only for the partner)
landing/<partner>/<feed>/archive/dt=2026-10-16/   # processed originals, immutable
landing/<partner>/<feed>/quarantine/      # failed validation, with an error report
```
Never edit or delete a received file; corrections arrive as new files.

## 5. Validate before load
1. Manifest matches: file present, row count and checksum (`sha256sum`) agree.
2. Structure: expected columns/header, delimiter, encoding (detect BOM, non-UTF-8 bytes).
3. Content: required fields not null, types parse, dates in expected range, no duplicate keys within the file.
4. Business sanity: row count within ±X% of the trailing average.
Fail → move to quarantine, alert the partner contact and on-call with the report.

## 6. Load exactly once
- Track processed files in a control table (`file_name, sha256, received_at, loaded_at, rows`) or use your load engine's built-in file tracking if it has one.
- Re-sent file with the same name but different checksum = correction → define the rule (replace that day's partition / MERGE by key).
- Record source file name on every loaded row for traceability.

## Verify
- [ ] A partial upload (no done-file) is not picked up.
- [ ] Sending the same file twice loads it once.
- [ ] A malformed file lands in quarantine and alerts with a readable reason.
- [ ] Late or missing file triggers an alert at the agreed cut-off.
