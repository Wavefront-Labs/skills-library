# TF-TRT optimization

TF-TRT replaces TensorRT-compatible subgraphs of a SavedModel with `TRTEngineOp` nodes; unsupported ops stay in TensorFlow. Requires a TensorFlow build that includes TF-TRT; the TF-TRT README says TensorFlow nightly builds include it and that TensorFlow containers from Docker Hub and the latest pip package are other ways to get it.

## Convert
```python
import tensorflow as tf
conv = tf.experimental.tensorrt.Converter(
    input_saved_model_dir="saved_model",
    precision_mode="FP16",
    max_workspace_size_bytes=1 << 30,
    minimum_segment_size=3,
    maximum_cached_engines=16,           # large enough to cache every engine you build
    use_dynamic_shape=True,
    dynamic_shape_profile_strategy="Optimal")
conv.convert()
def input_fn():                        # representative shapes to pre-build engines
    for b in (1, 8, 32):
        yield (tf.random.normal((b, 224, 224, 3)),)
conv.build(input_fn=input_fn)          # build engines now instead of on first request
conv.save("saved_model_trt")
```

## INT8
```python
conv = tf.experimental.tensorrt.Converter(
    input_saved_model_dir="saved_model",
    precision_mode="INT8", use_calibration=True,
    maximum_cached_engines=1)            # the TF source notes only one INT8 engine is supported in this mode
conv.convert(calibration_input_fn=calibration_input_fn)   # yields inputs that all have the same shape
conv.build(input_fn=input_fn)           # optional: build engines for more shapes offline
conv.save("saved_model_trt")
```
Use representative real samples for calibration; validate accuracy per class or slice afterwards.

## Inspect the result
- Count engines and remaining TF ops: load the converted graph and count `TRTEngineOp` nodes; many small engines with TF ops in between means poor coverage, little speedup.
- `minimum_segment_size` (default 3) is the minimum number of nodes a subgraph needs to be replaced by a `TRTEngineOp`.

## Dynamic shapes
`maximum_cached_engines` caps the cached engines for dynamic ops: when the cache is full and no engine supports the input shapes, the `TRTEngineOp` falls back to the original TensorFlow subgraph. With `use_dynamic_shape=True`, call `build()` with an input function so profiles are created from the inputs; `dynamic_shape_profile_strategy` is one of `Range` (one profile spanning the min and max dimensions seen), `Optimal` (one profile per input) or `Range+Optimal`.

## Serve
Engines generated by `build()` are platform dependent: run `build()` in an environment similar to production, for example with the same type of GPU.

## Verify
Compare outputs with the original model on a validation set, and benchmark latency and throughput with warm-up at production batch sizes.
