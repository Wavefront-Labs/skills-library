# Constructors, CreateDefaultSubobject and the CDO

**Goal:** keep constructors to defaults and subobjects, and put runtime initialisation where the engine documents it.

## The CDO
Each UCLASS maintains one Class Default Object (CDO): a default "template" object generated by the class
constructor and unmodified thereafter. The CDO and UCLASS can be retrieved for an instance (`GetClass()`) but
should be treated as read-only. So the constructor sets defaults; it is not "spawn time".

## Constructor rules
- UObjects do not support constructor arguments. The engine calls the default constructor at engine startup;
  a UObject with no default constructor will not compile.
- Constructors should be lightweight: set default values and subobjects only. For Actors and Actor Components,
  put initialisation functionality in `BeginPlay()` instead.
- Create UObjects with `NewObject` at runtime and `CreateDefaultSubobject` inside constructors. Never use `new`
  or `delete` on a UObject: the engine manages and garbage collects them.
- Default subobjects are constructed at engine startup, so a constructor should work only with local data or
  load static assets.

## Where init work goes (spawn path, from the Actor Lifecycle page)
`SpawnActor` -> `PostSpawnInitialize` -> `PostActorCreated` (the page says constructor-style implementation
behaviour belongs here for spawned Actors) -> `ExecuteConstruction` / `OnConstruction` (Blueprint Actors get their
components created and variables initialised) -> `PreInitializeComponents` -> `InitializeComponent` on each
component -> `PostInitializeComponents` -> `BeginPlay`.
- Actors already in a level take the load path: `PostLoad` (custom versioning and fixup belong here; it is
  mutually exclusive with `PostActorCreated`), then `PreInitializeComponents`, `InitializeComponent`,
  `PostInitializeComponents`, and `BeginPlay` when the level starts.
- Spawn with `UWorld::SpawnActorDeferred` when you need extra setup on a valid but incomplete Actor; then
  `FinishSpawning` resumes at `ExecuteConstruction`.

## Verify
- [ ] No gameplay logic runs in the constructor; it only sets defaults and creates subobjects.
- [ ] Init order you rely on matches the lifecycle sequence above for your Unreal version (the page is not
      versioned in its text).
