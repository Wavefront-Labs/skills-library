# Blueprint interfaces

**Goal:** one function call works on unrelated types (page example: a car and a tree both take `OnTakeWeaponFire`).

## Blueprint Interface asset (Blueprint Interface page)
- A collection of function names with no implementation; any Blueprint that adds the interface is guaranteed to have them,
  and gives each its own behaviour. It cannot add variables, edit graphs or add components.
- Create: Content Browser Add > Blueprints > Blueprint Interface (or right-click > Blueprints > Blueprint Interface). A new
  interface opens with `NewFunction_0` ready to rename.
- Add functions with + in My Blueprint. Inputs and outputs are added in Details (Inputs category, + icon); an input can
  have a default value (expand the entry). Parameters can be removed and reordered by dragging.
- The Replicates checkbox (Details, via Class Settings) is for interfaces whose functions must replicate across the server.

## C++ Unreal Interface (Unreal Interfaces page)
- Use `UINTERFACE` (not `UCLASS`) on an empty class deriving `UInterface`, for reflection visibility. The actual interface
  is the I-prefixed class (same name, U replaced by I) holding the functions; implementers inherit the I-class.
  Page example: `UINTERFACE(MinimalAPI, Blueprintable)`, `ATrap : public AActor, public IReactToTriggerInterface`.
- Specifiers: `Blueprintable` (needed for a Blueprint to implement it; the interface can only be exposed to Blueprint if it
  contains nothing but `BlueprintImplementableEvent` and `BlueprintNativeEvent` functions; opt out with `NotBlueprintable`
  or `meta=(CannotImplementInterfaceInBlueprint)`), `BlueprintType`, `DependsOn`, `MinimalAPI`.
- Function kinds, all declared public in the I-class:
  - Plain virtual C++ functions without UFUNCTION: C++ only, not visible to Blueprint, cannot be used in Blueprintable
    interfaces.
  - Blueprint-callable: UFUNCTION with `BlueprintCallable` plus `BlueprintImplementableEvent` or `BlueprintNativeEvent`;
    these cannot be virtual. With no return value, Blueprint treats it as an event.
  - `BlueprintImplementableEvent` cannot be overridden in C++, only in Blueprint. `BlueprintNativeEvent` can be
    implemented in C++ (add `_Implementation` suffix to the name) or Blueprint.
- Calling from C++ safely, whether implemented in C++ or Blueprint: the static `Execute_` wrapper, e.g.
  `IReactToTriggerInterface::Execute_ReactToTrigger(OriginalObject)`. The page's table: Base function is for C++-only
  interfaces; the `_Implementation` wrapper calls only the C++ implementation, not Blueprint overrides; the `Execute_`
  wrapper (generated by reflection) calls C++ and Blueprint overrides.
- Implements checks: `Obj->GetClass()->ImplementsInterface(UFoo::StaticClass())` or `Obj->Implements<UFoo>()`.
  `Cast<IFoo>(Obj)` only works if implemented in a C++ class; a Blueprint implementation does not exist in the C++
  object, so `Cast<>` returns null and only `Execute_` wrappers work.
- Interface-to-interface and interface-to-class casts are supported. `TScriptInterface<IFoo>` stores an object plus its
  interface pointer; `GetObject()` and `GetInterface()` retrieve them.
