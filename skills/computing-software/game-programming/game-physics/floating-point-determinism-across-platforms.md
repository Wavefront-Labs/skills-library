# Floating-point determinism across platforms

**Goal:** the same inputs produce bit-identical physics on every client (lockstep RTS, rollback
fighting games, replays), without switching to fixed point.

## What is and is not deterministic
IEEE 754 `+ − × ÷ sqrt` are correctly rounded, so they are reproducible **if** every machine executes
the same operations in the same order with the same precision. Breakers:
- **Compiler reassociation/contraction**: `-ffast-math`, `/fp:fast`, and FMA contraction
  (`a*b+c` fused on one platform, not another). Use `/fp:precise` or `/fp:strict` (MSVC; per Microsoft, contractions are not generated by default under `/fp:precise` from
  Visual Studio 2022, older compilers could emit them),
  `-ffp-contract=off` and no fast-math (GCC/Clang), and the same for every platform.
- **x87 80-bit intermediates** on 32-bit x86: force SSE2 (`-msse2 -mfpmath=sse`). x64 uses SSE by default.
- **Transcendentals** (`sin`, `cos`, `atan2`, `pow`, `exp`) differ between libm implementations and
  CPU microcode. Ship your own polynomial approximations built from basic ops.
- **Different code paths**: SIMD vs scalar fallbacks, CPU-feature dispatch (AVX2 path on one PC),
  different library versions.
- **Order**: multithreaded reductions, unordered hash-map iteration, sorting with unstable sort on
  equal keys, pointer-address-based ordering. Sort by stable ids.
- Uninitialised memory and denormal flush settings (FTZ/DAZ) differing between threads.

## Engine support
- Jolt Physics: the `CROSS_PLATFORM_DETERMINISTIC` CMake option (`JPH_CROSS_PLATFORM_DETERMINISTIC`) gives determinism across
  compilers, OS and architectures at roughly 8% slower, with caveats: same source and defines (for example not mixing
  `JPH_DOUBLE_PRECISION`), same body/constraint creation order, and non-deterministic broad-phase queries and listener
  callback order.
- Box2D v3.1 lists cross-platform determinism, and its docs say simulation order follows creation order.
- PhysX/Unity/Unreal Chaos: no cross-platform determinism guarantee found in their docs (gated: unconfirmed, source is paywalled or blocked); do not rely on them for
  cross-platform lockstep. Unity's DOTS Physics is deterministic on same-architecture builds (gated: unconfirmed, source is paywalled or blocked).

## Detect desyncs early
- Every N ticks, hash the simulation state (positions, velocities as raw bits) and exchange hashes;
  on mismatch dump full state from both peers and diff to find the first diverging field.
- Run CI that simulates a recorded input log on every target platform/compiler and compares the
  final hash with a golden value.
- Keep rendering/interpolation floats out of the simulation state.

## When to give up and use fixed point
Mixed CPU architectures (ARM consoles/phones vs x86 PCs) plus third-party libraries you cannot
control: fixed point is simpler to make deterministic (see `fixed-point-math-for-simulation`).

## Verify
- [ ] Recorded 10-minute match replays to the same hash on Windows/MSVC, Linux/Clang, ARM.
- [ ] Build scripts assert the strict FP flags (fail the build if fast-math sneaks in).
- [ ] grep for `std::sin`/`Mathf.Sin` etc. in simulation code returns nothing.
