Goal: fix wrong generated URLs when automatic detection fails behind a proxy.

Automatic hostname, protocol or webroot detection can fail in some reverse proxy setups. Only if it does, set these in `config/config.php`:

- `overwritehost`: the hostname of the proxy. A port may be included.
- `overwriteprotocol`: the proxy protocol, `http` or `https`.
- `overwritewebroot`: the absolute web path of the proxy to the Nextcloud folder.
- `overwritecondaddr`: apply the overrides only when the remote address matches. The value is a regular expression of the proxy IP addresses.
- `overwrite.cli.url`: the base URL for any URLs generated by command line tools.

Typical case: TLS ends at the proxy and Nextcloud sees plain HTTP, so it builds `http://` links. Setting the protocol fixes that:

```
'overwriteprotocol' => 'https',
'overwritehost' => 'cloud.example.com',
```

Leave a value empty, or omit the parameter, to keep automatic detection. Do not set values you do not need, since each override replaces what Nextcloud would otherwise work out.

Use `overwritecondaddr` when the same instance is also reached directly, so only requests arriving from the proxy get overridden.

Pair this with `trusted_proxies` (see trusted-proxies-and-forwarded-headers); the two solve different problems, client IP versus URL generation.

Check: links in share emails and the login redirect use the public https hostname.
