Two ways exist to create users without open registration, and both rely on `registration_shared_secret`. A random value is generated by `--generate-config`. Keep it secret: anyone who knows it can register users, including admins, even when `enable_registration` is false.

**Command line.** With the virtualenv active (packages already put it on the path), run against the running server:

```sh
register_new_matrix_user -c homeserver.yaml
```

It prompts for localpart, password and whether to make the user admin, then connects to Synapse.

**Admin API.** The API is for bootstrapping admin accounts, is not enabled if no shared secret is configured, and is disabled when Matrix Authentication Service integration is enabled. First `GET /_synapse/admin/v1/register` to obtain a one-time `nonce`. Then `POST` to the same URL with `nonce`, `username`, `password`, `mac`, and optionally `admin` (default false) and `displayname` (default the username). The response contains `access_token`, `user_id`, `home_server` and `device_id`.

The `mac` is the hex HMAC-SHA1 digest keyed with the shared secret over the nonce, user, password, the string `admin` or `notadmin`, and optionally the user_type, separated by NUL bytes. The docs' Bash version:

```bash
printf '%s\0%s\0%s\0%s' "$nonce" "$username" "$password" "$admin" |
  openssl sha1 -hmac "$secret" |
  awk '{print $2}'
```

Mind the nonce is single-use, so request a fresh one per user. The same result can be produced in Python with `hmac.new(key=shared_secret, digestmod=hashlib.sha1)` and `update` calls for each part with `b"\x00"` separators.
