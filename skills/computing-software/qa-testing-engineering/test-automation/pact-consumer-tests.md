# Writing Pact consumer tests

**Goal:** the consumer records exactly what it needs from the provider as a contract, verified later against the real provider.

## JavaScript (PactV3)
```ts
import { PactV3, MatchersV3 as M } from '@pact-foundation/pact';
const provider = new PactV3({ consumer: 'web-shop', provider: 'order-api', dir: './pacts' });

it('gets an order', () => {
  provider
    .given('order 42 exists', { id: 42 })
    .uponReceiving('a request for order 42')
    .withRequest({ method: 'GET', path: '/orders/42', headers: { Accept: 'application/json' } })
    .willRespondWith({
      status: 200,
      headers: { 'Content-Type': 'application/json' },
      body: { id: M.integer(42), status: M.regex('PAID|PENDING', 'PAID'),
              items: M.eachLike({ sku: M.string('SKU-1'), qty: M.integer(1) }) },
    });
  return provider.executeTest(async (mock) => {
    const order = await new OrderClient(mock.url).get(42);   // real client code
    expect(order.status).toBe('PAID');
  });
});
```

(Ran as written with @pact-foundation/pact 17.1.4 and vitest: one interaction passed against the mock server and wrote `pacts/web-shop-order-api.json` with the matching rules.)

## JVM (JUnit 5)
`@ExtendWith(PactConsumerTestExt.class)`, `@Pact(consumer = "web-shop")` method returning `RequestResponsePact` via `PactDslWithProvider`, and `@PactTestFor(pactMethod = "...")` on the test.

## Rules
- Test through your real API client class; the value is checking your code's assumptions.
- Use matchers (type, regex, eachLike) not exact values, so the contract checks shape, not data.
- Include only fields the consumer uses (Postel's law); extra provider fields must not break you.
- One interaction per meaningful scenario: success, not found, validation error. Each needs a provider state.

## Publish
The `pact-broker` command comes from the separate `@pact-foundation/pact-cli` package (not installed by `@pact-foundation/pact`; its `--help` shows the flags below).
```bash
npx pact-broker publish ./pacts --consumer-app-version=$GIT_SHA --branch=$GIT_BRANCH \
  --broker-base-url=$PACT_BROKER_URL --broker-token=$PACT_BROKER_TOKEN
```
Before deploy: `pact-broker can-i-deploy --pacticipant web-shop --version $GIT_SHA --to-environment production`, then `record-deployment` after.

## Gotchas
- Pact is not a functional test of the provider; do not assert provider business logic.
- Exact-value bodies make brittle contracts.
- Using the same version for different commits breaks can-i-deploy; version = commit SHA.

## Verify
Pact file is generated by tests through the real client, published with SHA and branch, and can-i-deploy gates the consumer's deployment.
