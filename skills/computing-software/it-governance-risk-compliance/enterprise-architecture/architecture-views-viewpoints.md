# Views, viewpoints and stakeholder concerns

Goal: every view has a purpose.

- A viewpoint defines conventions for constructing and reading a view: concerns addressed, notation, models used.
- A view is what a stakeholder sees; it covers a set of concerns.
- Architecture description per ISO/IEC/IEEE 42010 requires identifying stakeholders, concerns, viewpoints, views and consistency across views.
- Keep a concern-to-viewpoint table.

Gotchas:
- A diagram without a stated concern is decoration.
- Views must stay consistent; generate from one model.

Verify: each view in the pack lists its stakeholder and concern.
