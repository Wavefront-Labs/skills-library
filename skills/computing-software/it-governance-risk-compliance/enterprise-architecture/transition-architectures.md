# Define transition architectures

Goal: stable, valuable intermediate states.

- Create a transition architecture when risk, funding or dependencies prevent one step.
- Each should deliver measurable business value and be operable on its own.
- Define entry and exit criteria, interim interfaces and temporary components.
- Record which work packages land in each transition.
- Review with the business for value, not only IT feasibility.

Gotchas:
- Throwaway integration adds cost; budget it explicitly.
- Too many transitions slows delivery; cap them (often 2 or 3).

Verify: each transition has a name, date range, value statement and exit criteria.
