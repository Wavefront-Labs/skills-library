# Document and reuse architecture patterns

Goal: reuse proven solutions.

- Pattern fields: name, context, problem, forces, solution, consequences, related patterns, known uses.
- Distinguish patterns (a way to solve a recurring problem) from reference architectures (a full blueprint) and from standards.
- Review patterns against current technology periodically.

Gotchas:
- A pattern without a stated trade-off is advice, not a pattern.

Verify: each pattern includes at least one real use and a consequences section.
