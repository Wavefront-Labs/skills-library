# Tailor TOGAF and select tools

Goal: a minimal, fit-for-purpose method rather than full TOGAF.

- Decide which phases, steps and deliverables are mandatory, optional or dropped.
- Choose a modelling notation (ArchiMate is common) and a repository tool.
- Map TOGAF terms to local terms and to other frameworks in use (ITIL, COBIT, Agile).
- Define review cadence and the iteration pattern.
- Record each deviation and its reason in an architecture method document.

Gotchas:
- Tailoring that is not written down cannot be onboarded or audited.
- Do not pick tooling before deciding which viewpoints stakeholders need.

Verify: another architect can run a cycle from the method document alone.
