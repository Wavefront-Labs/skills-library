# ADM cycle at a glance

Goal: explain the ADM in one pass.

Order: Preliminary, A Architecture Vision, B Business Architecture, C Information Systems Architectures (data and application), D Technology Architecture, E Opportunities and Solutions, F Migration Planning, G Implementation Governance, H Architecture Change Management. Requirements Management sits in the centre and runs continuously.

Each phase is described by Objectives, Approach, Inputs, Steps and Outputs. Steps are guidance, not a checklist to follow blindly.

Gotchas:
- The ADM is not waterfall; phases can be iterated, skipped or overlapped when tailored.
- Phase H feeds back to A or to requirements, closing the loop.

Verify: you can name the main output of each phase, for example Architecture Vision, Architecture Definition Document, Architecture Roadmap, Implementation and Migration Plan.
