# Setting up an OSPO

Goal: coordinated, safe use of open source.

Method:
- Mandate from an executive; scope: consumption, contribution, release of projects, inner source.
- Team: programme manager, legal counsel, security rep, engineering champions.
- Core processes: component intake, licence policy, contribution approval, project release checklist, training.
- Metrics: components with approved licences, time to approve, SBOM coverage, upstream contributions, vulnerabilities fixed.
- Use TODO Group guides to benchmark.

Gotchas:
- An OSPO that only says no is bypassed; give fast lanes (pre-approved list).
- Funding must be explicit.

Verify: intake requests are answered within the SLA.
