**Internal links** become SPA router links. Best practice is to omit the extension so VitePress can generate final URLs per your config (clean URLs or not):

```md
[Getting Started](./getting-started)       <!-- do -->
[Getting Started](../guide/getting-started)
[Getting Started](./getting-started.md)     <!-- works, but don't -->
```

From `foo/one.md`: `[Home](/)` goes to the root index, `[foo](/foo/)` to the `foo` folder index, `[foo heading](./#heading)` anchors into the folder index, `[bar - three](../bar/three)` is fine with or without `.md`/`.html`. Every `index.md` is served at its folder URL.

**External links** get `target="_blank" rel="noreferrer"` automatically. The default theme can show an icon with `themeConfig.externalLinkIcon: true`.

**Linking to a page not generated by VitePress** (for example a hand-placed `public/pure.html`): either use a full URL, or force a normal navigation:

```md
[Link to pure.html](/pure.html){target="_self"}
<a href="/pure.html" target="_self">Link to pure.html</a>
```

In Markdown links the `base` is prepended automatically, so to leave the base you need a relative path such as `../../pure.html`; the raw anchor tag keeps its href as written.

**Dead links.** The build fails on unresolved internal links unless `ignoreDeadLinks` is set. When using `rewrites`, base relative links on the rewritten paths.
