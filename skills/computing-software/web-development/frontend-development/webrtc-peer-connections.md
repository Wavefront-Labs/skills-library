# WebRTC peer connections

## 1. Connection setup
```js
const pc = new RTCPeerConnection({ iceServers: [
  { urls: "stun:stun.example.com:3478" },
  { urls: ["turn:turn.example.com:3478?transport=udp", "turns:turn.example.com:443?transport=tcp"],
    username, credential },                       // short-lived creds from your API
]});
const stream = await navigator.mediaDevices.getUserMedia({ audio: true, video: { width: 1280 } });
stream.getTracks().forEach(t => pc.addTrack(t, stream));
pc.ontrack = ({ streams: [s] }) => (remoteVideo.srcObject = s);
pc.onicecandidate = ({ candidate }) => signal.send({ candidate });   // trickle ICE
```
WebRTC has no signalling: exchange SDP and candidates over your own WebSocket/HTTP channel.

## 2. Perfect negotiation (avoids glare)
```js
let makingOffer = false, ignoreOffer = false; const polite = myId < peerId;   // how roles are assigned is up to you
pc.onnegotiationneeded = async () => {
  try { makingOffer = true; await pc.setLocalDescription(); signal.send({ description: pc.localDescription }); }
  finally { makingOffer = false; }
};
signal.onmessage = async ({ description, candidate }) => {
  if (description) {
    const collision = description.type === "offer" && (makingOffer || pc.signalingState !== "stable");
    ignoreOffer = !polite && collision;
    if (ignoreOffer) return;                        // impolite peer ignores the colliding offer
    await pc.setRemoteDescription(description);
    if (description.type === "offer") { await pc.setLocalDescription(); signal.send({ description: pc.localDescription }); }
  } else if (candidate) {
    try { await pc.addIceCandidate(candidate); }
    catch (err) { if (!ignoreOffer) throw err; }   // candidates for an ignored offer may fail; MDN's example swallows only those
  }
};
```

## 3. TURN is not optional
Some networks (for example restrictive firewalls or symmetric NAT) cannot connect peer-to-peer, so provide a TURN server as a relay; see webrtc.org's TURN guidance for server options. Use short-lived credentials generated by your backend and offer TLS (`turns:`) so relayed traffic can pass restrictive firewalls.

## 4. Operations
- Switch camera/mute without renegotiation: `sender.replaceTrack(newTrack)` / `track.enabled = false`.
- Recover: when the connection state becomes `failed`, call `pc.restartIce()`; the next offer from `createOffer()` then triggers an ICE restart and `negotiationneeded` fires so you can renegotiate.
- Diagnose: `pc.getStats()` resolves with an `RTCStatsReport`; its candidate-pair stats include fields such as `currentRoundTripTime`, and an ICE candidate of type `relay` was obtained from a TURN server (so a selected relay candidate means traffic goes through TURN).
- Larger groups: a full mesh multiplies every participant's uplink, so consider a selective forwarding unit (SFU) such as LiveKit, mediasoup, Janus or Jitsi.

## Gotchas
- Handle `NotAllowedError` / `NotFoundError` from `getUserMedia` with clear UI.

## Verify
- [ ] Call works between two networks with UDP blocked (forces TURN/TLS).
- [ ] `getStats()` shows plausible round-trip time and packet loss for your target networks, and the selected `candidate-pair` is the type you expect (relay means TURN).
