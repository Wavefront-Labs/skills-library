Goal: throw, shape and render errors correctly.

Every error passes through the `handleError` hook before rendering. Its `kind` is `'app'`, `'framework'`, `'validation'` (bad remote-function argument; comes with an `issues` array) or `'unknown'`. Default shape: `{ status: number, message: string }`.

## App errors
```js
/// file: src/routes/blog/[slug]/+page.server.js
import { error } from '@sveltejs/kit';
import * as db from '#lib/server/database.js';

export async function load({ params }) {
	const post = await db.getPost(params.slug);
	if (!post) {
		error(404, 'Not found');
	}
	return { post };
}
```
Sets the status and renders `+error.svelte` with `error` as an `App.Error`. Safe to expose. Extra props: `error(404, 'Not found', { code: 'NOT_FOUND' })`. (In 1.x you had to `throw` it.)

## Framework errors
Generated by SvelteKit (no route match 404, POST to a page without actions 405, body too large 413). `kind: 'framework'`, messages are terse and safe (`'Not Found'`). They are routine, so usually avoid logging 404s.

## Unknown errors
Exposed to users only as `{ "status": 500, "message": "Internal Error" }`; logged to console/server logs. In `handleError` you receive the raw thrown value and can report it or return a custom object:
```js
/// file: src/hooks.server.js
class NotFound extends Error {}

/** @type {import('@sveltejs/kit/hooks').HandleServerError} */
export function handleError({ kind, error, event }) {
	if (kind === 'unknown') {
		if (error instanceof NotFound) {
			return { status: 404, message: 'Not found' };
		}
		return { message: 'Something went wrong' };
	}
	// app and framework errors are already safe to expose
	return error;
}
```

## Boundaries
Errors in `load` or rendering bubble to the nearest `+error.svelte`. For finer control wrap content in `<svelte:boundary>` with a `failed` snippet whose `error` is an `App.Error`.

## Responses and fallback
Errors in `handle` or `+server.js` yield a JSON error or the fallback page by `Accept`. Customise with `src/error.html` using `%sveltekit.status%` and `%sveltekit.error.message%`. Errors in the root `+layout.js` or `+layout.server.js` also use the fallback page, since the root layout would contain `+error.svelte`.

## Type safety
```ts
/// file: src/app.d.ts
declare global {
	namespace App {
		interface Error {
			code: string;
			id: string;
		}
	}
}

export {};
```
`status: number` and `message: string` are always included.
