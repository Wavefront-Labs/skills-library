# Enqueueing scripts and styles

**Goal:** each asset loaded once, only where needed, in the right order, cache-busted on change.

## 1. The basic pattern
```php
add_action( 'wp_enqueue_scripts', function () {
    $asset = include get_theme_file_path( 'build/main.asset.php' );    // generated by @wordpress/scripts: deps + version hash
    wp_enqueue_style( 'acme-main', get_theme_file_uri( 'build/main.css' ), [], $asset['version'] );
    wp_enqueue_script( 'acme-main', get_theme_file_uri( 'build/main.js' ), $asset['dependencies'], $asset['version'],
        [ 'in_footer' => true, 'strategy' => 'defer' ] );               // array $args since WP 6.3.0 ('defer' or 'async')
} );
```
- Hooks: `wp_enqueue_scripts` (front end), `admin_enqueue_scripts` (admin, receives the page hook suffix), `enqueue_block_editor_assets` (editor UI), `enqueue_block_assets` (front + editor content).
- Never hard-code `<script>`/`<link>` tags in templates - plugins can't dequeue, dependencies aren't resolved, duplicates happen.
- Version: use a content hash, `filemtime()` or the build's asset file; `null` adds no version query string and `false` (the default) uses the installed WordPress version (poor cache busting for your own files).
- Handles are global: prefix them (`acme-`).

## 2. Load conditionally
```php
if ( is_singular( 'event' ) ) { wp_enqueue_script( 'acme-map', ... ); }
```
Admin: check the screen.
```php
add_action( 'admin_enqueue_scripts', function ( $hook ) {
    if ( 'settings_page_acme' !== $hook ) return;
    wp_enqueue_script( 'acme-admin', ... );
} );
```
Blocks: declare `script`/`viewScript`/`style` in `block.json`; when the theme supports lazy loading of assets, the front-end `style` and `script` assets are enqueued only for pages that render the block. `viewScriptModule` registers an ES module (added in WordPress 6.5.0).

## 3. Passing data to JS
```php
wp_add_inline_script( 'acme-main', 'window.acme = ' . wp_json_encode( [
    'restUrl' => esc_url_raw( rest_url( 'acme/v1/' ) ),
    'nonce'   => wp_create_nonce( 'wp_rest' ),
] ) . ';', 'before' );
```
`wp_localize_script( $handle, $object_name, $l10n )` also attaches a JavaScript object to a registered script, but it was designed for localisation data; `wp_add_inline_script( $handle, $data, $position )` defaults to the `after` position, so pass `'before'` when the script reads the data on load.

## 4. Remove or replace others' assets
```php
add_action( 'wp_enqueue_scripts', function () { wp_dequeue_style( 'some-plugin-css' ); wp_deregister_style( 'some-plugin-css' ); }, 100 );
```
Late priority so it runs after the original enqueue.

## 5. jQuery and core scripts
Core registers `jquery`, `wp-element`, `wp-api-fetch`, etc. Depend on handles rather than bundling copies. Don't replace core jQuery with a CDN version.

## 6. Modules (6.5+)
`wp_enqueue_script_module( $id, $src, $deps, $version, $args )` (WordPress 6.5.0; the `$args` parameter was added in 6.9.0) enqueues a script module, for example `wp_enqueue_script_module( 'acme-app', get_theme_file_uri( 'build/app.js' ), [ '@wordpress/interactivity' ] )`. As with scripts, a `null` version adds no query string and `false` uses the WordPress version.

## Verify
- [ ] View source: no duplicate libraries, deferred scripts have `defer`, assets have versioned URLs.
- [ ] Pages without the feature don't load its JS/CSS (Network tab).
- [ ] No hard-coded `<script src>` tags remain in theme templates.
