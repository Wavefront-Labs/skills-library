Classic GitHub Pages builds run in a restricted environment with whitelisted plugins and themes. GitHub Actions lets you build and host with full control of the build environment and gemset:

- Any Jekyll version, or point the Gemfile at the repository.
- Any plugin, including `*.rb` files in `_plugins`, whitelisted or not.
- Themes that need features from newer Jekyll versions.
- Custom build steps and environment variables, tweakable verbose logs, and automatic gem caching through `ruby/setup-ruby`.

Migrating but keeping a GitHub-hosted theme: use `jekyll-remote-theme`, add the theme's formerly bundled dependencies to `_config.yml` and `Gemfile`, and set `remote_theme: <owner>/<repo_name>`.

Setup:

1. Repository Settings, Pages, change Source under Build and deployment from "Deploy from a branch" to "GitHub Actions".
2. Actions tab, New workflow, search Jekyll, click Configure under the Jekyll workflow (not "GitHub Pages Jekyll"), review and Commit changes.

Pushing to the default branch triggers the build. Check status via the commit's tick or X symbol, or the Actions tab's `jekyll` workflow. The live URL is under the Deployments tab.

Caution: the action installs gems itself, but a checked-in `Gemfile.lock` generated by an old Bundler can cause problems. The official workflow template is in the actions/starter-workflows repository (`pages/jekyll.yml`).
