Goal: stop repeating `else` error branches in every action by routing non-`conn` results to a fallback plug.

Action fallback calls a plug when a controller action fails to return a `%Plug.Conn{}`. The plug receives the original `conn` and the action's return value.

## Before: repeated handling

An action using `with` plus `else` clauses that `put_status`, `put_view(html: HelloWeb.ErrorHTML, json: HelloWeb.ErrorJSON)` and `render(:"404")` / `render(:"403")` has to be repeated in every controller.

## Fallback controller

Controllers are module plugs, so define the fallback as one with `call/2` clauses:

```elixir
defmodule HelloWeb.MyFallbackController do
  use Phoenix.Controller

  def call(conn, {:error, :not_found}) do
    conn
    |> put_status(:not_found)
    |> put_view(json: HelloWeb.ErrorJSON)
    |> render(:"404")
  end

  def call(conn, {:error, :unauthorized}) do
    conn
    |> put_status(403)
    |> put_view(json: HelloWeb.ErrorJSON)
    |> render(:"403")
  end
end
```

## Use it

```elixir
action_fallback HelloWeb.MyFallbackController

def show(conn, %{"id" => id}, current_user) do
  with {:ok, post} <- fetch_post(id),
       :ok <- authorize_user(current_user, :view, post) do
    render(conn, :show, post: post)
  end
end
```

Whenever a `with` clause fails to match, the fallback gets the conn and the non-matching result.

## Generated by phx.gen.json

`FallbackController` handles changeset errors (the other clause is an example):

```elixir
def call(conn, {:error, %Ecto.Changeset{} = changeset}) do
  conn
  |> put_status(:unprocessable_entity)
  |> put_view(json: HelloWeb.ChangesetJSON)
  |> render(:error, changeset: changeset)
end
```

`ChangesetJSON.error/1` returns `%{errors: Ecto.Changeset.traverse_errors(changeset, &translate_error/1)}`. With a changeset using `validate_required([:link, :title])`, posting `{"url": {}}` returns `{"errors": {"link": ["can't be blank"], "title": ["can't be blank"]}}`.
