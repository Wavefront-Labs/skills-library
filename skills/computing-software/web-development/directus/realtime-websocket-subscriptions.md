Subscribe by sending JSON on the open socket:

```json
{ "type": "subscribe", "collection": "messages", "event": "create", "query": { "fields": ["text"] }, "uid": "any-string" }
```

You first get `{ "type": "subscription", "event": "init" }`. Then changes arrive as `{ "type": "subscription", "event": "create", "data": [...] }`. Events are `create`, `update`, `delete`; create and update carry full items (or the requested fields); delete returns just the `id`. `event` and `query.fields` are optional.

`uid`: identifies which subscription a message belongs to when several watch one collection. It is generated by the server if omitted. A manual `uid` must be unique per connection; later duplicates are ignored.

Unsubscribe: `{ "type": "unsubscribe", "uid": "identifier" }`; omit `uid` to stop all.

Heartbeat: you periodically receive `{ "type": "ping" }`; reply `{ "type": "pong" }` to keep the connection open and exclude pings from app logic. Self-hosted tuning: `WEBSOCKETS_HEARTBEAT_ENABLED`, `WEBSOCKETS_HEARTBEAT_PERIOD`.
