# REST filters

Syntax: `GET /api/:pluralApiId?filters[field][operator]=value`

Operators: `$eq`, `$eqi`, `$ne`, `$nei`, `$lt`, `$lte`, `$gt`, `$gte`, `$in`, `$notIn`, `$contains`, `$notContains`, `$containsi`, `$notContainsi`, `$null`, `$notNull`, `$between`, `$startsWith`, `$startsWithi`, `$endsWith`, `$endsWithi`, and the combinators `$or`, `$and`, `$not`. A trailing `i` means case-insensitive.

Multiple fields are implicitly ANDed. `$and`, `$or`, `$not` can be nested. By default filters work only on `find` endpoints generated by the Content-type Builder and the CLI.

```bash
curl 'http://localhost:1337/api/users?filters[username][$eq]=John' \
  -H 'Authorization: Bearer <token>'
```

Build query strings with `qs`:

```js
const qs = require('qs');
const query = qs.stringify({
  filters: {
    username: {
      $eq: 'John',
    },
  },
}, {
  encodeValuesOnly: true, // prettify URL
});
await request(`/api/users?${query}`);
```

Arrays use indexes: `filters[id][$in][0]=3&filters[id][$in][1]=6&filters[id][$in][2]=8`.

With i18n or Draft & Publish enabled you can also filter by locale and by `published` (default) or `draft` status.
