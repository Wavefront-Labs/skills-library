Doc ID: by default the file name without extension relative to the docs root (`greeting.md` is `greeting`, `guide/hello.md` is `guide/hello`). Only the last part can be set in front matter: `id: part1` makes `guide/hello.md` become `guide/part1`. IDs are used in handwritten sidebars and docs hooks/components.

Doc URL: derived from the ID. These file names are omitted from the URL: `index` or `README` (case-insensitive), or a file named like its parent folder (`docs/Guides/Guides.md`). The slug is just `/Guides`. This mirrors the category index convention, but `isCategoryIndex` configuration does not affect URLs.

Override with `slug`, appended to the plugin `routeBasePath` (`/docs` by default):

```md
---
slug: /bonjour
---
```

`guide/hello.md` is then at `/docs/bonjour`. Slugs can be absolute (`/mySlug`) or relative (`mySlug`, `./../mySlug`).

Renaming a file or `id` changes its default URL, so set an explicit `slug` to keep permalinks stable.

To serve a doc at the docs root:

```md
---
id: my-home-doc
slug: /
---
```

Recommended organisation: make the file system mirror the sidebar (autogenerated) and use `slug` to customize URLs.
