A sidebars file can export several sidebars, one per set of docs you want grouped:

```js title="sidebars.js"
export default {
  tutorialSidebar: {'Category A': ['doc1', 'doc2']},
  apiSidebar: ['doc3', 'doc4'],
};
```

Browsing `doc1` shows `tutorialSidebar`; browsing `doc3` shows `apiSidebar`.

Adding doc Y to sidebar X is a two-way binding: X links to Y, and Y displays X. If a doc is in two sidebars, which one displays is not guaranteed.

Override with front matter `displayed_sidebar`:

```md
---
displayed_sidebar: apiSidebar
---
```

The named sidebar shows even if it does not contain the doc (useful for a "home" doc). `displayed_sidebar: null` shows no sidebar and no pagination.

A `ref` item is identical to `doc` but takes no part in navigation: it is ignored for sidebar association and pagination. The doc belongs to the sidebar where it is registered as `doc` (or autogenerated), while the link appears everywhere it is a `ref`.

```js
tutorialSidebar: {'Category A': ['doc1', {type: 'ref', id: 'commonDoc'}, 'doc5']},
apiSidebar: ['doc3', 'commonDoc'],
```
