Goal: pick the right kind of default.

Database defaults (emitted as `DEFAULT` in the generated DDL): `.default(42)`, `.default(sql`42`)`, `uuid().defaultRandom()` (`DEFAULT gen_random_uuid()`), and `timestamp().defaultNow()` (`DEFAULT now()`).

Identity columns:

```ts
id: integer().primaryKey().generatedAlwaysAsIdentity({ startWith: 1000 }),
```

`GENERATED ALWAYS AS IDENTITY` does not allow manual inserts or updates unless the `OVERRIDING SYSTEM VALUE` clause is used; `GENERATED BY DEFAULT AS IDENTITY` generates a value by default but uses a manual one if given. You can pass all sequence properties to `.generatedAlwaysAsIdentity()`, plus custom names for the sequence.

Runtime defaults, computed in JavaScript by drizzle-orm and NOT seen by drizzle-kit:

```ts
id: text().$defaultFn(() => createId()),          // $default is an alias
updatedAt: timestamp({ mode: 'date', precision: 3 }).$onUpdate(() => new Date()),
```

`$onUpdate` (alias `$onUpdateFn`) runs on every update when no value is supplied, and on insert too when there is no default.

Because these values exist only at runtime in drizzle-orm, they are not part of the table DDL: rows inserted by other clients (SQL console, other services) do not get them, so use database defaults for anything that must always exist.
