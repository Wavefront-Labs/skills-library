# KDS root key (gMSA prerequisite)

gMSA passwords are generated by the Key Distribution Service (KDS) on DCs from a **KDS root key**. Without a root key
you cannot generate gMSA passwords. Domain controllers must be Windows Server 2012 or later.

## Create (production)
Membership in **Domain Admins** or **Enterprise Admins** (or equivalent) is Microsoft's minimum for this procedure.
```powershell
Add-KdsRootKey -EffectiveImmediately
```
Despite the parameter name, the DCs wait up to **10 hours** from creation so all DCs can converge through AD
replication before they begin generating gMSA passwords. Microsoft's tip: use `-EffectiveTime` to give the key time to
propagate to all DCs before first use. Plan the key ahead of the first gMSA.

## Test environments only: backdate
For a test environment with a single DC, avoid the wait by setting the start time in the past:
```powershell
Add-KdsRootKey -EffectiveTime ((Get-Date).AddHours(-10))
```

## Notes
- Root keys are stored in `CN=Master Root Keys,CN=Group Key Distribution Service,CN=Services,CN=Configuration,DC=<forest>`;
  the `msKds-DomainID` attribute links a key to the DC that created it. If that DC is demoted the value refers to a
  tombstone and Microsoft says you can ignore the broken value (or repoint it to another DC).
- Deleting and re-creating the root key can lead to the old key still being used after deletion; do not delete a key
  that gMSAs rely on.
- `Add-KdsRootKey` also has a `-LocalTestOnly` switch (see the cmdlet reference).

## Verify
- [ ] A root key object exists under `CN=Master Root Keys` and has replicated to every DC.
- [ ] At least 10 hours have passed since creation (unless backdated in a test forest) before the first gMSA is used.
