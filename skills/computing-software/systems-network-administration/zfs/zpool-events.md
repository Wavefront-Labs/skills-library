# zpool events

```
zpool events [-vHf] [pool]
zpool events -c
```

Lists events generated by the ZFS kernel modules. These are consumed by `zed(8)` to automate tasks such as swapping in a hot spare. Each event is named `ereport.fs.zfs.<subclass>`.

```
zpool events
zpool events -v
zpool events -f
zpool events -H
zpool events -c
```

## Options

- `-v`: print the full payload of each event.
- `-f`: follow; new events appear as they occur.
- `-H`: scripted mode; no headers, fields separated by a single tab.
- `-c`: clear all previous events. It is the second synopsis form and takes no other options.

## Event subclasses

A selection from the man page: `checksum`, `io`, `data`, `deadman`, `delay` (an I/O exceeding `zio_slow_io_ms`), `config_sync`, `pool_create`, `pool_import`, `pool_export`, `pool_destroy`, `scrub_start`, `scrub_finish`, `scrub_abort`, `scrub_paused`, `scrub_resume`, `resilver_start`, `resilver_finish`, `trim_start`, `trim_finish`, `vdev_add`, `vdev_attach`, `vdev_online`, `vdev_clear`, `vdev_spare`, `io_failure`, `probe_failure`, `log_replay`, `authentication`, `sitout`. Payload fields include `pool`, `vdev_path`, `vdev_state` and `zio_err`; for `zed` they are uppercased and prefixed with `ZEVENT_`.

Pair with zpool-status-health for current state and zpool-history for the commands that were run.
