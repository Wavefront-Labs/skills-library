# Finding field names in the display filter reference

Guessing field names wastes time; every field has an exact abbreviation and type.

## In the GUI
- The "Display Filter Expression" dialog (User's Guide section 6.5) shows a tree of field names organised by protocol, with a
  relation selector, and is described as a good way to learn filter strings.

## On the web
`https://www.wireshark.org/docs/dfref/<first-letter>/<protocol>.html`, e.g. `dfref/t/tcp.html`.
Each page lists field name, description, type and the version range it exists in. Fields get renamed
between versions (`ssl.*` became `tls.*` in 3.0); check the version column when an old filter fails.

## From the command line
```
tshark -G fields | awk -F'\t' '$3 ~ /^tls\.handshake\./ {print $3, $4}'
tshark -G protocols | grep -i quic
tshark -G values | awk -F'\t' '$2=="dns.flags.rcode"'      # value strings
tshark -G fields | awk -F'\t' '$3=="dns.qry.name"'
```
`-G fields` is tab separated: `F`, name, abbreviation, type (`FT_STRING`), parent protocol, display base, bitmask, blurb; e.g.
`F  Name  dns.qry.name  FT_STRING  dns  (empty)  0x0  Query Name`. `-G values` lines are `V`, field, value, text (`V dns.flags.rcode 0 No error`).
On Windows the output has CRLF line endings, and `grep -P` may fail with "supports only unibyte and UTF-8 locales"; awk avoids that.

## Gotchas
- Some fields are generated by the dissector (e.g. `tcp.analysis.*`, `tcp.stream`): filterable, but not bytes on the wire (`@tcp.stream == 00`
  matched nothing while `tcp.stream == 0` did).
- Text-only lines in the details tree have no field name; filter on the parent field or use `frame contains`.

## Verify
- [ ] `tshark -r cap -Y '<filter>'` accepts the filter and the match count equals what you expect.
