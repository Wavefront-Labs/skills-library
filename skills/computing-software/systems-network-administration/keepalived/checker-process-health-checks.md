# Checker process

Checkers decide, with a binary pass/fail, whether a real server stays in the LVS topology. They are built as a finite state machine.

Check types:
- **TCP_CHECK:** layer 4. Opens a nonblocking TCP connection with a timeout.
- **HTTP_GET:** layer 5. Fetches a page and compares an MD5 digest of the response with an expected value generated by `genhash`. Several URLs can be listed per service.
- **SSL_GET:** HTTP_GET carried over SSL.
- **MISC_CHECK:** runs a user script on the director; the script must return 0 or 1.

A failed real server is removed from the pool; when it passes again it is added back.

The configuration synopsis notes that only TCP is currently implemented for service monitoring.

See the per-check skills for the keywords each type accepts.

Verify: stopping a real server's service removes it from the IPVS virtual server table and restarting it adds it back.
