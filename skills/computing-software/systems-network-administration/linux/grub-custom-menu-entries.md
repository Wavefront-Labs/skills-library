# Custom GRUB menu entries

**Goal:** a persistent extra boot entry (rescue kernel with odd args, Windows chainload, ISO boot)
that survives `grub-mkconfig` / kernel updates.

## Where it goes
- Never edit `grub.cfg` — it is regenerated by `grub-mkconfig`. Type custom entries at the end of `/etc/grub.d/40_custom`,
  leaving at least its first two lines intact, or put them in `/boot/grub/custom.cfg`.

## Entry syntax
```
menuentry 'Rescue (nomodeset, single)' --class rescue {
    insmod part_gpt
    insmod ext2
    search --no-floppy --fs-uuid --set=root 6f1c...-boot-uuid
    linux  /vmlinuz-<version> root=UUID=<root-uuid> ro nomodeset
    initrd /initrd.img-<version>
}
```
- Paths are relative to the filesystem `root` points at: if `/boot` is a separate partition,
  the path is `/vmlinuz-...`, not `/boot/vmlinuz-...`.
- `search --fs-uuid --set=root <uuid>` finds the device by filesystem UUID and sets `root` (`--no-floppy` skips slow floppy probing).
- For chainloading and loopback boots see the `chainloader` command and the "Loopback booting" section of the GRUB manual.

## Apply
```bash
grub-mkconfig -o /boot/grub/grub.cfg          # some distributions name it grub2-mkconfig or wrap it as update-grub
```
To make it default: set `GRUB_DEFAULT` to the entry's `--id` (preferred; titles still work but often contain unstable names), or use `grub-set-default` with `GRUB_DEFAULT=saved`.

## Gotchas
- A syntax error in a custom script makes `grub-mkconfig` emit a broken config — run
  `grub-script-check /boot/grub/grub.cfg` before rebooting.
- Version-pinned kernel paths go stale after a kernel is removed.

## Verify
- [ ] The regenerated `grub.cfg` contains your entry and `grub-script-check` reports no error.
- [ ] Entry boots in a console/VM test before you depend on it.
