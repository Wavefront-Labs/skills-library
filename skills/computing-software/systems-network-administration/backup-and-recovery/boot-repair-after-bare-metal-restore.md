# Boot repair after bare-metal restore

Restores to new disks or different hardware often copy the data but not a working boot
path: new disk IDs, missing EFI system partition (ESP) entries, BIOS vs UEFI mismatch.

## Windows (from WinPE / recovery media command prompt)
Find the Windows volume and the FAT32 ESP with `diskpart` (`list vol`), assign the ESP a
letter (`sel vol <ESP#>`, `assign letter=S`), then rebuild the boot files with BCDBoot, which
copies boot files from the Windows folder to the system partition and creates the BCD store:
```cmd
bcdboot <OS>:\Windows /s S: /f UEFI
```
`/s` names the system partition volume letter and `/f` the firmware type (`UEFI`, `BIOS` or
`ALL`). On UEFI PCs BCDBoot also adds the Windows Boot Manager entry to firmware NVRAM; `/p`
keeps the existing boot order. For a BIOS/MBR target use `/f BIOS`. A missing storage driver (INACCESSIBLE_BOOT_DEVICE) must be injected offline; see
the Microsoft DISM documentation.

## Linux (rescue ISO, chroot)
Identify devices (`lsblk -f`), mount root, `/boot` and the ESP under `/mnt`, bind-mount `/dev`,
`/proc`, `/sys` and `/run`, then `chroot /mnt`. Fix `/etc/fstab` if UUIDs changed (`blkid`).
GRUB is installed to a drive with `grub-install` as root (for example `grub-install /dev/sda`
for BIOS; for UEFI pass the EFI target and directory options from the GRUB manual), and
`grub.cfg` is normally generated by `grub-mkconfig`. Distribution wrappers, paths, shim and
initramfs rebuilds differ, so follow the distribution's documentation for those.

## Verify
System boots without media, correct root mounted, services start; document the steps in the
BMR runbook for that hardware model.
