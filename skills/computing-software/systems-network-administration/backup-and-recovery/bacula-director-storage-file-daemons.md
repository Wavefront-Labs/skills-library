# Bacula Director, Storage and File daemons

**Goal:** the Director schedules jobs, the File daemon on each client sends data, and the Storage daemon writes
volumes. Checked against the Bacula 15.0.x manual.

## Components and default ports
| Daemon | Config file | Default port |
|---|---|---|
| Director (`bacula-dir`) | `bacula-dir.conf` | 9101 (Console connections) |
| Storage (`bacula-sd`) | `bacula-sd.conf` | 9103 (Director connections) |
| File (`bacula-fd`) | `bacula-fd.conf` | 9102 (Director connections) |
| Console (`bconsole`) | `bconsole.conf` | connects to the Director on 9101 |

Ports must agree between the two ends: the Client resource `FDPort` must equal the FD's `FDport`, the Storage
resource `SDPort` must equal the SD's port, and the Console's `DIRport` must equal the Director's `DIRport`.

## Names and passwords
To contact another daemon, a daemon authorises itself with a password, and in most cases the password belongs to
a name, so both the name and the password must match. Passwords are plain text, any text, not generated by a
special process. The manual has a picture of which names and passwords in `bacula-dir.conf` (Director, Storage and
Client resources) correspond to values in the Console, SD and FD files. If you edit the default files, keep them
consistent.

## Director resources (bacula-dir.conf)
Directives confirmed in the manual:
- Client: `File Retention` is how long File records stay in the catalog after the job End time; `Job Retention` does
  the same for Job records; when the period expires and `AutoPrune` is yes, records are pruned. This affects only the
  catalog, not the backup data. The shortest of File Retention, Job Retention and Volume Retention takes precedence.
  Time can be given in seconds, minutes, hours, days, weeks, months, quarters or years. The default File Retention
  is 60 days.
- Storage: `Media Type` must be the same string as the `Media Type` in the matching SD Device. Bacula permits only
  one Media Type per Storage and Device definition.
- Job: `Write Bootstrap` names a file where Bacula writes a bootstrap file for each Backup job. A Full job erases
  the file first; Incremental and Differential append to it. The manual's example uses `"%c_%n.bsr"` in a JobDefs.
- Schedule: `Run` lines use forms such as `Level=Full Pool=Monthly 1st sun at 2:05` and
  `Level=Differential 2nd-5th sun at 2:05`.
- FileSet Options: `compression=ZSTD` compresses file by file in the File daemon (faster than GZIP, lower ratio);
  `signature=SHA256` computes a SHA256 for each file, costing about 5% overhead per file plus 44 bytes per file in
  the catalog.
- `JobDefs` resources hold shared defaults for Jobs.

## Media Type matching
The SD manual says the Media Type string in the SD Device must also appear in the Director's Storage resource, is
required for every device, and is used to choose the device on restore. With disk storage each Device resource
should have a unique Media Type so Bacula selects the right one.

## Verify
- [ ] Each daemon pair uses the same name and password on both sides.
- [ ] Ports in Client, Storage and Console resources match what each daemon listens on.
- [ ] The Storage `Media Type` equals the SD Device `Media Type`.
