# ASR replication health and alerts

## Where to look
Recovery Services vault > Site Recovery > **Replicated items**: Replication health, Status, RPO (current value and when
it was last computed), last test failover; use Columns and Filter to add RPO, target configuration issues and
replication errors. **Site Recovery infrastructure** shows the health of the infrastructure components.

## Replication health
- Healthy: replication progressing normally. Warning: one or more symptoms that might affect replication. Critical:
  one or more critical error symptoms, typically replication stuck or not keeping up with the data change rate.
- Check the replicated item's replication errors and RPO before changing anything.

## Alerts
- Vault > Monitoring > **Site Recovery Events** > Email notifications: sends to subscription admins and optional
  addresses for critical events (for example critical state of a replicated machine); no extra cost.
- Built-in Azure Monitor alerts are generated by default for: enable-replication failure, replication health critical,
  agent version expiry (Azure VM and Hyper-V), agent not reachable (Hyper-V), failover failure and certificate expiry
  (Azure VM). Alerts need no rule, but notifications need an **alert processing rule** or action group.
- For custom queries, send vault diagnostics to a Log Analytics workspace. Tables: resource-specific
  `AzureSiteRecoveryJobs` and Replicated Items Details, plus legacy Events and Replicated Items in `AzureDiagnostics`.
```kusto
AzureDiagnostics
| where replicationProviderName_s == "A2A"
| where isnotempty(name_s) and isnotnull(name_s)
| summarize hint.strategy=partitioned arg_max(TimeGenerated, *) by name_s
| project name_s, replicationHealth_s
| summarize count() by replicationHealth_s
```
  Create log alerts from queries like this; Microsoft's page also has an RPO bucket query (under 15 min, 15-30 min,
  over 30 min) and a job query using `Category == "AzureSiteRecoveryJobs"`.

## Test failover hygiene
Track the last successful test failover per item and plan; run one per application each quarter.
