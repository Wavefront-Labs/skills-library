# Config archive and configure replace (IOS / IOS XE)

`configure replace` compares the running configuration with a saved file and applies only the differences, using
the same algorithm as `show archive config differences`. Combined with the archive it gives versioned configs
and a safe undo.

## 1. Turn on the archive
```
configure terminal
 archive
  path flash:myconfig
  maximum 14
  time-period 1440
  end
archive config
```
- `path url` sets the location and filename prefix; a directory must end with a forward slash (`path flash:/directory/`).
  Each saved file gets an incrementing version number (and optional timestamp).
- `maximum number` is 1 to 14 (default 10); when full, the oldest file is deleted on the next save.
- `time-period minutes` saves an archive file automatically at that interval. `maximum` and `time-period` need `path` first.
- `archive config` saves the current running configuration into the archive.

## 2. Look at and diff versions
```
show archive
show archive config differences <archive-file> system:running-config
show archive config incremental-diffs <archive-file>
```
See archive-config-differences for how to read the `+`, `-` and `!` output.

## 3. Roll back
```
configure replace <archive-file> list
```
- The target must be a COMPLETE configuration generated by an IOS device (or externally generated in the same
  format). Commands in the running configuration that are not in the file are removed: this is the difference from
  `copy <file> running-config`, which merges and accepts partial files.
- Options: `nolock` (skip the default lock on the running configuration), `list` (show the command lines applied in
  each pass and the number of passes), `force`, `ignorecase`.
- Commands for physical components (for example interfaces that exist or do not exist on the box) cannot be
  added or removed, and a few commands cannot be removed without a reload; those lines fail with error messages.
  Read the output.
- Free memory larger than the running config plus the replacement file combined is required, or the replace is not performed.
- With PKI signature certificate validation, `configure replace` is not supported, and a reload is needed.

## 4. Timed auto-rollback (the change-window safety net)
```
configure replace <known-good-file> list time 30
... check that management access still works ...
configure confirm
```
- `time minutes` makes the replace revert to the previous running configuration automatically unless
  `configure confirm` is entered in time. `configure confirm` is only meaningful with `time`.
- `configure revert {now | timer {minutes | idle minutes}}` cancels the timed rollback and rolls back immediately
  (`now`), or resets the revert timer (`timer minutes`) or the idle timeout (`timer idle minutes`).
- `revert trigger [error] [timer minutes]` can also trigger a rollback on command failure.
- A configuration archive must be configured before using these.

## Verify
- [ ] `show archive` lists the numbered files and `archive config` adds a new one.
- [ ] `configure replace <file> list` on a lab device prints the passes and `Rollback Done`.
- [ ] A timed replace without `configure confirm` returns the device to its prior configuration.
