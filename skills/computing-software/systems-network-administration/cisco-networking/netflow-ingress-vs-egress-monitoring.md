# Ingress vs egress monitoring and double counting

## The rule
A flow is created where a monitor is attached. Attach the same monitor on several interfaces
and both directions and the same packets are counted multiple times.

## Recommended pattern
- Apply `ip flow monitor X input` on **all** interfaces of the router (or all relevant ones). Every
  packet enters the router once, so total = real traffic.
- Collectors use the input interface field plus the output interface field (exported as a
  non-key field) to build both directions.
```
flow record FNF-REC
 match ipv4 source address
 match ipv4 destination address
 match transport source-port
 match transport destination-port
 match ipv4 protocol
 match interface input
 match flow direction
 collect interface output
 collect counter bytes long
 collect counter packets long
interface range Gi0/0/0 - 2
 ip flow monitor FNF-MON input
```

## When egress makes sense
- WAN interface only, to see what leaves the site after NAT/compression (egress shows post-NAT addresses).
- Traffic generated by the router itself or that is encrypted/decapsulated on the router.
- Interfaces where ingress monitoring is not supported.
If you mix ingress and egress, include `match flow direction` in the record so the collector can
de-duplicate.

## Double counting symptoms
- Collector top talkers show exactly 2x the interface counter bandwidth.
- Same 5-tuple appears with two different exporters (multiple routers in path each export it):
  configure the collector to dedupe by exporter or only enable NetFlow at the edge/WAN routers.

## Verify
- [ ] Collector total for an interface within ~5% of SNMP ifHCInOctets over the same period.
- [ ] `show flow monitor FNF-MON cache` and `show flow interface` match intended attachments.
