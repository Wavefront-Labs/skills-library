# Advertising prefixes into BGP

Routes generated by the `network` command, by redistribution or by a static route all mark your AS as the
origin; they are advertised in addition to routes learned from neighbours.

## Option 1: network statement (preferred for your own space)
```
router bgp 64512
 network 198.51.100.0 mask 255.255.255.0
ip route 198.51.100.0 255.255.255.0 Null0
```
- `network network-number [mask network-mask] [route-map route-map-name]` tells BGP which networks to originate;
  it does not run BGP on an interface. The mask is needed because BGP-4 handles subnetting and supernetting.
- It works only if the router already knows the network in its routing table (connected, static or learned
  dynamically). The Null0 static route supplies that matching entry when no IGP route exists.
- With a Null0 static, a more specific route still wins for forwarding; traffic with no more specific match is
  discarded. The Cisco case study calls this a good way to advertise a supernet.
- Routes originated this way show origin code `i` (IGP).

## Option 2: redistribution (dynamic, filter it)
```
router bgp 64512
 redistribute static
ip route 198.51.100.0 255.255.255.0 Null0
```
- Redistributing dumps internal routes into BGP, some of which BGP may itself have learned. Filter so that only
  the routes you intend to advertise leave your AS.
- Origin is incomplete (`?`) for redistributed and static-sourced routes.
- OSPF is special: plain `redistribute ospf 1` under `router bgp` does not bring everything in; keywords such as
  `internal`, `external` and `nssa-external` are needed.

## Option 3: aggregate
```
router bgp 64512
 aggregate-address 192.168.0.0 255.255.0.0 summary-only
```
- `aggregate-address address mask` advertises the aggregate AND the more specific routes.
- `summary-only` advertises only the aggregate and suppresses the more specific routes to all neighbours. If a
  component was injected with the `network` command, that network is still advertised despite `summary-only`.
- `as-set` keeps AS_SET path information from the components in the aggregate's path.
- An aggregate is generated only when a more specific route exists in the BGP table: learned from another AS,
  redistributed, or injected with `network`.

## Verify
```
show ip bgp
show ip bgp neighbors 203.0.113.1 advertised-routes
```
- [ ] Origin codes (`i`, `e`, `?`) are as expected in the table.
- [ ] Exactly the intended prefixes appear in `advertised-routes`.
