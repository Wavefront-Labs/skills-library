# Duplex and speed mismatch

## The classic cause
One of the most common causes of poor performance on 10/100 Ethernet is one port running half duplex while its
partner runs full duplex. It happens when ports are reset and auto-negotiation does not leave both sides with the
same settings, or when someone reconfigures one side and forgets the other. Rule from Cisco: both sides of a link
must have auto-negotiation on, or both must have it off; Cisco recommends leaving it on for devices that comply
with 802.3u.
- Hard-coding the speed on a port disables all auto-negotiation for speed and duplex on that port.
- A port cannot detect the duplex of a partner that is not auto-negotiating: the page states there is no method to do so.
- Gigabit Ethernet negotiates duplex, flow control and more; built-in ports usually negotiate but modular SFP/GBIC
  types do not. A Gigabit port connected to a Fast Ethernet port can have the line protocol down.

## Signature
| Where | Symptom |
|---|---|
| Half-duplex side | rapid increase of FCS and alignment errors |
| Full-duplex side | rapid increase of runts |
| CDP | `%CDP-4-DUPLEX_MISMATCH: duplex mismatch discovered on GigabitEthernet2/0/20 (not half duplex), with XXXXX GigabitEthernet0 (half duplex)` |

- A mismatch may or may not produce a log message. The CDP message is generated by CDP, not by 802.3
  auto-negotiation; CDP reports the problem but does not fix it.
- Collisions and late collisions (a collision after the 512th bit of the frame) exist only on half-duplex Ethernet;
  collision detection is disabled in full duplex.
- CRC errors can also appear when both ends are hard-coded, caused by an earlier IOS version on one device; set both
  to auto or upgrade.

```
show interfaces status
show interfaces counters errors
show interfaces capabilities
show cdp neighbors <interface> detail
```
In `show interfaces status` the `a-` prefix (for example `a-full`, `a-100`) means the setting was negotiated; without
it (`full`, `100`) the port is hard-coded. `show run interface <interface>` shows the configuration.

## Fix
1. Prefer auto on both ends: remove the hard-coded `speed` and `duplex` lines, or enter `speed auto`.
2. If a device cannot negotiate, hard-code BOTH ends to the same speed and duplex.
3. Duplex is subordinate to speed: with `speed auto`, duplex cannot be set manually, and on newer platforms
   `duplex half` is refused while the auto speed subset includes 1, 2.5, 5 or 10 Gbps (message: `Duplex cannot be set
   to half when speed autonegotiation subset contains ...`). Only a port set to `speed 100` accepts `duplex half`.

## Verify
- [ ] `show interfaces status` shows matching negotiated (`a-`) or matching forced values on both ends.
- [ ] FCS/alignment errors and runts stop increasing.
