# openssl.cnf .include and FIPS sections

## .include
```ini
.include /usr/local/ssl/fipsmodule.cnf
.include /etc/ssl/openssl.cnf.d          # every .cnf or .conf file in the directory (sub-directories ignored)
```
- `OPENSSL_CONF_INCLUDE` (if set) is prepended to relative paths; a still-relative path is read from the current working
  directory, so prefer absolute paths (`.pragma abspath:true` enforces this). Directory includes need POSIX IO support.
- `.include = path` is accepted (the equals sign is ignored). Set `config_diagnostics = 1` so a configuration error
  prevents use instead of silently leaving the desired configuration unused; `openssl version -d` shows OPENSSLDIR.

## FIPS provider setup
```sh
openssl fipsinstall -out /usr/local/ssl/fipsmodule.cnf -module /usr/local/lib/ossl-modules/fips.so
```
Then in `openssl.cnf`:
```ini
config_diagnostics = 1
openssl_conf = openssl_init

.include /usr/local/ssl/fipsmodule.cnf

[openssl_init]
providers = provider_sect
alg_section = algorithm_sect

[provider_sect]
fips = fips_sect
base = base_sect

[base_sect]
activate = 1

[algorithm_sect]
default_properties = fips=yes
```
`fipsmodule.cnf` is generated by `fipsinstall` and defines `[fips_sect]` (the default `-section_name`) with items such as
`activate`, `module-mac`, `install-mac`, `install-version` and `install-status`.

## Notes
- `fipsmodule.cnf` records a MAC of the specific module file; generate it for the module file you deploy and re-check it with
  `openssl fipsinstall -verify -in fipsmodule.cnf -module /path/fips.so`.
- `OPENSSL_CONF=/path/openssl.cnf` points a process at an alternate config.
- `config_diagnostics = 1` makes a configuration error block use of the service; weigh that before enabling it in production.

## Verify
- [ ] `openssl list -providers` shows `fips` and `base` active; `fipsinstall -verify` reports the config file as correct.
