# http response rules
`http-response <action> [options] [ { if | unless } <condition> ]` rules apply to layer 7 responses. They are evaluated in declaration order, and because they apply to responses the backend rules run first, followed by the frontend's rules. There is no limit to the number of rules.

```
frontend fe_web
    bind :443 ssl crt /etc/haproxy/certs/
    http-response set-header Strict-Transport-Security "max-age=31536000; includeSubDomains"
    http-response set-header X-Content-Type-Options nosniff
    http-response del-header Server
    http-response del-header X-Powered-By
    http-response replace-header Set-Cookie (.*) \1;\ Secure;\ SameSite=Lax if { ssl_fc }
    http-response deny if { res.hdr(X-Debug) -m found }
```
- Response conditions can use the fetches `res.hdr(<name>)`, `res.cook(<name>)` and `status`.
- `set-header <name> <fmt>` does what `add-header` does but first removes the header if it existed; the new value is computed before removal, so it can concatenate onto the old one. The manual suggests it to force response headers such as `Server`.
- `replace-header <name> <match-regex> <replace-fmt>` matches all occurrences of the header case-sensitively and replaces whole matching values; `\1` style back-references are supported. It acts on whole header lines, so it suits headers that naturally contain commas (`Set-Cookie`, `If-Modified-Since`). For comma-separated lists such as `Accept` or `Cache-Control` the manual says to use `replace-value`.
- `set-status <status> [reason <str>]` replaces the status code with an integer from 100 to 999; the reason text exists only in HTTP/1.x and is ignored by other versions.
- `deny` on a response returns 502 by default and stops evaluating that rule set.
- `http-after-response` rules apply to all responses, including those generated by HAProxy itself, and are evaluated at the end of response analysis before data forwarding. Use it to add security headers to HAProxy-generated error pages. It does not run for errors raised early in request parsing by the multiplexer.
- Like `http-request`, `http-response` rules are only available from named `defaults` sections.

Verify: `curl -sI https://site/` shows the Strict-Transport-Security header and no `Server` header.
