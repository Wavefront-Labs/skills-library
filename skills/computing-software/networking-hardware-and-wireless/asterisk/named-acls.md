# named ACLs
Named ACLs are shared across modules, unlike ACLs written in one module's config. Each context in `acl.conf` is an ACL named after the context, using `deny` and `permit` with an IP and optional mask. Rules chain.
```
[name_of_acl1]
deny=0.0.0.0/0.0.0.0
permit=127.0.0.1

[template_deny_all](!)
deny=0.0.0.0/0.0.0.0

[deny_all_whitelist_these](template_deny_all)
permit=10.24.20.1
```
Templates and additions work as elsewhere. IPv6 works too, for example `deny = ::/0` then `permit = ::1/128`.

**Realtime:** use the `acls` keyword in `extconfig.conf`, for example `acls => odbc,asterisk,acltable`. Columns: `name` (varchar 80), `rule_order` (integer, ascending, need not be sequential), `sense` (`permit` or `deny`), `rule` (varchar 95, address/mask). The page gives PostgreSQL and SQLite3 creation scripts generated by tools and says they may not suit your setup.

Consumers fetch ACLs when they load. A realtime change does not reach consumers using static configuration automatically; realtime consumers see it only for objects built after the change. Consumers listed are the manager, chan_sip, chan_pjsip and chan_iax2 (IPv4 and IPv6 each). Reloading the Named ACL component reloads all consumers. The CLI command `acl show` lists named ACLs.
