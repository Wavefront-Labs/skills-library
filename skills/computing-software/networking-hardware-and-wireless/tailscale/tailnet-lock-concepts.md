# Tailnet Lock concepts

Goal: understand what Tailnet Lock protects and its moving parts.

**Problem.** Without it, the coordination server distributes public node keys to peers, so you must trust the control plane not to insert nodes.

**With Tailnet Lock** a new node's public node key needs a signature from a Tailnet Lock key (TLK) before the coordination server distributes it. Peers reject unsigned keys.

**Parts**

- Node key: pair generated by the client; the public half goes to the coordination server.
- TLK: also a pair; every node generates one even when the feature is off. The private key stays on the node.
- Signing nodes: nodes whose TLKs can sign new nodes.
- Tailnet key authority (TKA): a cryptographic chain storing the trusted TLKs; it verifies node key signatures and requests to change the trusted set. It can grow unbounded as configuration changes.
- Disablement secrets: long passwords generated while enabling; required to disable Tailnet Lock because disabling is security relevant.

The alternative named in the docs for self-hosting trust is Headscale, at the cost of availability guarantees and low maintenance.

**Checklist**

1. Choose signing nodes.
2. Store disablement secrets safely.
3. Read the white paper for architecture.
