# Dependencies with vcpkg, Conan and find_package

**Goal:** reproducible third-party dependencies that CMake finds through `find_package`, with pinned versions on every platform.

## 1. find_package basics
```cmake
find_package(fmt 11 CONFIG REQUIRED)
find_package(OpenSSL REQUIRED)          # module mode: CMake's FindOpenSSL.cmake
target_link_libraries(app PRIVATE fmt::fmt OpenSSL::SSL)
```
- **Config mode** looks for `<Pkg>Config.cmake`/`<pkg>-config.cmake` shipped by the package; search paths include `CMAKE_PREFIX_PATH` and `<Pkg>_DIR`.
- **Module mode** uses `Find<Pkg>.cmake` (CMake ships many).
- Always link the imported targets (`Pkg::Pkg`), not `${PKG_LIBRARIES}` variables.
- Debug discovery: `cmake --debug-find-pkg=fmt` or `-DCMAKE_FIND_DEBUG_MODE=ON`.

## 2. vcpkg (manifest mode)
```json
// vcpkg.json
{
  "name": "acme",
  "dependencies": ["fmt", "spdlog", { "name": "openssl", "platform": "!windows" }],
  "builtin-baseline": "<vcpkg git commit sha>",
  "overrides": [{ "name": "fmt", "version": "<exact version>" }]
}
```
```bash
cmake -B build -S . -DCMAKE_TOOLCHAIN_FILE="$VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake"
```
Dependencies install automatically during configure. `builtin-baseline` pins the whole port set; `vcpkg x-update-baseline` bumps it. Binary caching (local, a NuGet feed, GitHub Packages or the GitHub Actions cache) avoids rebuilding ports in CI. Triplets select architecture and linkage (for example `x64-windows-static`).

## 3. Conan 2
```ini
# conanfile.txt
[requires]
fmt/<version>
spdlog/<version>
[generators]
CMakeDeps
CMakeToolchain
[layout]
cmake_layout
```
```bash
conan profile detect
conan install . --output-folder=build --build=missing -s build_type=Release
cmake --preset conan-release && cmake --build --preset conan-release   # preset generated by CMakeToolchain
conan lock create .        # lockfile for reproducibility
```
Conan builds binaries per profile settings (compiler, version, runtime, build type).

## 4. FetchContent (small/header-only or in-house deps)
```cmake
include(FetchContent)
FetchContent_Declare(Catch2 GIT_REPOSITORY https://github.com/catchorg/Catch2.git GIT_TAG <tag>
                     FIND_PACKAGE_ARGS 3)          # 3.24+: use an installed package if found
FetchContent_MakeAvailable(Catch2)
```
Builds the dependency as part of your tree; fine for tests and small libraries, slow for big ones (Boost, Qt).

## Choosing
- vcpkg: manifest mode plus the CMake toolchain file, ports built from source with optional binary caching.
- Conan: binaries per profile and settings, with lockfiles.
- System packages (apt, brew): fine for distro builds, harder to reproduce across platforms.

## Gotchas
- Mixing package managers for the same library leads to two copies and ODR violations.
- ABI matters: runtime library, standard library ABI and compiler version must match prebuilt binaries.
- Set the toolchain file on the first configure; after changing it, use `cmake --fresh` or a new build directory.

## Verify
- A clean CI agent configures and builds from scratch with only the manifest/lockfile, and `cmake --debug-find-pkg` shows each package resolved from the intended location.
