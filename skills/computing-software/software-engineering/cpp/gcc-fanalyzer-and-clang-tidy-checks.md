# GCC -fanalyzer and clang-tidy checks

## GCC -fanalyzer
```
gcc -fanalyzer -c src/legacy.c
gcc -fanalyzer -fanalyzer-verbosity=3 -c src/legacy.c
```
`-fanalyzer` does coverage-guided symbolic execution looking for interprocedural paths with problems. It is much more expensive than other GCC warnings, neither sound nor complete (false positives and false negatives), and a bug-finding tool rather than a proof of correctness. The manual states that the analyzer is only suitable for use on C code in that release, so do not rely on it for C++ and check the manual for your GCC version. It runs late, after some optimisation, so paths may show inlined frames that do not match the source.

Warnings it enables include `-Wanalyzer-double-free`, `-Wanalyzer-use-after-free`, `-Wanalyzer-malloc-leak`, `-Wanalyzer-file-leak`, `-Wanalyzer-double-fclose`, `-Wanalyzer-null-dereference`, `-Wanalyzer-use-of-uninitialized-value` and the `-Wanalyzer-tainted-*` family.

## clang-tidy curated set
```
# .clang-tidy
Checks: >
  -*,bugprone-*,cert-*,clang-analyzer-*,performance-*,
  cppcoreguidelines-pro-type-member-init,
  modernize-use-override,misc-const-correctness,
  -bugprone-easily-swappable-parameters,-cert-err58-cpp
WarningsAsErrors: 'bugprone-*,cert-*,clang-analyzer-*'
HeaderFilterRegex: '^(src|include)/'
```
`Checks`, `WarningsAsErrors` and `HeaderFilterRegex` in `.clang-tidy` are the file equivalents of `--checks`, `--warnings-as-errors` and `--header-filter`. A leading `-` removes checks from the list.

Use a compilation database (`compile_commands.json`), generated by CMake with `-DCMAKE_EXPORT_COMPILE_COMMANDS=ON`:
```
cmake -S . -B build -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
run-clang-tidy.py -p=build/ -j 4 src/
clang-tidy -p build --checks='-*,modernize-use-nullptr' --fix-errors src/a.cpp
```
`run-clang-tidy.py` ships with clang-tidy and analyses all files in the database in parallel. `--fix-errors` applies suggested fixes even if compilation fails, so review the diff. CMake can run clang-tidy during the build with `CMAKE_CXX_CLANG_TIDY`.

Checks on the list page that fit this set: `bugprone-use-after-move`, `bugprone-unused-return-value`, `bugprone-dangling-handle`, `bugprone-narrowing-conversions`, `cert-err33-c`, `cert-dcl50-cpp`, `performance-for-range-copy`, `modernize-use-nullptr`.

## Gotchas
- clang-tidy needs the same flags and standard as the real build; pass extra compiler arguments with `--extra-arg` (or `ExtraArgs`) when the database holds flags clang does not understand.
- `--header-filter` defaults to `.*`, so diagnostics from all non-system headers are shown by default; narrow it with `HeaderFilterRegex` to skip third-party headers.
- Findings are leads, not proof. For a false positive that has no specific suppression, clang-tidy supports `NOLINT`, `NOLINTNEXTLINE` and `NOLINTBEGIN` ... `NOLINTEND` comments: name the check and say why.

## Verify
- [ ] A deliberate use-after-move in a scratch file is reported by `bugprone-use-after-move`, and a double free in a C file by `-Wanalyzer-double-free`.
- [ ] CI runs the configured checks and fails on new findings.
