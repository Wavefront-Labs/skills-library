# Publishing to npm with provenance

- Provenance has two attestations: a provenance attestation (public link from the build environment to the source and build instructions) and a publish attestation (generated by the registry when an authorised user publishes). Published packages are signed via Sigstore and logged in a public transparency ledger.
- Limits: you must build on a supported cloud CI/CD provider with a cloud-hosted runner (GitHub Actions and GitLab CI/CD today). Provenance does not guarantee the package is free of malicious code; it gives a verifiable link to source and build instructions that consumers can audit.
- Prerequisites: npm CLI 9.5.0 or later; `package.json` points at a public repository that matches (case-sensitive) the repository you publish from; automation set up in a supported provider; review the Linux Foundation Immutable Record notice for the public log.
- GitHub Actions: give the job `permissions: id-token: write` (the docs example also sets `contents: read`), run on a GitHub-hosted runner such as `ubuntu-latest`, and publish with `npm publish --provenance`. The first publish of a package also needs `--access public`. The docs example installs with `npm ci` and passes `NODE_AUTH_TOKEN` from a secret.
- If a tool does not call `npm publish` directly, enable provenance with the `NPM_CONFIG_PROVENANCE=true` environment variable, a `"publishConfig": { "provenance": true }` block in `package.json`, or `provenance=true` in `.npmrc`. Yarn needs v4.9.0 or later.
- With trusted publishing, attestations are generated automatically without the `--provenance` flag and without access tokens in CI.
- GitLab CI/CD: the docs example gives the job an `id_tokens` entry `SIGSTORE_ID_TOKEN` with `aud: sigstore` and runs `npm publish --provenance --access public`.
- Verify downloaded packages with `npm audit signatures`, which reports counts of verified registry signatures and verified attestations. Keep the npm CLI current, which can mean updating beyond the version bundled with Node.js.

Self-check: after a CI publish, `npm audit signatures` in a project that depends on the package reports it among the packages with verified attestations.
