# Using Tauri plugin permissions

Goal: enable only the plugin commands and paths your frontend needs. The page's worked example lets the `fs` plugin write `$HOME/test.txt`.

## Method

1. Create an app (for example `pnpm create tauri-app`).
2. Add the plugin. For official plugins: `pnpm tauri add fs`. For a community plugin found on crates.io (`tauri-plugin-<name>`): `cargo add tauri-plugin-fs`, then initialize it in `src-tauri/src/lib.rs`:

```rust
tauri::Builder::default()
  .plugin(tauri_plugin_fs::init())
  .run(tauri::generate_context!())
  .expect("error while running tauri application");
```

3. Read the plugin's `default` permission set, which holds the permissions and scopes for a reasonable minimal feature set. For official plugins it is rendered in the docs; for community plugins check `your-plugin/permissions/default.toml`. The `fs` default is `permissions = ["read-all", "scope-app-recursive", "deny-default"]`.
4. Find individual permissions in the docs permission table or the plugin source (`fs/permissions/autogenerated`), for example `allow-write-text-file`.
5. Add them to a capability in `src-tauri/tauri.conf.json` or `src-tauri/capabilities/` (an existing `src-tauri/capabilities/default.json` can be modified). The `fs` plugin only autogenerates scopes for the full `$HOME` folder, so give the command its own scope:

```json
"permissions": [
  "fs:allow-write-text-file",
  {
    "identifier": "fs:allow-write-text-file",
    "allow": [{ "path": "$HOME/test.txt" }]
  }
]
```

6. Test from the frontend:

```ts
import { writeTextFile, BaseDirectory } from '@tauri-apps/plugin-fs';
await writeTextFile('test.txt', message, { baseDir: BaseDirectory.Home });
```

Run `pnpm run tauri dev`. A failure reading `fs.write_text_file not allowed. Permissions associated with this command: ...` means the permission step was not followed correctly.
