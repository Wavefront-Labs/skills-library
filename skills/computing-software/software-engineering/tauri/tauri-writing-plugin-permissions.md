# Writing Tauri plugin permissions

Goal: ship a new plugin command together with its permissions. Example plugin: `test`, command `write_custom_file`.

## Method

1. Bootstrap with the CLI (check `cargo tauri info` shows `tauri-cli` 2.x):

```sh
cargo tauri plugin new test
cd tauri-plugin-test
pnpm install
pnpm build
cargo build
```

2. Implement the command in `src/commands.rs`:

```rust
#[command]
pub(crate) async fn write_custom_file<R: Runtime>(
    user_input: String,
    app: AppHandle<R>,
) -> Result<String> {
    std::fs::write(app.path().temp_dir().unwrap(), user_input)?;
    Ok("success".to_string())
}
```

List it in `build.rs` so permissions are autogenerated:

```rust
const COMMANDS: &[&str] = &["ping", "write_custom_file"];
```

The build writes them to `permissions/autogenerated/commands`; the page says an `enable-<command>` and a `deny-<command>` permission are created, but its own `default.toml` (and the plugin development page) use `allow-<command>`, so check the generated names in `permissions/autogenerated/commands`.

3. Expose it in `src/lib.rs` through the invoke handler:

```rust
.invoke_handler(tauri::generate_handler![
    commands::ping,
    commands::write_custom_file,
])
```

Add a wrapper in `guest-js/index.ts` (convenience only, no security impact), then run `pnpm build`:

```ts
export async function writeCustomFile(user_input: string): Promise<string> {
 return await invoke('plugin:test|write_custom_file',{userInput: user_input});
}
```

The invoke parameter must be camelCase: `userInput`, not `user_input`.

4. Add it to the default permission in `permissions/default.toml`:

```toml
"$schema" = "schemas/schema.json"
[default]
description = "Default permissions for the plugin"
permissions = ["allow-ping", "allow-write-custom-file"]
```

5. Try it in `examples/tauri-app`: import `writeCustomFile` from `tauri-plugin-test-api` and call it from a button. Success returns `success`.
