# Tauri plugin development

A plugin is a Cargo crate plus an optional NPM package with bindings; it can also include an Android library and a Swift package.

## Naming and scaffold

- Crate `tauri-plugin-{name}`; default NPM package `tauri-plugin-{name}-api` (convention with a scope: `@scope-name/plugin-{name}`).
- Identifiers: lowercase a-z, 0-9, hyphens (not first or last), one colon only with a prefix (`sqlite-store:allow-read`); no underscores or uppercase. Base name max 64 chars, with prefix 129. Violations fail the build with `identifiers can only include lowercase ASCII, hyphens which are not leading or trailing, and a single colon if using a prefix`.
- Scaffold: `npx @tauri-apps/cli plugin new [name]`; flags `--no-api`, `--android`, `--ios`. Layout: `src/` (`commands.rs`, `desktop.rs`, `error.rs`, `lib.rs`, `mobile.rs`, `models.rs`), `permissions/`, `android`, `ios`, `guest-js`, `dist-js`.
- Add mobile later: `plugin android add`, `plugin ios add`.
- Declare support in `Cargo.toml` under `[package.metadata.platforms.support]`: per platform `level` (`"full"`, `"partial"`, `"none"`) and optional `notes`.

## Config and lifecycle

App config lives in `tauri.conf.json > plugins > <plugin-name>`. Read it via `Builder::<R, Config>::new("<plugin-name>").setup(|app, api| { api.config()... })` with a `serde::Deserialize` struct (use `Option<Config>` to make it optional).

Hooks on `tauri::plugin::Builder`: `setup` (manage state, background tasks), `on_navigation` (return `false` to cancel), `on_webview_ready`, `on_event` (`RunEvent::ExitRequested` can `api.prevent_exit()`; `RunEvent::Exit` for cleanup), `on_drop`.

Rust APIs from `desktop.rs`/`mobile.rs` are exposed as a managed struct named after the plugin in Pascal case, retrieved through an extension trait (e.g. `app.global_shortcut()`).

## Commands

Write `#[command]` functions in `commands.rs` (they can take `AppHandle`, `Window`, `Channel`), register with `.invoke_handler(tauri::generate_handler![commands::upload])`, and bind in JS with `invoke('plugin:<plugin-name>|upload', {...})`.

## Permissions

Commands are denied to the frontend by default. Define permissions in `permissions/*.toml|json`:

- `[[permission]]` with `identifier`, `description`, `commands.allow` / `commands.deny`.
- `[[set]]` groups permissions; `[default]` is the `default` set.
- Autogenerate `allow-$command` and `deny-$command` by listing snake_case names in `const COMMANDS` and calling `tauri_plugin::Builder::new(COMMANDS).build()` in `build.rs`.
- Scopes: a permission with no commands defines a global scope (`[[permission.scope.allow]]`). Read with `tauri::ipc::CommandScope` and `GlobalScope` (`allows()`, `denies()`); check both. Generate a schema with `schemars` (in `[dependencies]` and `[build-dependencies]`) via `.global_scope_schema(schemars::schema_for!(scope::Entry))`.
