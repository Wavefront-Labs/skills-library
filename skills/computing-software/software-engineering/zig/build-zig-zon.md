# build.zig.zon manifest fields
**Goal:** declare package metadata correctly.

```zig
.{
    .name = .myapp,                       // enum literal, required, max 32 bytes
    .version = "0.1.0",                   // semver string, required, max 32 bytes
    .fingerprint = 0x1234567890abcdef,    // placeholder: generated by the toolchain, never changes
    .minimum_zig_version = "0.15.1",
    .dependencies = .{
        .zlib = .{ .url = "https://example.com/zlib-1.3.tar.gz", .hash = "1220..." },
        .local = .{ .path = "../local" },
    },
    .paths = .{ "build.zig", "build.zig.zon", "src", "LICENSE" },
}
```
- `paths` is required: it lists the files and directories (relative to the build root; `""` is the root itself) that are included in the package and in its `hash`.
- `fingerprint` together with `name` is the globally unique package identity: a 64-bit integer (32-bit id plus 32-bit checksum of `name`), initialised by the toolchain and never changed. A fork should regenerate it by deleting the field and running `zig build`.
- `minimum_zig_version` is advisory only; the compiler does not act on it yet.
- A dependency needs either `url` and `hash`, or `path` (mutually exclusive with `url`); `hash` is multihash and is the source of truth, `url` is just a mirror.
- `.lazy = true` on a dependency fetches it only if actually used.
- `std.zon` (zon.zig, with `parse`, `stringify`) exists in the standard library for reading ZON in your own code.

## Gotchas
- When you change a `url`, delete its `hash`; a changed file behind a URL gives a hash mismatch and Zig will not use it.
- Local `.path` dependencies are not hashed.
- The manifest format changes between releases; `zig init` writes the shape for your compiler.
