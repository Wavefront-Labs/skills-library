# gofmt, goimports and generated-code conventions

**Goal:** zero formatting discussion in review, imports managed automatically, and generated code
recognised by every tool.

## gofmt
```bash
gofmt -l .            # list files that differ (CI check)
gofmt -w .            # rewrite in place
gofmt -s -w .         # also simplify ([]T{T{}} -> []T{{}}, for range simplifications)
gofmt -d file.go      # diff
gofmt -r 'a[b:len(a)] -> a[b:]' -w .   # rewrite rule (pattern -> replacement)
```
`go fmt ./...` runs `gofmt -l -w` on packages. Formatting is not configurable: tabs for
indentation, alignment by gofmt.

## goimports
Superset of gofmt that also adds missing and removes unused imports.
```bash
go install golang.org/x/tools/cmd/goimports@latest
goimports -w -local example.com/myorg .
```
`-local` puts your module's imports in a separate group after third-party ones:
```go
import (
    "context"
    "fmt"

    "github.com/google/uuid"

    "example.com/myorg/internal/store"
)
```
gopls applies `local` when organising imports (LSP Organize Imports, completion inserts); a plain format request only sorts existing imports (gopls settings docs), so bind organize-imports on save (`"gopls": {"formatting.local": "example.com/myorg"}` in VS Code).
gofumpt is a stricter, gofmt-compatible formatter (enable via `"gopls": {"formatting.gofumpt": true}`
or golangci-lint).

## CI check
```bash
test -z "$(gofmt -l .)" || { gofmt -l .; exit 1; }
# or golangci-lint with formatters: gofmt, goimports, gofumpt (v2: under `formatters:`)
```

## Generated code
Every generated file must contain, before the first non-comment, non-blank text, a line matching:
```
^// Code generated .* DO NOT EDIT\.$
```
e.g. `// Code generated by protoc-gen-go. DO NOT EDIT.` Linters (staticcheck, golangci-lint),
gopls, coverage tools and GitHub's diff view use it to skip or collapse the file.
- Drive generators with `//go:generate` directives and `go generate ./...`; it is never run by
  `go build`, so commit the output.
- Pin generator versions (go.mod `tool` directive in Go 1.24+, or `go run pkg@version` in the
  directive) so regeneration is reproducible.
- CI: `go generate ./... && git diff --exit-code` catches stale generated files.
- Generators should emit gofmt'd code (`go/format.Source`) so regeneration produces no diff.

## Verify
- [ ] `gofmt -l .` prints nothing on main.
- [ ] Generated files carry the exact header and are excluded from lint/coverage.
- [ ] `go generate` + `git diff --exit-code` passes in CI.
