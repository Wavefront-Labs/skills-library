# Publishing to Maven Central

**Goal:** a release users can depend on from Central, passing validation first time.

## 1. Namespace
Register at central.sonatype.com and verify your groupId: `io.github.<user>` (granted
automatically when you sign up with GitHub) or a reverse domain you own (follow the Portal's
verification steps). The legacy OSSRH service is replaced by the Central Portal; new setups use the Portal.

## 2. Required metadata (validation rejects without it)
```xml
<name>${project.artifactId}</name>
<description>Fast CSV parsing</description>
<url>https://github.com/acme/fastcsv</url>
<licenses><license><name>Apache-2.0</name><url>https://www.apache.org/licenses/LICENSE-2.0</url></license></licenses>
<developers><developer><id>jane</id><name>Jane Doe</name><email>jane@acme.dev</email></developer></developers>
<scm><url>https://github.com/acme/fastcsv</url><connection>scm:git:https://github.com/acme/fastcsv.git</connection></scm>
```
Plus: `-sources.jar`, `-javadoc.jar`, `.asc` GPG signatures for every file, and checksums
(md5/sha1 generated by tooling). No SNAPSHOT versions in releases.

## 3. Maven setup
```xml
<plugin><groupId>org.apache.maven.plugins</groupId><artifactId>maven-source-plugin</artifactId>
  <executions><execution><id>attach-sources</id><goals><goal>jar-no-fork</goal></goals></execution></executions></plugin>
<plugin><groupId>org.apache.maven.plugins</groupId><artifactId>maven-javadoc-plugin</artifactId>
  <executions><execution><id>attach-javadocs</id><goals><goal>jar</goal></goals></execution></executions></plugin>
<plugin><groupId>org.apache.maven.plugins</groupId><artifactId>maven-gpg-plugin</artifactId>
  <executions><execution><phase>verify</phase><goals><goal>sign</goal></goals></execution></executions></plugin>
<plugin><groupId>org.sonatype.central</groupId><artifactId>central-publishing-maven-plugin</artifactId>
  <extensions>true</extensions>
  <configuration><publishingServerId>central</publishingServerId><autoPublish>false</autoPublish></configuration></plugin>
```
`settings.xml` `<server><id>central</id>` holds the Portal user token (not your login password).
Release: `mvn -P release clean deploy`, check the deployment in the Portal UI, then publish
(or `autoPublish=true` once trusted). Put these plugins in a `release` profile so local builds
don't need GPG.

## 4. Gradle
Use `maven-publish` + `signing` plugins with `java { withSourcesJar(); withJavadocJar() }`;
Central's Gradle page says Gradle support is on their roadmap; check it for current community-plugin and API options.

## 5. CI signing
Provide the signing key and passphrase to the maven-gpg-plugin from your CI's secret store, using the environment-variable options described on the plugin's pages.
Use a dedicated signing key and distribute the public key to a key server such as `keyserver.ubuntu.com` (Central checks it).

## Gotchas
- Do a dry run with `autoPublish=false` and check the deployment in the Portal before publishing.
- Javadoc errors can fail the javadoc jar build; fix them.

## Verify
- [ ] Portal validation passes with no warnings before publishing.
- [ ] A fresh project resolves the new version from Central.
