# JPA Specifications and auditing

## Specifications for reusable filters
Extend `JpaSpecificationExecutor` on the repository, then compose predicates over the entity with the Criteria API. Current docs offer `PredicateSpecification` (query-type-agnostic, from Spring Data JPA 4.0) and the query-bound `Specification`, `UpdateSpecification` and `DeleteSpecification`.
```java
public interface CustomerRepo extends CrudRepository<Customer, Long>, JpaSpecificationExecutor<Customer> {}

class CustomerSpecs {
    static PredicateSpecification<Customer> hasFirstname(String firstname) {
        return (from, builder) -> builder.equal(from.get("firstname"), firstname);
    }
    static PredicateSpecification<Customer> isLongTermCustomer() {
        return (from, builder) -> builder.lessThan(from.get(Customer_.createdAt), LocalDate.now().minusYears(2));
    }
}
```
`Customer_` is a type generated by the JPA metamodel generator. Specifications compose with `.and(...)`, which removes the need for a repository method per filter combination. On older Spring Data JPA versions the same shape is written `Specification<Customer>` with a `(root, query, builder)` lambda. Check the docs for your version, since the specification API has changed.

## Auditing
Annotations: `@CreatedBy` and `@LastModifiedBy` capture the user; `@CreatedDate` and `@LastModifiedDate` capture when. They can be applied selectively, and date annotations work on JDK 8 date and time types, `long`, `Long`, `Date` and `Calendar`. Apps that track only dates do not need to implement `AuditorAware`.
```java
@Configuration
@EnableJpaAuditing(auditorAwareRef = "auditor")
class AuditConfig {
    @Bean AuditorAware<String> auditor() {
        return () -> Optional.ofNullable(SecurityContextHolder.getContext().getAuthentication()).map(Authentication::getName);
    }
}
@MappedSuperclass @EntityListeners(AuditingEntityListener.class)
abstract class Auditable {
    @CreatedDate Instant createdAt; @LastModifiedDate Instant updatedAt;
    @CreatedBy String createdBy; @LastModifiedBy String updatedBy;
}
```
Register `AuditingEntityListener` either for all entities in `orm.xml` or per entity with `@EntityListeners`. The docs say auditing needs `spring-aspects.jar` on the classpath. A bean of type `AuditorAware` in the context is picked up automatically; with several, choose one via `auditorAwareRef`.

## Verify
A `@DataJpaTest` saves an entity under a mock user and asserts the four audit fields; a spec test composes several specifications with `.and` and checks the result rows.
