# gen_statem callback modes and state transitions
**Goal:** model a protocol as a state machine.

```erlang
-behaviour(gen_statem).
callback_mode() -> state_functions.
init([]) -> {ok, locked, #{}}.
locked({call, From}, {button, Code}, Data) when Code =:= 1234 ->
    {next_state, open, Data, [{reply, From, ok}, {state_timeout, 5000, relock}]};
locked({call, From}, {button, _}, Data) -> {keep_state, Data, [{reply, From, bad}]}.
open(state_timeout, relock, Data) -> {next_state, locked, Data}.
```
- `state_functions`: the state must be a `state_name()` (an atom) and one callback function per state, `Module:StateName/3`, is used. `handle_event_function`: the state can be any term and `Module:handle_event/4` is used for all states.
- Event types: external `{call, From}`, `cast`, `info`; time-out types `timeout`, `{timeout, Name}`, `state_timeout`; and `internal`, which can only be generated by the machine itself through the `next_event` action.
- Actions include `{reply, From, R}`, `postpone`, `{next_event, Type, Content}`, the timeout actions and `hibernate`. Transition options of the same type override earlier ones in the list, so the last one wins.
- Returns include `{next_state, S, D, Actions}`, `{keep_state, D, Actions}`, `keep_state_and_data` (same as `keep_state` with the current data) and `repeat_state`; stopping uses `{stop, Reason, D}`.
- State enter calls: return `[state_functions, state_enter]` (or `[handle_event_function, state_enter]`) from `callback_mode/0` to get calls with event type `enter` on each state change.

## Gotchas
- `postpone` is not allowed from a state enter call, since there is no event to postpone; some other transition actions are also not allowed there, so check the `state_enter_result` type for the return values you may use.
- After a state change all postponed events are retried; a change in the server data alone does not retry them, so put anything that changes which events are handled into the state, not the data.
