# Unit testing COBOL paragraphs and programs
**Goal:** repeatable automated checks for batch logic.

- Structure for testability: put business rules in subprograms with a LINKAGE interface (no file I/O inside), so a driver can CALL them with test data.
```cobol
CALL 'CALCTAX' USING WS-AMT WS-RATE WS-TAX
IF WS-TAX NOT = 12.00
    DISPLAY 'FAIL CALCTAX 100@12%' ADD 1 TO WS-FAILS
END-IF
```
- Frameworks exist for both platforms (examples: the open-source COBOL Check on GitHub, IBM zUnit via Developer for z/OS; verify current availability and licences before adopting).
- GnuCOBOL: run test drivers from a shell script and fail on non-zero RETURN-CODE; compare output with `diff` against golden files.
- Golden-file regression: run old and new builds on the same input, diff the output datasets.

## Gotchas
- Programs that read files in the middle of logic need file stubs; use SELECT with a test DD pointing at fixtures.
- Packed data in fixtures should be generated by a program, not typed in a text editor.

## Self-check
Introduce a deliberate bug in CALCTAX and see the driver return a non-zero code.
