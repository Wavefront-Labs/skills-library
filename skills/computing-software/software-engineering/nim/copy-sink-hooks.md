# =copy, =sink, =wasMoved and =dup hooks

Goal: control copying and moving of a resource type.

- ``proc `=copy`(dest: var T; source: T)`` is called for assignments that could not be turned into `=sink` operations. Typical body: guard against self-assignment, `=destroy(dest)`, `wasMoved(dest)`, then duplicate the resource.
- ``proc `=sink`(dest: var T; source: T)`` moves: the resources are stolen from the source and the source is set to its default value. Typical body: `=destroy(dest)`, `wasMoved(dest)`, copy the fields. It does not need a self-assignment check.
- When `=sink` is not provided the compiler uses `=destroy` and `copyMem`; usually `=destroy` and `=copy` are enough.
- ``proc `=wasMoved`(x: var T)`` sets the object to a state that tells the destructor there is nothing to destroy, usually by setting a pointer field to `nil`.
- ``proc `=dup`(x: T): T`` duplicates an object and can be regarded as an optimisation of `wasMoved(dest); =copy(dest, x)`.
- Forbid copies: ``proc `=copy`(dest: var T; source: T) {.error.}`` (no `=` before the pragma) makes any assignment that would copy a compile-time error; then use `move(x)` or `sink` parameters. A custom message such as `{.error: "custom error".}` is not emitted by the compiler.
- `=trace` is for custom container types under `--mm:orc`; without it cyclic data built through the container may leak, but memory safety is not compromised. It is described as more experimental than the other hooks.

Gotchas:
- `x = x` for plain symbols, field access and constant-index access is removed by the compiler; other self-assignments reach `=copy`, so guard it (for example compare the resource field).
- Define a hook before the code that uses the type, otherwise the compiler reports that the hook was seen too late.

Verify: move-only type: `let b = a` errors, `let b = move a` works.
