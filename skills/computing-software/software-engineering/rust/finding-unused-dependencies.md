# Finding unused dependencies

**Goal:** smaller builds and supply chain by dropping crates nobody imports.

Three tools with different trade-offs:

```bash
cargo install cargo-machete
cargo machete                 # fast but imprecise; exit 0 none found, 1 unused found, 2 error

cargo install cargo-udeps --locked
cargo +nightly udeps          # needs Rust nightly to run

cargo install cargo-shear
cargo shear                   # report only; --fix removes unused dependencies
```

- cargo-machete scans source with regex patterns, does not compile, and can miss usages; it does not remove unused dependencies from the workspace root.
- cargo-udeps compiles your project and finds usage from the `target/` directory. Known bugs: it may miss crates used by std and by other dependencies, and it handles crates by name only (two versions of one crate are a problem).
- cargo-shear parses sources with rust-analyzer's parser, also reports misplaced dev/build dependencies and unlinked source files, and needs no compile. Macro-expanded imports are hidden unless you pass `--expand` (nightly, slower, via `cargo expand`).

Handle false positives (a crate used only in build.rs output, doc-tests or macros):

```toml
[package.metadata.cargo-machete]
ignored = ["prost"]             # e.g. used in code generated by build.rs
[package.metadata.cargo-udeps.ignore]
normal = ["if_chain"]           # e.g. used only in doc-tests; also development / build
[package.metadata.cargo-shear]
ignored = ["crate-name"]
```

Workspace-wide ignores go under `workspace.metadata.cargo-machete`, `workspace.metadata.cargo-udeps.ignore` or `workspace.metadata.cargo-shear`. For a crate whose import name differs from its dependency name (such as `rustls-webpki`), cargo-machete offers `--with-metadata` or `[package.metadata.cargo-machete.renamed]` (`rustls-webpki = "webpki"`); `--with-metadata` calls `cargo metadata --all-features` and may modify `Cargo.lock`.

## Gotchas
- cargo-shear `--fix` exits 1 when it found and fixed issues; with `--deny-warnings` warnings (empty or unlinked files, unused optional dependencies) also fail.
- cargo-shear misplaced-dependency detection covers integration tests, benchmarks and examples, not unit tests inside `#[cfg(test)]`.
- An ignore that suppresses nothing is reported as redundant by cargo-shear; remove it.

## Verify
Run your build and tests after `cargo shear --fix`; add `cargo machete` (exit code 1 on unused dependencies) or `cargo shear` as a CI step.
