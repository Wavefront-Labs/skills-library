The page documents three naming conventions for internal metrics.

- `otelcol_` prefix: metrics generated by Collector components carry it. Metrics from instrumentation libraries do not, unless their names are explicitly prefixed. Before v0.106.1, all internal metrics through the Prometheus exporter were prefixed.
- `_total` suffix: the Prometheus exporter can add it to counters, for example `otelcol_exporter_send_failed_spans_total`. The `without_type_suffix` option controls it, and the Collector defaults it to `true`, so counters keep raw names such as `otelcol_exporter_send_failed_spans`. Set `false` to re-enable.
- Unit suffixes: `otelcol_process_uptime` (unit seconds) can become `otelcol_process_uptime_seconds_total`. The `without_units` option controls this and defaults to `true`.

To opt back in to full Prometheus-style names, set both options to `false`:

```yaml
service:
  telemetry:
    metrics:
      readers:
        - pull:
            exporter:
              prometheus:
                host: '0.0.0.0'
                port: 8888
                without_units: false
                without_type_suffix: false
```

Defaults apply whether or not you configure `readers`. Metrics exported through OTLP do not have these suffixes, and the page lists metrics in OTLP form. Views should use the OTLP name, such as `otelcol_process_uptime`.
