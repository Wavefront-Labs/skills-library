Namespaces enforcing the Baseline or Restricted Pod Security Standards reject the operator-generated pods unless container security contexts are patched. Use `spec.containers` and `spec.initContainers` merge entries.

## Prometheus
Patch three containers with the same context:
```yaml
spec:
  serviceAccountName: prometheus
  containers:
    - name: prometheus
      securityContext:
        runAsNonRoot: true
        runAsUser: 65534
        seccompProfile:
          type: RuntimeDefault
    - name: config-reloader
      securityContext: {runAsNonRoot: true, runAsUser: 65534, seccompProfile: {type: RuntimeDefault}}
  initContainers:
    - name: init-config-reloader
      securityContext: {runAsNonRoot: true, runAsUser: 65534, seccompProfile: {type: RuntimeDefault}}
```
If the Thanos sidecar is enabled, apply the same to the `thanos-sidecar` container.

## Alertmanager
Same pattern with containers `alertmanager`, `config-reloader` and init container `init-config-reloader`.

## ThanosRuler
Containers `thanos-ruler` and `config-reloader` with the same security context.

The config-reloader and its init container are generated by the operator too, so they need the same patch as the main container.
