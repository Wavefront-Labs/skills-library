# TraceQL query builder and trace search in Grafana

## Query types in the Tempo data source (Explore > Tempo > Query type)
- **Search** (query builder): drop-downs and text fields generate TraceQL, shown in the builder and copyable to the TraceQL editor. Available by default, no feature toggle. It supports a subset of TraceQL, including some structural operators (>>, >, =~, !=). Filters: Service Name, Span Name, Status, Duration; plus tags scoped to span, resource or unscoped. An empty query is allowed (`{}` lists all traces or spans). Default time range is the last hour.
- **TraceQL editor**: autocomplete for attribute names, scopes and operators; use it for complex filters, structural queries and aggregations. You can also paste a trace ID into the query field.
- **Service Graph**: RED metrics across service connections; requires metrics generation to be configured.
- Use + Add query to combine blocks of different types.

TraceQL pattern: `{ conditions } | pipeline`, where `{}` selects spans and operators like `count()` or `avg()` aggregate.

## Builder to TraceQL examples (generated by the builder)
```
{ resource.service.name = "frontend" && status = error }
{ name = "POST /api/orders" && duration > 500ms }
{ span.http.response.status_code >= 500 }
```
Multiple values for `=` become `||` conditions (`{ name="get" || name="log_results_cache" }`); for `!=` they join with `&&`; for `=~` and `!~` they become one regex (`name=~"get|log_results_cache"`). Duration units: ns, ms, s, m, h.

## Query options
Limit (traces; default 20), Span Limit (spans per spanset; default 3), Table Format (Traces default, or Spans), Step (metrics queries, such as 30ms or 1m), Streaming. Re-run the query after changing options.

## Search is non-deterministic
Tempo scans the time range in parallel and returns the first N matches, so identical searches can differ. Append `with (most_recent=true)`, for example `{ status = error } with (most_recent=true)`, for the most recent matches.

## Streaming
Streaming shows partial results as they arrive, for Search and TraceQL. Control it per data source in the Streaming section of the Tempo data source configuration.

## Traces Drilldown
A queryless app that uses RED metrics derived from traces, automatic visualizations, and saved filter configurations; no TraceQL needed. (Explore menu path and backend requirements were not confirmed on the pages read.)

## Dashboards and other
Add TraceQL panels with the Traces panel; example dashboards are on Grafana Play. In Explore, Import trace uploads a JSON file containing a single trace (first trace used if several). Cross-tenant queries that compare multiple spansets, such as `{ span.attr1 = "bar" } && { span.attr2 = "foo" }`, may miss traces whose conditions are satisfied in separate tenants.
