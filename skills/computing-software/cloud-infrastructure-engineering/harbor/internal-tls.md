By default Harbor components (core, jobservice, proxy, portal, registry, registryctl, trivy adapter) talk over HTTP. Since v2.0 you can enable TLS for this traffic, recommended in production.

In `harbor.yml` set `internal_tls`: `enabled: true` and `dir` to the directory holding the internal certificates.

Generate all certificates automatically with the prepare image:
`docker run -v /:/hostfs goharbor/prepare:<current_harbor_version> gencert -p /path/to/internal/tls/cert`

Bring your own CA by placing its files in that directory named `harbor_internal_ca.key` and `harbor_internal_ca.crt`. You can also supply every component certificate, subject to three constraints:
1. All certificates must be signed by one unique CA.
2. File names and the certificate `CN` must follow the convention: `core.crt` (CN `core`), `job_service.crt` (CN `jobservice`), `proxy.crt` (CN `proxy`), `portal.crt` (CN `portal`), `registry.crt` (CN `registry`), `registryctl.crt` (CN `registryctl`) and `trivy_adapter.crt` (CN `trivy-adapter`), each with a matching `.key` file.
3. Certificates need a SAN extension whose DNS name equals the CN, because Go deprecated self-signed certificates without SAN. Without it Harbor will not start normally.

Gotcha: certificates generated by prepare scripts from before v2.2 lack the SAN extension, so regenerate them after upgrading.
