# ACR connected registry

**Goal:** sites with poor or intermittent connectivity pull images locally, synced from the cloud registry on a schedule.

## Concepts
- Requires a **Premium** cloud registry with **dedicated data endpoints** enabled.
- **ReadOnly** mode: local mirror for pulls (most common). **ReadWrite**: clients can also push locally; synced up.
- A connected registry syncs a defined list of repositories from its **parent** (the cloud registry or another
  connected registry - nested hierarchies for factory networks).
- Clients authenticate to it with **client tokens** (scoped repository permissions), not Entra.

## Create in Azure
```bash
az acr update -n crcorp --data-endpoint-enabled true
az acr connected-registry create -r crcorp -n crsite01 --mode ReadOnly \
  --repository orders payments "acr/connected-registry" \
  --sync-schedule "0 1 * * *" --sync-window PT4H --log-level Warning
az acr token create -r crcorp -n site01-client --repository orders content/read metadata/read
az acr connected-registry update -r crcorp -n crsite01 --add-client-tokens site01-client
```
`--sync-schedule` is a cron expression and `--sync-window` (ISO 8601 duration such as `PT4H`) is required when a schedule is given. Without a schedule the connected registry is treated as always online and syncs every minute. `--mode` defaults to ReadOnly and `--log-level` to Information.

## Deploy on-prem (Arc-enabled Kubernetes)
```bash
az acr connected-registry get-settings -r crcorp -n crsite01 --parent-protocol https --generate-password 1 --yes
az k8s-extension create --cluster-name arc-k8s-site01 --resource-group rg-edge --cluster-type connectedClusters \
  --name crsite01 --extension-type Microsoft.ContainerRegistry.ConnectedRegistry \
  --config service.clusterIP=192.168.0.100 \
  --config-protected-file protected-settings-extension.json
```
The protected settings file is a JSON object `{"connectionString": "<value>"}`; the quickstart builds it from `az acr connected-registry get-settings ... --query ACR_REGISTRY_CONNECTION_STRING --output tsv`. `service.clusterIP` must be an unused address inside the cluster's service IP range. Clients then pull from that address, authenticating with a client token (for example through a `kubectl create secret docker-registry` image pull secret).

## Gotchas
- The sync token password generated by `get-settings` is the connected registry's identity to the parent -
  protect and rotate it.
- Parent and child modes must be compatible: a ReadOnly parent can only have ReadOnly children.
- Every connected registry needs a sync token, and a cloud registry is limited to 20,000 tokens and 20,000 scope maps, which indirectly caps the number of connected registries.
- Repository delete is not supported on a ReadOnly connected registry.
- Artifacts pushed in ReadWrite mode synchronize with the cloud registry.
