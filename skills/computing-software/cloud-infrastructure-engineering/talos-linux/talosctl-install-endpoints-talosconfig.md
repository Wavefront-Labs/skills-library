`talosctl` is the reference implementation of the Talos API. Its config lives in `$HOME/.talos/config`, overridable with the `TALOSCONFIG` environment variable or `--talosconfig`. Like `kubectl` it has contexts; merging a new context is non-destructive and renames a clashing name by appending an index (overwrite is available).

Generated by `talosctl gen config`, a talosconfig looks like:

```yaml
contexts:
  my-cluster:
    endpoints:
      - 192.168.0.10
    nodes:
      - 192.168.0.10
    ca: <base64-encoded-ca>
    crt: <base64-encoded-client-cert>
    key: <base64-encoded-client-key>
```

Top-level `context` names the active entry. `endpoints` is required; `nodes`, `ca`, `crt`, `key`, `auth` and `cluster` are optional. Manage with `talosctl config endpoint <endpoint>` and `talosctl config node <node-ip>`.

**Endpoints vs nodes.** Endpoints are what the client connects to (load balancers, DNS names, IP lists; multiple entries give automatic load balancing and failover). Point them at control plane nodes. Each endpoint proxies to other nodes, but must belong to the same Talos cluster because proxying relies on certificate auth. The target node is better given per command with `-n/--nodes`, and its IP or hostname is as seen by the endpoint, not the client.

With Omni, `endpoints` points at the Omni URL, `auth.siderov1.identity` is set, and `ca`, `crt`, `key` must be empty; download it with `omnictl talosconfig --cluster <cluster-name>`.

`talosctl kubeconfig` safely merges into the default kubeconfig, index-renames conflicts, `--force` overwrites, and a positional path writes elsewhere. Install with Homebrew or `curl -sL https://talos.dev/install | sh`.
