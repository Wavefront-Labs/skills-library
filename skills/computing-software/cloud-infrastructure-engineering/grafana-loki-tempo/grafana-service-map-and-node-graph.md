Goal: a dependency view of your services with health at a glance.

Prerequisites:
1. Service graph metrics generated by the Tempo metrics-generator or Grafana Alloy and written to a Prometheus-compatible backend.
2. That Prometheus data source linked in the Tempo data source under Additional settings > Service graph. Without it, Service Graph queries return empty results.
```yaml
jsonData:
  serviceMap:
    datasourceUid: 'prometheus'
  nodeGraph:
    enabled: true
```
The node graph setting (off by default) shows a node graph above the trace view; it is separate from the Service Graph query type.

Display: Explore > Tempo data source > query type **Service Graph** > run, optionally filter by service. Each circle is a service, with response time and requests per second inside it; colour shows proportions: green success, red fault, yellow errors, purple throttled. Click a service for a context menu of trace and metric links. To investigate a high-error node, query `{ resource.service.name = "<SERVICE_NAME>" && status = error }`.

Metrics read for the graph: `traces_service_graph_request_total`, `traces_service_graph_request_failed_total`, `traces_service_graph_request_server_seconds`, `traces_service_graph_request_client_seconds`.

Service Graph view: a table of RED metrics alongside the graph. It uses different metrics: `traces_spanmetrics_calls_total` (rate and error rate columns) and `traces_spanmetrics_latency_bucket`, or `traces_spanmetrics_latency` for native histograms (duration). So span metrics must be generated too. Clicking a rate, error rate or duration cell opens a Prometheus query with that span name; the links column opens a Tempo query.

Gotchas
- Empty graph: usually no linked Prometheus data source, or no service graph metric generation.
- A cloned provisioned data source shows the Service graph section only when it connects to Tempo successfully.
- Provisioned data sources are read-only in the UI.

## Verify
The graph renders nodes for known services after the query runs; for troubleshooting see the Tempo data source "Service graph issues" page.
