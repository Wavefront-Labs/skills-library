Goal: attach data to a Quadlet container.

`Volume=` is `--volume` with the form `[[SOURCE-VOLUME|HOST-DIR:]CONTAINER-DIR[:OPTIONS]]`. If the source starts with `.`, Quadlet resolves it relative to the unit file's location. If the source ends with `.volume`, the named volume `systemd-$name` is used and the generated service depends on `$name-volume.service`; the matching `.volume` file must exist. The key can be repeated.

`Mount=` is `--mount` with `type=TYPE,TYPE-SPECIFIC-OPTION[,...]`. Special cases: for `type=volume`, a `source` ending in `.volume` uses the volume generated by that file; for `type=image`, a `source` ending in `.image` uses the image generated by that `.image` file. Both add a dependency on the generated service, and the referenced file must exist. Repeatable.

Other storage keys from the page's table: `Tmpfs=/work` (`--tmpfs /work`), `ReadOnly=true` (`--read-only`), `ReadOnlyTmpfs=true`, `ShmSize=100m` (`--shm-size`, form `number[unit]`), and `ImageVolume=` which controls built-in image volumes (default `anonymous`; the old `bind` value is deprecated and aliased to `anonymous`).

`WorkingDir=` overrides the image's WORKDIR via `-w`.
