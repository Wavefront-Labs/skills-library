# Kubebuilder project scaffolding — the layout every Go operator should start from

**Goal:** stand up a new operator with the directory structure, codegen pipeline and
Makefile targets that controller-runtime tooling expects, so `make manifests` and
`make generate` produce correct CRDs/RBAC instead of you hand-writing YAML that
drifts from the Go types.

## 1. Init and create
```bash
kubebuilder init --domain example.com --repo github.com/you/widget-operator
kubebuilder create api --group apps --version v1 --kind Widget \
  --resource --controller
```
This produces:
```
api/v1/widget_types.go       # Spec/Status structs + markers; your schema source of truth
api/v1/zz_generated.deepcopy.go  # generated — never hand-edit, regenerated by `make generate`
internal/controller/widget_controller.go   # Reconcile() lives here
config/crd/bases/              # generated CRD YAML — never hand-edit
config/rbac/role.yaml          # generated from +kubebuilder:rbac markers
config/samples/
cmd/main.go                    # manager entrypoint, scheme registration
PROJECT                        # kubebuilder's own bookkeeping file; do not delete
```
`--group`/`--version`/`--kind` become the API: `apps.example.com/v1, Kind=Widget`.
Picking the domain and group wrong is expensive to rename later (it's in the CRD
name on the cluster, RBAC, and every manifest) — pick the real reverse-DNS domain
you control, not `example.com`, before anyone installs v1 anywhere.

## 2. Markers drive everything — they are not comments
```go
// +kubebuilder:validation:Minimum=1
// +kubebuilder:default=1
Replicas int32 `json:"replicas"`

// +kubebuilder:rbac:groups=apps,resources=deployments,verbs=get;list;watch;create;update;patch;delete
```
`controller-gen` (invoked by `make manifests`/`make generate`) parses these comments
to emit CRD YAML, RBAC YAML, and webhook config. Forgetting to run `make manifests`
after changing a marker is the single most common "why doesn't my validation work"
bug — the Go struct and the cluster's CRD are two different artifacts, synced only
by this generator, only when you run it.
- `make generate` — regenerates `zz_generated.deepcopy.go` (DeepCopyObject etc.,
  required for every type implementing `runtime.Object`) and conversion stubs.
- `make manifests` — regenerates CRD YAML in `config/crd/bases` and RBAC YAML in
  `config/rbac` from markers.
- Run both before every commit that touches `api/` — add them to a pre-commit hook
  or CI check (`git diff --exit-code` after regenerating catches drift).

## 3. Multi-version and multi-group layout
Adding a second version (`v1beta1` alongside `v1`): run `kubebuilder create api` with the
new `--version` for the same group and kind; the book's multiversion tutorial walks through
it, and the conversion details are in
`computing-software.cloud-infrastructure-engineering.kubernetes.crd-versioning-and-conversion-webhooks`.
Multi-group projects (useful when APIs serve different purposes or domains) use
`kubebuilder init --domain <domain> --multigroup` for new projects, giving
`api/<group>/<version>/` and `internal/controller/<group>/`. For an existing
project, `kubebuilder edit --multigroup=true` sets `multigroup: true` in `PROJECT`
and applies the layout to new APIs only; existing APIs must be moved by hand
(see the book's single-group to multi-group migration guide).

## 4. The manager entrypoint
`cmd/main.go` wires: scheme registration (every API type the manager's client needs
to know how to (de)serialize — forgetting `AddToScheme` for a type gives a runtime
"no kind registered" error, not a compile error), leader election flags, metrics/
health probe bind addresses, and `SetupWithManager` calls for each controller and
webhook. For projects initialised with Kubebuilder v4.1.0 or higher the scaffold serves
metrics on port 8443 with authn/authz via controller-runtime's
`filters.WithAuthenticationAndAuthorization`; don't strip the metrics auth filter to
"simplify" unless the operator is genuinely cluster-internal-only with network policy
already restricting access.

## 5. Kustomize overlays, not hand-edited YAML
`config/` is a kustomize base; `config/default` composes CRDs + RBAC + manager
deployment. Environment differences (image tag, replica count, resource limits) go
in overlays (`config/overlays/prod`), not by hand-editing the generated base —
regenerating manifests after a marker change should never require re-applying
manual YAML patches. `make deploy IMG=<registry>/widget-operator:tag` deploys the controller
image to the cluster (the quick start pairs it with `make docker-build docker-push IMG=...`).

## Gotchas
- `zz_generated.deepcopy.go` and `config/crd/bases/*.yaml` are generated — committing
  manual edits to either is guaranteed to be silently overwritten by the next
  `make generate`/`make manifests` and the diff gets confusing in review.
- `kubebuilder create api` run twice for the same GVK is destructive on
  confirmation prompts — always check `git status` is clean before running
  generators so an accidental overwrite is a `git checkout` away from undone.
- Review the scaffolded RBAC in `config/rbac/role.yaml` and the manager scope (see the book's
  manager-scope reference) and tighten it deliberately,
  see `computing-software.cloud-infrastructure-engineering.kubernetes.operator-rbac-and-multi-tenancy-scoping`.
- Renaming a Kind after it's been applied anywhere is effectively a new CRD; there
  is no in-place rename, only create-new/migrate-data/delete-old.

## Verify
- [ ] `make manifests generate` produces no diff on a clean checkout (codegen is
      deterministic and committed, not run only in CI).
- [ ] `make install` applies the CRD; `kubectl explain widget.spec` shows the
      fields and descriptions from the Go struct's markers/comments.
- [ ] `cmd/main.go`'s scheme includes every custom type the controller touches —
      a missing `AddToScheme` surfaces immediately as a runtime error on first use.
- [ ] `make deploy` then `make undeploy` round-trips cleanly with no orphaned
      cluster-scoped resources left behind.
