# Renewing certs embedded in kubeconfigs

## admin.conf and friends
```bash
kubeadm certs check-expiration
sudo kubeadm certs renew admin.conf          # or: renew all
sudo kubeadm certs renew super-admin.conf
sudo kubeadm certs renew controller-manager.conf scheduler.conf
```
Then restart the control-plane static pods (the docs: remove each manifest from
`/etc/kubernetes/manifests/`, wait longer than `fileCheckFrequency`, default 20 seconds, so the
kubelet stops the pod, then move it back). Do this on every control-plane node:
```bash
sudo mkdir -p /root/manifests-parked && sudo mv /etc/kubernetes/manifests/*.yaml /root/manifests-parked/ && sleep 30 && sudo mv /root/manifests-parked/*.yaml /etc/kubernetes/manifests/
```
Copy the new admin.conf to where it was distributed (for example
`sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config`, then fix ownership); copies of the
old certificate stop working when it expires. Prefer `kubeadm kubeconfig user` for anyone who
is not the cluster admin.

## kubelet.conf
A healthy kubelet.conf points at a rotating file instead of embedding data:
```yaml
users:
- name: default-auth
  user:
    client-certificate: /var/lib/kubelet/pki/kubelet-client-current.pem
    client-key: /var/lib/kubelet/pki/kubelet-client-current.pem
```
kubeadm configures the kubelet for automatic client certificate rotation, which is why
`kubelet.conf` is not in the `kubeadm certs check-expiration` list. If rotation failed (errors
such as `x509: certificate has expired or is not yet valid` in the kube-apiserver logs), the
documented repair is: back up and delete `/etc/kubernetes/kubelet.conf` and
`/var/lib/kubelet/pki/kubelet-client*` on the failed node; on a working control-plane node that
has `/etc/kubernetes/pki/ca.key` run
```bash
kubeadm kubeconfig user --org system:nodes --client-name system:node:<node> > kubelet.conf
```
(adjust the cluster name and server endpoint, or pass `--config`); copy it to
`/etc/kubernetes/kubelet.conf` on the node, restart the kubelet, wait for
`/var/lib/kubelet/pki/kubelet-client-current.pem` to reappear, edit `kubelet.conf` to point at it
as above, restart the kubelet again and confirm the node is `Ready`.

## Gotchas
- kubeadm renews its certificates during a control-plane upgrade, and client certificates
  generated by kubeadm expire after 1 year, so clusters not upgraded within a year need
  `kubeadm certs renew`. With a replicated control plane run it on every control-plane node.
- `super-admin.conf` uses `O = system:masters` (bypasses RBAC); do not share it.

## Verify
```bash
kubectl --kubeconfig /etc/kubernetes/admin.conf get nodes
openssl x509 -noout -enddate -in /var/lib/kubelet/pki/kubelet-client-current.pem
sudo kubeadm certs check-expiration
```
