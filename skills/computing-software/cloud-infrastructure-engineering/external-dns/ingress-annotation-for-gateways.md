# The ingress annotation for Istio and Gloo gateways

**Problem:** by default ExternalDNS takes the public IP for a record from a Service of type `LoadBalancer`. In some setups the Gateway's Service is `ClusterIP`, and all public traffic reaches it through a separate Kubernetes Ingress. The Gateway then has no public IP to discover.

**Fix:** annotate the Istio or Gloo Edge Gateway so ExternalDNS ignores the Gateway Service IP and reads the load balancer address from a named Ingress instead.

```yaml
apiVersion: gateway.solo.io/v1
kind: Gateway
metadata:
  name: gateway-proxy
  namespace: gloo-system
  annotations:
    external-dns.kubernetes.io/ingress: gateway-proxy
```

The referenced Ingress (here also `gateway-proxy` in `gloo-system`) supplies the target through its status:

```yaml
status:
  loadBalancer:
    ingress:
    - hostname: k8s-alb-c4aa37c880-740590208.us-east-1.elb.amazonaws.com
```

The value is the name of the Ingress. In the docs example the Ingress sits in the same namespace as the Gateway.

**Gotchas**
- The Gloo `Proxy` object is generated by the Gloo control plane, so you cannot edit it directly.
