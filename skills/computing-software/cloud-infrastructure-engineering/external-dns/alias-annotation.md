# The alias annotation

`external-dns.kubernetes.io/alias: "true"` turns CNAME records generated by the resource into alias records. Setting `A` or `AAAA` creates only that alias type, useful when the alias target is IPv4-only and an AAAA alias would fail.

```yaml
annotations:
  external-dns.kubernetes.io/hostname: app.example.com
  external-dns.kubernetes.io/target: ipv4-only-target.example.com
  external-dns.kubernetes.io/alias: "A"
```

`A` and `AAAA` values are supported only by the AWS Route53 provider.

Only A, AAAA and CNAME endpoints accept it; MX, SRV, TXT and others with the annotation are rejected.

**Per provider**
- **AWS:** relevant only when `--aws-prefer-cname` is set.
- **AWS-SD (Cloud Map):** for a CNAME whose target is a recognised AWS load balancer hostname, `"true"` requests a new service with both `A` and `AAAA` records instead of the default A-only alias. Only the literal `"true"` works. The load balancer must support dual stack. Cloud Map record types are immutable, so ExternalDNS logs a warning when desired types differ from an existing service; recreate the service to apply them.
- **PowerDNS:** CNAMEs become ALIAS records, useful with `expand-alias=yes` on the server. `--prefer-alias` converts all CNAMEs globally.
- **Scaleway:** CNAMEs become ALIAS records; `--prefer-alias` does it globally.
