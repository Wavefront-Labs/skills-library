When a key is attached to a lease, its lifetime is bound to the lease's time-to-live. When the TTL elapses, the lease expires and all attached keys are deleted.

```bash
etcdctl lease grant 60
# lease 32695410dcc0ca06 granted with TTL(60s)
etcdctl put --lease=32695410dcc0ca06 foo bar
etcdctl lease keep-alive 32695410dcc0ca06
etcdctl lease timetolive 32695410dcc0ca06
etcdctl lease timetolive --keys 32695410dcc0ca06
etcdctl lease revoke 32695410dcc0ca06
```

- `lease grant TTL` returns a lease ID. The TTL you pass is a minimum: the lease's actual TTL is at least that and is chosen by the cluster.
- `put --lease=ID KEY VALUE` attaches a key to the lease.
- `lease keep-alive ID` refreshes the lease's TTL; it prints a `keepalived with TTL(60)` line each time it does.
- `lease timetolive ID` prints the granted TTL and the remaining time, for example `granted with TTL(500s), remaining(258s)`; with `--keys` it also lists the attached keys.
- `lease revoke ID` revokes the lease and deletes all of its attached keys; a `get` of an attached key then returns nothing.
- If the lease has expired or does not exist, `timetolive` fails with `etcdserver: requested lease not found`.

The example lease IDs above are from the guide; real IDs are generated by the cluster.
