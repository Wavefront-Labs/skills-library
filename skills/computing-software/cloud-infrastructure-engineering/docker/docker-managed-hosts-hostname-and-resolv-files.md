# Docker-managed /etc/hosts, /etc/hostname and /etc/resolv.conf

Docker generates these three files per container and bind-mounts them over the image's
copies.

## Where they live
```bash
docker inspect -f '{{.HostsPath}} {{.HostnamePath}} {{.ResolvConfPath}}' web
# /var/lib/docker/containers/<id>/hosts  .../hostname  .../resolv.conf
docker exec web mount | grep -E '/etc/(hosts|hostname|resolv.conf)'
```

## What goes in
| File | Content | Controlled by |
|---|---|---|
| `/etc/hostname` | Container hostname (defaults to the container ID) | `--hostname`, Compose `hostname:` |
| `/etc/hosts` | localhost lines, the container's own IP and hostname, `--add-host` entries | `--add-host`, `extra_hosts`, `--hostname`, `--domainname` |
| `/etc/resolv.conf` | `127.0.0.11` on user networks, or host-derived/`--dns` servers on the default bridge; search and options | `--dns*`, daemon `dns*` |

Other containers' names are **not** in `/etc/hosts` on user-defined networks; they resolve via
the embedded DNS. Only legacy `--link` writes peer entries into `/etc/hosts`.

## Why edits disappear
Treat these files as generated by Docker: make lasting changes through flags or Compose keys (`--add-host`, `--hostname`, `--dns*`) rather than by editing them inside the container.

## Replacing them entirely (rarely right)
```bash
docker run -v $PWD/hosts:/etc/hosts:ro app     # bind-mounts your own file over the generated one
```
You then maintain the file yourself. Use only for appliances that require a fixed file.

## Gotchas
- Custom entries in the host's own `/etc/hosts` are not inherited by containers; use `--add-host` (the special value `host-gateway` resolves to the host).
- Containers started with `--network container:<name>` do not support `--add-host`, `--hostname` or `--dns*`.
