# buildx SBOM and provenance attestations

## Turning them on
```sh
docker buildx build --sbom=true --provenance=mode=max \
  -t registry.example.com/app:1.4.0 --push .
# long form
docker buildx build --attest type=sbom --attest type=provenance,mode=max ...
```
GitHub Actions `docker/build-push-action`: `sbom: true`, `provenance: mode=max` (shorthands
for `--attest`). Bake: `attest = ["type=sbom", "type=provenance,mode=max"]`.

Attestations attach to the image index as extra manifests with platform `unknown/unknown`
and annotation `vnd.docker.reference.type=attestation-manifest`, one per platform, wrapped in
the in-toto JSON format. The `local` and `tar` exporters write them as JSON files in the
output root instead.

## Provenance modes
`mode=min` is the default and is added to images automatically; `mode=max` includes everything
in `min` plus more detail, including the full base64-encoded Dockerfile source and build argument
values. `min` leaves out build argument values, secret identities and rich layer metadata.
`mode=max` exposes build argument values - **don't** pass secrets as build args.
`--provenance=false` opts out; the `BUILDX_NO_DEFAULT_ATTESTATIONS` environment variable disables
the default provenance. The provenance `version` parameter takes `v0.2` (default) or `v1`.

## SBOM details
- Generated by the BuildKit Syft scanner plugin (`docker/buildkit-syft-scanner`) in SPDX format.
- By default scans the **final stage** only. Add scanning of earlier stages:
```dockerfile
ARG BUILDKIT_SBOM_SCAN_STAGE=true          # in a stage you want included (or a list of stage names)
ARG BUILDKIT_SBOM_SCAN_CONTEXT=true        # scan the build context too
```
- Custom generator: `--attest type=sbom,generator=<image>`.

## Gotchas
- Attestations need an image index, which the classic image store cannot hold. With the default
  `docker` driver on the classic store the build fails ("Attestation is not supported for the
  docker driver"); turn on the containerd image store, use a `docker-container`, `kubernetes`
  or `remote` builder, or opt out with `--provenance=false --sbom=false`. With the other
  drivers, `--push` keeps attestations; `--load` has the same image store requirement.
- Only stages that are built are scanned; stages that are not dependencies of the target stage
  are neither built nor scanned.

## Verify
```sh
docker buildx imagetools inspect registry.example.com/app:1.4.0 --format '{{ json .SBOM.SPDX }}'
docker buildx imagetools inspect registry.example.com/app:1.4.0 --format '{{ json .Provenance }}'
# multi-platform: --format '{{ json (index .SBOM "linux/amd64").SPDX }}'
```
