# Apigee analytics and API monitoring

## Dashboards
Analyze → API Metrics (proxy performance, error code analysis, cache performance, latency
analysis), Developers, End users. Data latency is minutes; retention per subscription.

## Custom dimensions with DataCollector
```xml
<!-- policy DC-tenant attached in proxy PreFlow -->
<DataCollector name="DC-tenant">
  <Collect ref="request.header.x-tenant-id"/>
  <Capture><Collect ref="request.header.x-tenant-id"/><DataCollector>dc_tenant_id</DataCollector></Capture>
</DataCollector>
```
Create the data collector resource `dc_tenant_id` in the org first, then build Custom Reports
grouped by it (traffic, errors, latency per tenant).

## Stats API
```bash
curl -s -H "Authorization: Bearer $(gcloud auth print-access-token)" \
  "https://apigee.googleapis.com/v1/organizations/<ORG>/environments/prod/stats/apiproxy?select=sum(message_count),sum(is_error),avg(total_response_time)&timeRange=10/17/2026%2000:00~10/18/2026%2000:00&timeUnit=hour"
```
Use for exports to BigQuery or external dashboards; asynchronous queries for large ranges.

## API Monitoring / alerts
- Investigate dashboard: fault codes (`messaging.adaptors.http.flow.ServiceUnavailable`,
  `policies.ratelimit.QuotaViolation`, `steps.oauth.v2.InvalidAccessToken`) by proxy and target.
- Alerts: create on 5xx rate, latency p95, or specific fault codes, notify via Cloud Monitoring
  channels. Cloud Monitoring metrics `apigee.googleapis.com/proxy/request_count`,
  `.../proxy/latencies`, `.../target/response_count` also support standard alert policies.

## Gotchas
- Distinguish proxy errors (Apigee policy faults, 4xx/5xx generated by Apigee) from target errors; fault source shown in analytics.
- Analytics sampling may apply at high volume on some tiers.
- Advanced API Security/abuse detection is a separate add-on.

## Verify
- [ ] Custom report shows per-tenant traffic; a forced target outage triggers the 5xx alert.
