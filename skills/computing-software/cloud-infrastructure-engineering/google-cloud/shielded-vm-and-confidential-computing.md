# Shielded VM and Confidential Computing

**Goal:** no VM boots tampered firmware or kernel without you knowing, and workloads that
must be opaque even to the cloud operator run in hardware-encrypted memory with attestation you verify.

## 1. Shielded VM (the fleet baseline)
Three features:
- **Secure Boot** (`--shielded-secure-boot`): UEFI verifies the digital signature of every boot component (firmware drivers, bootloader, kernel) and halts the boot if verification fails. A failed boot logs `UEFI: Failed to load image` and `Status: Security Violation` to the serial console; disable Secure Boot temporarily to diagnose, then re-enable it.
- **vTPM** (`--shielded-vtpm`): virtual TPM compatible with TPM 2.0, enabling Measured Boot and sealing of secrets.
- **Integrity monitoring** (`--shielded-integrity-monitoring`): compares each boot's measurements with the integrity policy baseline (taken at the first boot) and logs a pass/fail for early boot and late boot. Log events: `earlyBootReportEvent`, `lateBootReportEvent` (each with `policyEvaluationPassed`), `setShieldedInstanceIntegrityPolicy`, `startupEvent`, `shutdownEvent`, `updateShieldedInstanceConfig`, `clearTPMEvent`.
```bash
gcloud compute instances create app-1 --image-family=debian-12 --image-project=debian-cloud \
  --shielded-secure-boot --shielded-vtpm --shielded-integrity-monitoring
gcloud compute instances update app-1 --shielded-learn-integrity-policy    # after a legit kernel update
```
- Alert on integrity failures in Cloud Monitoring or from the Cloud Logging events. An unexpected failure: stop the instance and investigate. An expected one (for example a system update): update the baseline so it matches the latest boot.
- Integrity alerts also appear in Security Command Center.

## 2. Confidential VMs (data in use)
Confidential VM uses hardware-based memory encryption; the keys are generated by and stay in dedicated hardware, inaccessible to the hypervisor. The technology used depends on the machine type and CPU platform you choose.
| Tech | What it adds |
|---|---|
| **AMD SEV** | memory encryption, boot-time attestation through Google's vTPM; on N2D and C3D machine types it supports live migration, unlike the other technologies |
| **AMD SEV-SNP** | adds protection against hypervisor-based attacks such as data replay and memory remapping; attestation reports can be requested from the AMD Secure Processor |
| **Intel TDX** | an isolated trust domain within the VM, with memory encryption |
| **NVIDIA Confidential Computing** | extends the TEE to attached NVIDIA GPUs, combined with SEV or TDX |
```bash
gcloud compute instances create cvm-1 --machine-type=<MACHINE_TYPE> --zone=<ZONE> \
  --confidential-compute-type=SEV_SNP --maintenance-policy=TERMINATE \
  --image-family=<CONFIDENTIAL_CAPABLE_IMAGE_FAMILY> --image-project=<IMAGE_PROJECT>
```
- Supported machine types, images and live-migration behaviour differ per technology: check the Confidential VM supported-configurations page before templating.
- Org policy `compute.restrictNonConfidentialComputing` can require Confidential Computing.
- **Confidential GKE Nodes** enforce Confidential VM for all nodes of a cluster or node pool (`--enable-confidential-nodes`; see the GKE page for the per-technology flags).

## 3. Attestation and Confidential Space
- Confidential VMs support attestation: you can verify the identity and state of the VM so key components are shown not to have been tampered with. See the Confidential VM attestation page for the token flow.
- **Confidential Space** uses Confidential VM so that parties can share sensitive data with a mutually agreed workload while keeping confidentiality and ownership of their data. Use its debug image only for development; see the Confidential Space docs for the production image and workload-identity attribute conditions.

## Gotchas
- Integrity monitoring compares against a baseline learned at first boot: pin and scan images, do not rely on integrity alone.
- A compromised-but-measured boot still passes if it matches the baseline; treat failures as the signal, not passes as proof.
