# Kernel module signing

## Kernel options
| Option | Effect |
|---|---|
| `CONFIG_MODULE_SIG` | kernel checks signatures; with enforcement off, unsigned modules load but taint the kernel (flag `E`) |
| `CONFIG_MODULE_SIG_FORCE` (or `module.sig_enforce=1`) | unsigned/invalid modules are refused |
| `CONFIG_MODULE_SIG_ALL` | in-tree modules signed during `make modules_install` |
| `CONFIG_MODULE_SIG_KEY` | key used for automatic signing (default `certs/signing_key.pem`, generated per build) |
| `CONFIG_SYSTEM_TRUSTED_KEYS` | extra certificates built into the kernel keyring |

## Signing an out-of-tree module
```sh
openssl req -new -x509 -newkey rsa:2048 -nodes -days 3650 -subj "/CN=My Modules/" \
    -keyout MOK.priv -outform DER -out MOK.der
/usr/src/linux-headers-$(uname -r)/scripts/sign-file sha256 MOK.priv MOK.der mydrv.ko
```
Sign **after** stripping: the signature is appended outside the ELF container, so the module
must not be stripped once it is signed.

## Making the kernel trust the key
- **Custom kernels**: add the certificate to `CONFIG_SYSTEM_TRUSTED_KEYS` or sign with the
  kernel's own build key (`CONFIG_MODULE_SIG_KEY`) inside the build.
- **Distro kernels with Secure Boot**: enrol in the Machine Owner Key list:
```sh
sudo mokutil --import MOK.der        # set a one-time password
sudo reboot                          # MokManager blue screen: Enroll MOK, enter password
mokutil --list-enrolled | grep "My Modules"
```

## Troubleshooting
- `insmod: ERROR: could not insert module: Key was rejected by service` -> signature enforced and
  the signing key isn't trusted (not enrolled, or signed with a different key).
- Without enforcement an unsigned or untrusted module still loads but taints the kernel (flag
  `E`, shown in `/proc/modules` and oops reports).

## Verify
- [ ] `dmesg` shows no verification warning on load and the module is not marked `E` in `/proc/modules`.
- [ ] With `sig_enforce`, an unsigned copy is refused and the signed one loads.
