# STM32Cube CMake / VS Code workflow

Recent STM32CubeMX versions generate a **CMake** project (Project Manager > Toolchain/IDE:
CMake). It builds with any `arm-none-eabi-gcc` and works in VS Code (ST's "STM32Cube for
VS Code" extension, or CMake Tools + Cortex-Debug) and in CI.

## What gets generated
```
CMakeLists.txt                     # top level: yours to edit (USER sections kept)
CMakePresets.json                  # Debug / Release presets
cmake/gcc-arm-none-eabi.cmake      # toolchain file: CPU flags, specs, linker script
cmake/stm32cubemx/CMakeLists.txt   # regenerated every time: HAL sources, defines, includes
Core/ Drivers/ startup_*.s  STM32L476XX_FLASH.ld
```
Rule: never edit `cmake/stm32cubemx/`. Add your sources in the top-level file:
```cmake
target_sources(${CMAKE_PROJECT_NAME} PRIVATE
    app/src/app_main.c
    app/src/sensor.c
)
target_include_directories(${CMAKE_PROJECT_NAME} PRIVATE app/inc)
target_compile_definitions(${CMAKE_PROJECT_NAME} PRIVATE APP_VERSION="${GIT_DESCRIBE}")
target_link_libraries(${CMAKE_PROJECT_NAME} stm32cubemx m)
```
Keep application code outside `Core/` too; only small hooks in `USER CODE BEGIN` blocks.

## CLI build (also CI)
```bash
cmake --preset Debug
cmake --build --preset Debug              # build/Debug/<project>.elf
arm-none-eabi-size build/Debug/app.elf
```
Ninja + GCC must be on PATH (or set in the preset). Pin the toolchain version in CI;
different GCC releases change code size and occasionally behaviour.

## Flash
```bash
STM32_Programmer_CLI -c port=SWD mode=UR -w build/Debug/app.elf -v -rst
```
(see stm32cubeprogrammer-cli-scripting). In VS Code, a task wrapping this line is enough.

## Debug in VS Code
- ST extension: provides `stlinkgdbtarget` launch configurations using ST-LINK GDB server,
  with SVD peripheral view and RTOS awareness.
- Cortex-Debug alternative:
  ```json
  { "type": "cortex-debug", "request": "launch", "servertype": "openocd",
    "executable": "build/Debug/app.elf",
    "configFiles": ["interface/stlink.cfg", "target/stm32l4x.cfg"],
    "svdFile": "STM32L476.svd", "runToEntryPoint": "main" }
  ```

## Regeneration discipline
- Commit the `.ioc` and generated code together; review diffs of generated files after each
  CubeMX run (version upgrades change HAL code).
- Pin the CubeMX version and firmware package version (shown in the `.ioc`) in the README.
- If you need flags CubeMX doesn't expose, add them in the top-level `CMakeLists.txt` or the
  toolchain file's user section, not in generated files.

## Verify
- [ ] Fresh clone builds with `cmake --preset Release && cmake --build --preset Release` on CI.
- [ ] Re-running CubeMX generation produces no diff in your own files.
- [ ] Debug launch reaches `main` with peripheral registers visible.
