# Multi-core board targets

Zephyr builds one image per CPU cluster. On HWMv2 the cluster is part of the board target:
```
<board>[@<revision>][/<soc>[/<cpucluster>[/<variant>]]]
nrf5340dk/nrf5340/cpuapp
nrf5340dk/nrf5340/cpunet
nrf5340dk/nrf5340/cpuapp/ns          # non-secure variant
stm32h747i_disco/stm32h747xx/m7
```
The board name plus optional revision and the `/`-separated qualifiers (SoC, CPU cluster, variant)
form the board target.

## Board definition
`board.yml`:
```yaml
board:
  name: widget
  vendor: acme
  socs:
    - name: acme_m4x2
```
Clusters come from the SoC's `soc.yml` (`cpuclusters:`). The board then provides per-cluster
files with the normalized target name:
```
widget_acme_m4x2_cpuapp.dts / _defconfig / .yaml
widget_acme_m4x2_cpunet.dts / _defconfig / .yaml
```
Kconfig symbols like `CONFIG_BOARD_WIDGET_ACME_M4X2_CPUAPP` and `CONFIG_SOC_..._CPUAPP` let code
specialise.

## Building both cores with sysbuild
```bash
west build -b nrf5340dk/nrf5340/cpuapp --sysbuild app
```
`app/sysbuild.cmake`:
```cmake
ExternalZephyrProject_Add(
  APPLICATION remote
  SOURCE_DIR  ${APP_DIR}/remote
  BOARD       nrf5340dk/nrf5340/cpunet                    # board target of the other cluster
)
sysbuild_add_dependencies(IMAGE FLASH app remote)         # optional: adjust flash order
```
`ExternalZephyrProject_Add()` takes `APPLICATION`, `SOURCE_DIR` and an optional `BOARD`; without
`BOARD` the image targets the same board as the main one. Vendor sysbuild configuration may add
such images for you; check your SoC vendor's documentation.

## Sharing resources
- Split peripherals in DT: each cluster's DTS enables only what it owns; memory shared for IPC
  must be described at the same address on both sides.
- IPC: Zephyr's `ipc_service` has `icmsg` and `icbmsg` backends documented under
  `services/ipc/ipc_service`; check the IPC documentation for the backends your SoC supports.
- Flash: sysbuild records the images as domains in a `domains.yaml` it generates and manages, and
  `west flash` uses it to program all of them.

## Gotchas
- Overlay, conf and board file names include the normalized target, e.g.
  `boards/nrf5340dk_nrf5340_cpuapp.overlay` and `nrf5340dk_nrf5340_cpuapp.dts` (`/` becomes `_`).
- A multi-core SoC needs the CPU cluster in the board target.

## Verify
- [ ] Both images built and flashed by one `west build --sysbuild` / `west flash`.
- [ ] IPC shared memory addresses identical in both `zephyr.dts` files.
