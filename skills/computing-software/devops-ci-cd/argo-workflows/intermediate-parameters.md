# Intermediate parameters and approvals
Intermediate inputs let a person supply values mid-run through a `suspend` template; the UI shows text fields or dropdowns. Uses: production approval, or choosing from a list the workflow generated.

Static approval:

```yaml
- name: approval
  suspend: {}
  inputs:
    parameters:
      - name: approve
        default: 'NO'
        enum: ['YES', 'NO']
        description: Choose YES to continue
  outputs:
    parameters:
      - name: approve
        valueFrom:
          supplied: {}
```
Later step: `when: '{{steps.approval.outputs.parameters.approve}} == YES'`.

Dynamic options: a previous step writes JSON with an `enum` key, for example `{"enum": ["db1","db2","db3"]}` to a file exposed through `outputs.parameters.valueFrom.path`; passing that parameter as the suspended step's input renders a dropdown. Any other string renders an editable text field.

Rules:
- The suspended node must declare the same parameters in `inputs.parameters` and `outputs.parameters`.
- Every output on that node needs `valueFrom.supplied: {}`.
- Chosen values are read from `<SUSPENDED_NODE>.outputs.parameters.<NAME>`.

The Jenkins pipeline input step is the analogous feature.
