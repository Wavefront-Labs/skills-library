# Gradle dependency verification

Verification is enabled once `gradle/verification-metadata.xml` exists. Bootstrap or update it and review the diff:

```bash
./gradlew --write-verification-metadata sha256
./gradlew --write-verification-metadata sha256,pgp
./gradlew --write-verification-metadata sha256 help --dry-run
```

The dry run writes `verification-metadata.dryrun.xml` without overwriting. Entries with `origin="Generated by Gradle"` need checking; change the origin to `"Verified"` once reviewed. Bootstrapping trusts whatever your repositories currently serve, so review it. Gradle does not remove unused entries: move the file aside, run `--dry-run` and compare.

Keys: export to the keyring with `./gradlew --export-keys` (files `gradle/verification-keyring.keys` or `.gpg`). Trust keys by full 40-character fingerprint at group level (`<trusted-key id="..." group="com.example"/>`), mark unavailable ones with `<ignored-key>`, configure `<key-servers>` or disable them with `enabled="false"`. Missing keys are cached for 24 hours; `--refresh-keys` refreshes.

Trust artifacts that need no verification with `<trust group="com.mycompany" reason="Internal artifacts"/>` (regex supported, including javadoc and sources jars).

Modes: `strict` (default, fails early), `lenient` (reports only), `off`. Set with `--dependency-verification lenient`, `-Dorg.gradle.dependency.verification=lenient`, or `org.gradle.dependency.verification` in `gradle.properties`. Disabling reduces security: `<verify-metadata>false</verify-metadata>` or `resolutionStrategy.disableDependencyVerification()` per configuration.
