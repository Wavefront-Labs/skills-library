Verdaccio downloads a tarball only from a URL a configured uplink actually serves. Registries that host tarballs on another host than the uplink URL (CDN-backed, such as GitHub Packages or AWS CodeArtifact) can trigger a problem: a package cached by an older Verdaccio that did not record its `_distfiles` bookkeeping, whose tarball is no longer on disk, answers `404 no such file available`.

Recovery:
```
rm -rf /path/to/storage/<package>
```
Verdaccio then re-syncs from the uplink and rebuilds the bookkeeping. Packages whose tarballs are on disk, or served from the uplink's own host, are unaffected.

Observability:
- `log: { level: http }` logs every outgoing tarball download with target URL and uplink.
- A tarball hosted outside any uplink is fetched through an autogenerated proxy named `verdaccio-<package>`.
- A refused off-uplink fetch logs at warn: `refused off-uplink tarball fetch`. Alert on it.
- `log: { format: json }` ships the events to a collector.

Verify: request the package again; Verdaccio re-syncs it from the uplink and rebuilds the bookkeeping.
