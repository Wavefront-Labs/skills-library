Out of the box, TechDocs builds docs inside the Backstage backend and keeps them on its local file system. When you open a TechDocs page, the reader asks the `techdocs-backend` plugin for the entity's static files. The files are HTML, CSS, images and a `techdocs_metadata.json`, generated by MkDocs; JavaScript is removed for security. A list of transformers then modifies the HTML for the reader.

When TechDocs generates docs it first downloads source files from the location in the `backstage.io/techdocs-ref` annotation (the Prepare step).

The recommended production deployment moves building out of Backstage:

1. CI builds the docs with `techdocs-cli generate`.
2. CI publishes the site to cloud storage such as S3 or GCS with `techdocs-cli publish`.
3. Backstage uses `techdocs.builder: 'external'`, so techdocs-backend only fetches docs from that storage and does not generate or publish.

```yaml
techdocs:
  builder: 'external'
  publisher:
    type: 'awsS3'
    awsS3:
      bucketName: 'techdocs-storage'
```

The docs recommend this for stability, scalability and speed: a local file system makes scaling harder, and docs are not built on demand because MkDocs cannot build per page. Reading from cloud storage may add latency, which techdocs-backend can offset with a cache. techdocs-backend needs only read access to storage, while CI needs write access. The how-to guides include a migration path from basic to recommended.
