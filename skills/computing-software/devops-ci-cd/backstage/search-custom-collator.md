To index data Backstage does not cover, create a collator. The recommended path is the built-in template:

```bash
yarn new --select search-collator-module
```

You are prompted for a module ID, which names the package and the generated collator class. The docs example uses `blog-posts`.

The collator class has a `type` that names its index, and produces documents:

```ts
export class BlogPostsCollator implements DocumentCollatorFactory {
  public readonly type = 'blog-posts';

  async getCollator(): Promise<Readable> {
    return Readable.from(this.execute());
  }

  private async *execute() {
    // fetch from your source, then:
    yield { title: 'Post', text: 'Body', location: '/blog/post-1' };
  }
}
```

- `type` names the document type; the frontend predicate matches it against `result.type`.
- Documents need at least `title`, `text` and `location`; extra fields can be added for filters.
- A backend module registers the collator through `searchIndexRegistryExtensionPoint` (from `@backstage/plugin-search-backend-node/alpha`) with a schedule (`frequency`, `timeout`, `initialDelay`).
- Use the injected logger and configured base URLs rather than hard-coding hosts.

On the frontend, register a `SearchResultListItemBlueprint` with a predicate such as `result.type === 'blog-posts'` (generated by `yarn new --select frontend-plugin-module`).
