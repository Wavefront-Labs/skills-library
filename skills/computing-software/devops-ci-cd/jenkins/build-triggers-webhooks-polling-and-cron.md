# Build triggers: webhooks, polling and cron

**Goal:** builds start within seconds of a push, scheduled jobs don't all fire at midnight,
and nothing polls Git every minute across 400 jobs.

## 1. Declarative `triggers {}`
```groovy
pipeline {
  agent any
  triggers {
    cron('H 2 * * 1-5')               // H = hash of job name → spreads load in the window
    pollSCM('H/15 * * * *')           // last resort when webhooks are impossible
    upstream(upstreamProjects: 'libs/core-lib/main', threshold: hudson.model.Result.SUCCESS)
  }
  …
}
```
The Pipeline Syntax reference lists `cron`, `pollSCM` and `upstream` as the built-in declarative
triggers; plugins add others (such as `GenericTrigger` below). For multibranch jobs, prefer the
branch source's webhook handling over per-Jenkinsfile triggers.

`H` syntax: `H H(0-7) * * *` = once daily between 00:00 and 07:59, at a time derived from
the job name; steps work with `H` too (for example `H */4 * * 1-5`). Avoid `0 0 * * *`: many
jobs firing together spike load on agents and SCM, whereas `H H * * *` still runs once a day
but spreads the jobs out.

## 2. Webhooks (the right way)
**GitHub**: the GitHub plugin documents the hook URL as `$JENKINS_BASE_URL/github-webhook/`
(for example `https://ci.example.com/jenkins/github-webhook/`). With github-branch-source,
GitHub App authentication is preferred: its API rate limit scales with organisation size,
whereas a user token is limited to 5000 requests regardless of repository count.

**GitLab (gitlab-branch-source or gitlab-plugin)**: webhook URL
`https://jenkins.example.com/gitlab-webhook/post` (branch source) or `/project/<job>`
(classic plugin) with a secret token. The branch source needs a GitLab **server**
configuration with a personal access token credential.

**Generic git** (any server): Git plugin `notifyCommit` endpoint
`https://jenkins/git/notifyCommit?url=<repo-url>&branches=main&token=<token>` → scans jobs
whose configured repository URL matches `url`. Tokens are generated by an administrator under
*Configure Global Security* → *Git plugin notifyCommit access tokens*; the
`hudson.plugins.git.GitStatus.NOTIFY_COMMIT_ACCESS_CONTROL` property (modes
`disabled-for-polling` and a stricter default) controls unauthenticated requests.

Check the *System Log* with loggers such as `com.cloudbees.jenkins.GitHubWebHook` when a hook
arrives but nothing builds (common: event type not enabled, repo URL mismatch `git@` vs
`https://`, discovery or build strategies exclude the branch).

## 3. Multibranch scan vs webhook
*Scan Multibranch Pipeline Triggers → Periodically if not otherwise run* (e.g. 1 day) is a
safety net for missed hooks, not the trigger. Branch indexing builds every discovered branch
on first scan: add build strategies from the Basic Branch Build Strategies plugin (*Skip initial
build on first branch indexing*, *Regular branches*, *Change requests*, *Named branches*) so
indexing does not launch hundreds of builds (see `branch-build-strategies`).

## 4. Generic Webhook Trigger (any JSON payload)
```groovy
triggers {
  GenericTrigger(
    genericVariables: [
      [key: 'ref', value: '$.ref'],
      [key: 'image', value: '$.push_data.tag', defaultValue: 'latest'],   // JSONPath
      [key: 'repo', value: '$.repository.repo_name']
    ],
    genericHeaderVariables: [[key: 'X-Event-Key']],
    token: 'docker-hub-app',                        // job-specific token → JENKINS_URL/generic-webhook-trigger/invoke?token=…
    tokenCredentialId: '',                          // or a Secret text credential
    causeString: 'Image $image pushed to $repo',
    regexpFilterText: '$ref',
    regexpFilterExpression: '^refs/heads/main$',
    printContributedVariables: true, printPostContent: false
  )
}
```
Use it for Docker Hub/Harbor/Quay image push events, Jira transitions, Artifactory
promotions. Contributed variables are available to the build by name (see the plugin README).
Filter in the trigger (`regexpFilterText` / `regexpFilterExpression`) so non-matching payloads
do not queue a build. Use a token per job, and consider `printPostContent: false` (payloads
can contain secrets). The token can also be sent as a `token` header, and `X-Gitlab-Token` is
detected.

## 5. Upstream/downstream and remote triggers
- `upstream(...)` or classic *Build after other projects are built*; in pipelines prefer
  `build job: 'deploy/app', parameters: [string(name: 'VERSION', value: env.VERSION)], wait: true, propagate: true`.
- Remote API: `curl -X POST -u user:API_TOKEN "https://jenkins/job/app/buildWithParameters?VERSION=1.2.3"`
  (API-token requests are exempt from CSRF protection). Legacy *Trigger builds remotely (token)* allows anonymous
  triggering with a job token — avoid on internet-facing controllers.
- Parameterized Trigger plugin for freestyle fan-out; pipelines use `build` + `parallel`.

## 6. Quiet period and dedupe
*Quiet period* (global default, overridable per Pipeline with `options { quietPeriod(30) }`):
identical queued triggers coalesce, so raise it on jobs that receive bursts of pushes. `disableConcurrentBuilds(abortPrevious: true)`
cancels a running older build of the same branch when a new push lands (multibranch PR
jobs: strongly recommended).

## Verify
- [ ] A push starts a build promptly and the build cause names the push; no `pollSCM` on webhook-enabled jobs.
- [ ] Nightly jobs show different `H`-spread start times.
- [ ] First branch indexing after creating a multibranch job queued no builds (strategy configured).
- [ ] Generic webhook payload filter rejects non-main refs (check *Cause* and contributed variables).
