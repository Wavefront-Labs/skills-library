# Registry-level credentials and expiry

Set the `credentials` property on a registry in `registries.conf` and every image from that registry uses it unless an image-level `pullSecret` overrides it.

Caching: registry credentials are read once at startup and cached until restart. Two remedies:

- use per-image credentials in the `ImageUpdater` CR, which are re-read each update cycle
- set `credsexpire` (for example `12h`; units `s`, `m`, `h`) so the source is re-read after expiry, which suits tokens generated by a script, such as EKS tokens from the aws CLI

Azure ACR with Workload Identity uses an `ext:` script on the registry:

```yaml
registries.conf: |
  registries:
    - name: acr-name
      prefix: acr-name.azurecr.io
      api_url: https://acr-name.azurecr.io
      default: true
      credentials: ext:/app/auth/auth.sh
      credsexpire: 1h
```

The docs build `auth.sh` in a ConfigMap (`argocd-image-updater-auth`) that exchanges the federated token for an ACR refresh token and prints `00000000-0000-0000-0000-000000000000:$ACR_REFRESH_TOKEN`. Then:

- label the controller ServiceAccount and Deployment pod template with `azure.workload.identity/use: "true"` and add client-id and tenant-id annotations
- mount the ConfigMap at `/app/auth` with `defaultMode: 493` so the script is executable
- set env `ACR_NAME`

Scripts are expensive: use them at registry level with `credsexpire` rather than per image.
