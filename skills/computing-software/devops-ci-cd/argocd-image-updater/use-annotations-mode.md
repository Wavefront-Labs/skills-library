# useAnnotations mode for ApplicationSets

For ApplicationSets that template image-updater annotations into hundreds of Applications, one CR can read the annotations:

```yaml
spec:
  applicationRefs:
    - namePattern: "*"
      labelSelectors:
        matchLabels:
          image-updater: my-image-updater
      imagesVerification:
        cosignKey:
          secretName: org-cosign-pubkey
          key: cosign.pub
      useAnnotations: true
```

With `useAnnotations: true`:

- all CR-based configuration is ignored: `images` (including `manifestTargets`), `commonUpdateSettings`, `writeBackConfig`
- the controller reads everything from the Application's `argocd-image-updater.argoproj.io/*` annotations
- only `namePattern` and `labelSelectors` select applications
- `imagesVerification` is still read from the CR and applied after a match

This lets one ImageUpdater CR manage the Applications generated by many ApplicationSets, with each Application supplying its own image configuration via annotations, so no separate CR per Application is needed.

Required annotation: `argocd-image-updater.argoproj.io/image-list`, comma separated, each `alias=image:tag` or `image:tag`, for example `app=myregistry/myapp:v1.0`. Other annotations follow the migration guide mapping (for example `<alias>.update-strategy`, `<alias>.allow-tags`, `write-back-method`, `write-back-target`).

Performance warning: `namePattern: "*"` without `labelSelectors` makes the controller process every Application in the namespace. Always limit with labels.
