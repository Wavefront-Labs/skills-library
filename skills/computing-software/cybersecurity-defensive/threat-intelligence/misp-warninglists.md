# MISP warninglists

Shared intel often contains values that would cause outages if blocked: public DNS resolvers,
top-1M domains, VPN provider ranges, URL shorteners. Warninglists flag those.

## What they are
JSON lists (misp-warninglists repo) of known-benign or non-actionable values: public DNS resolvers, Tranco top-site
lists (top 1M and top 10K), university domains, URL shorteners, TLDs, VPN provider ranges, Tor exit nodes. The repo README
lists every list. Types: `cidr`, `hostname`,
`string`, `substring`, `regex`.

## Enable and update
Use the `Update Warninglists` button in the side menu of the warninglists pages, then enable the lists you want.
CLI: `MISP/app/Console/cake Admin updateWarningLists`.

## Use in workflows
- UI: attributes matching a warninglist show a warning in event views; analysts decide.
- Exports and APIs: `enforceWarninglist: true` in restSearch
  removes matching attributes from feeds to firewalls, DNS RPZ, EDR, SIEM correlation.
- Feeds generated by MISP (cached exports) honour the setting configured for that export.

## Custom warninglists for your environment
Add your own infrastructure so it never gets blocked if it appears in a report:
```json
{
  "name": "ACME corporate infrastructure",
  "version": 1,
  "description": "Our egress IPs, domains and SaaS tenants",
  "type": "cidr",
  "list": ["198.51.100.0/24", "2001:db8:100::/48"],
  "matching_attributes": ["ip-src", "ip-dst"]
}
```
Use the same JSON format as the repo's lists (if `matching_attributes` is unset the list matches any attribute type).
Add a separate `hostname` type list for your domains.

## Review hits
Periodically search attributes with warninglist hits and `to_ids=True`: often the event author should set
`to_ids=False` or remove the attribute. Feed providers with many hits deserve lower trust.

## Gotchas
- Warninglists can hide real attacker use of cloud infrastructure (attackers host C2 on AWS/Azure). For those,
  use full URLs or domain-plus-IP context rather than blocking whole cloud ranges.
- Lists drift; schedule updates.

## Verify
Export via the production feed filter; known values (8.8.8.8, your egress IP) are absent
even when present in source events.
