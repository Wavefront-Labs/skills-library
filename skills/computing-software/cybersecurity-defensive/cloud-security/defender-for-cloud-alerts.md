# Defender for Cloud alerts triage

## Coverage
Alerts are generated by the workload protection plans when threats are found in Azure, hybrid or multicloud environments. They are triggered by advanced detections available when you enable Defender plans for specific resource types, so check plan coverage per subscription first.

## Alert anatomy
- Each alert gives affected resources, the issue and remediation steps, and is mapped to MITRE ATT&CK intent.
- Severity is set by the specific trigger and the confidence that the activity is malicious:
  - High: high probability the resource is compromised, look at once (example: a known credential-theft tool such as Mimikatz).
  - Medium: probably suspicious, usually machine learning or anomaly based (example: sign-in from an unusual location).
  - Low: may be a benign positive or a blocked attack (example: log clear, often routine admin work).
  - Informational: usually part of an incident, worth a look in context of other alerts.
- An **incident** is a collection of related alerts, giving one view of an attack. Correlation combines signals across resources and can rule out activity that only looks like an attack step.
- Alerts stay in the portal for 90 days, even if the resource was deleted.

## Suppression rules
- Matching alerts get status Dismissed: they still appear in the alerts list but no longer notify or show in active views.
- Roles: Security admin or Owner create and delete; Security reader or Reader view.
- Scope: subscriptions via portal or REST API; management groups via Azure Policy.
- A rule only applies to alert types that have already triggered at least once.
- Portal path: Security alerts > Suppression rules > Create new suppression rule. Choose subscriptions, Custom alert types or All, optional entity conditions, a name (2-50 characters, starts with a letter or number, only dashes and underscores as symbols), enabled or disabled, a reason, a comment, expiry (Custom date or None) and optionally Simulate.
- From an existing alert: Take action > Suppress similar alerts > Create suppression rule.
- Deleting a rule does not change the status of alerts it already dismissed.
- Keep rules narrow (alert type plus entity) and give them an expiry.

## Export
- Download CSV report on the alerts dashboard is a one-time export.
- Continuous export (Environment settings > subscription > Continuous export) streams alerts and recommendations to a Log Analytics workspace or Event Hubs; the target can be in another subscription or tenant. Choose data type, filters (for example only high-severity alerts) and frequency: streaming, or weekly snapshots (look for the field IsSnapshot).
- Needs Security Admin or Owner on the resource group plus write permission on the target. Log Analytics supports records up to 32 KB only.
- The Microsoft Sentinel connector streams alerts into Sentinel.

## Verify
- [ ] Defender plans enabled on every subscription that holds workloads.
- [ ] Suppression rules reviewed regularly, each with an expiry or a recorded reason.
- [ ] Exported alerts arrive in the workspace or SIEM.
