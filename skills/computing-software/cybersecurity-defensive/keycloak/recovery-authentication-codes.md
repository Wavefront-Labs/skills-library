# recovery authentication codes
Recovery codes are a number of sequential one-time passwords (currently 12) generated by Keycloak, used as a second factor by adding the Recovery Authentication Code Form authenticator to a flow. The user is asked for the next code in order; once entered it is removed and the next one is required at the next login. They normally back up another 2FA method such as the OTP Form or WebAuthn Authenticator, for a broken or unavailable device.

Setup:
1. *Authentication* > *Required Actions* tab: make sure *Recovery Authentication Codes* is Enabled. Toggle *Default Action* On to have all new users register codes at first login.
2. Optional: in the *Configure OTP* required action enable *Add recovery codes* to ask for codes automatically.
3. Optional: configure the Recovery Authentication Codes required action. *Warning Threshold*: when a user has fewer remaining codes than this, the Account Console warns them to set up a new set.
4. Browser flow: *Authentication* > *Browser* flow > execution *Recovery Authentication Code Form* inside the *Browser - Conditional 2FA* sub-flow; change the requirement from Disabled to Alternative. The OTP Form and the Recovery form are then alternatives; if a user has both credentials, the highest-priority one is shown and *Try Another Way* offers the other.

Creating the credential: users request codes with the required action (from the Account Console, or assigned by an administrator). It generates the list and offers print, download or copy; the checkbox *I have saved these codes somewhere safe* must be checked to complete setup. Codes can be re-created at any time.

Brute force detection applies to password, OTP and recovery codes.
