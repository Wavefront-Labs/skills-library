# Writing OKRs and running the quarterly cycle

**Goal:** turn strategy into a few measurable quarterly commitments per team, then
score and learn from them instead of letting them become a forgotten spreadsheet.

## 1. Anatomy
- **Objective:** qualitative, directional, memorable. "Make month-end close painless."
  No numbers in the objective.
- **Key results (2–4 per objective):** measurable *outcomes* that prove the objective
  was met. "Close completed by working day 5 (from 9)". "Manual journals per close
  < 40 (from 120)".
- **Initiatives:** the work you'll do (projects, tasks). They live *under* KRs, not
  as KRs.

The test for a KR: *if we hit this number but nothing else changed, would we be happy?*
If "launch the new tool" could be hit with nobody using it, it is an initiative.

## 2. Good KR checklist
- Has a **baseline and a target** ("from X to Y"), with the data source named.
- Is an outcome or leading indicator, not an activity count ("50 calls made").
- Is within the team's influence in one quarter.
- Has one **owner** (a person, not a team).
- Is not a business-as-usual metric already tracked in a KPI dashboard — OKRs are for
  change; KPIs are for health. Keep them separate and limit health metrics to a
  "must not get worse" guardrail where relevant.

## 3. Committed vs aspirational
Label each OKR:
- **Committed:** expected to be fully delivered (score 1.0); missing it is an
  escalation.
- **Aspirational ("stretch"):** ~0.6–0.7 is a good result.
Mixing these without labels causes either sandbagging or demoralisation.

## 4. Cascading without bureaucracy
- Company sets 3–5 objectives. Teams write their own OKRs that *contribute* to them;
  don't copy company KRs down as team objectives mechanically.
- Expect ~half of team OKRs to come bottom-up. Then run an **alignment check**:
  dependencies between teams written explicitly ("needs Finance systems by week 4").
- Limit: ≤3 objectives per team; more means no priorities.

## 5. The quarterly cadence
| When | Activity |
|---|---|
| Weeks −3 to −1 | Draft, review with leadership, alignment/dependency session |
| Week 1 | Publish all OKRs where everyone can see them |
| Weekly | 15-minute check-in: confidence per KR (e.g. 1–10 or red/amber/green), blockers |
| Mid-quarter | Re-plan initiatives; do not quietly change KRs (if you must, note why) |
| Last week | Score each KR 0.0–1.0, retrospective: what did we learn? |

Scoring: linear against the target is simplest (from 9 days to 5; achieved 6 → 0.75).

## 6. Retrospective questions
What moved the KR? What didn't work? Was the target well-calibrated? What carries over?
Write the answers down; they're the input to next quarter's draft.

## Gotchas
- **Tying OKR scores to bonuses** — widely reported to drive sandbagging; most OKR
  guidance advises against it. *(Practitioner consensus, not a rule.)*
- Too many KRs, set once and never looked at again — the weekly check-in is
  non-negotiable.
- Writing tasks as KRs: "Hire 2 analysts" → outcome version "Backlog < 2 weeks".
- No baseline: you can't score "improve NPS" without knowing the current value.

## Verify
- [ ] Each objective has 2–4 KRs, each with baseline, target, data source and owner.
- [ ] No KR is an activity or a launch; initiatives are listed separately.
- [ ] Each OKR is labelled committed or aspirational.
- [ ] Cross-team dependencies are written down and acknowledged by the other team.
- [ ] Weekly confidence check-ins happened and an end-of-quarter score + retro exists.
