# Range architecture and size curves

**Goal:** decide *what* goes in the range and *how much of each*, so the
assortment hits the sales plan with the right choice for each store, and the
size mix doesn't leave you with a rail of XLs at markdown. Written for fashion
and general merchandise buyers/planners; grocery category management uses the
same logic with planograms.

## 1. Start from the financial plan
From the season plan per category: sales £/$, units, average selling price
(ASP), target margin, closing stock. These cap everything else.
`Units ≈ planned sales ÷ ASP`.

## 2. Breadth vs depth
- **Breadth** = number of options (style-colours); **depth** = units per option.
- Options = units ÷ target depth. Depth per option is set by store count ×
  minimum presentation (e.g. 120 stores × 6 units to look full = 720 units minimum
  for a full-chain option).
- Too broad: thin, broken displays and high markdown. Too deep: boring range and
  stuck stock. Bias **depth** on proven core lines, **breadth** on fashion/trend
  tests in fewer stores.
- Benchmark options per category against last year's sell-through by option count.

## 3. Good-better-best price architecture
- Set 3–4 price points per category with clear steps (e.g. £15 / £25 / £40);
  each step should give a visible reason (fabric, detail, brand).
- Allocate options and units across tiers from last year's sales mix by price
  band, adjusted for strategy (trading up, opening-price entry).
- Avoid gaps where competitors sell volume; comp-shop to check.
- Hero/opening-price lines drive traffic; middle tier usually drives volume.

## 4. The option plan
A grid per category: rows = options; columns = tier, price, cost, intended
margin, colour, fabric, delivery month, store grade, units. Check totals against
the financial plan and colour balance (core vs fashion colours).

## 5. Size curves from data
1. Pull sales by size for comparable styles over 1–2 seasons, **from full-price
   periods with good availability** — sales in sizes that were out of stock are
   understated, and markdown sales over-sell leftover sizes.
2. Compute size mix % per category (and per store cluster if data allows).
3. Round into **size ratios/packs** suppliers can ship (e.g. S:M:L:XL = 1:2:2:1
   in a 6-pack). Check total pack size versus store depth.
4. Review after each season: compare sell-through by size; tweak curves where
   a size sells out early or remains at end.

## 6. Localise by store cluster
- Cluster stores by sales volume (grade A/B/C) and by customer profile/climate
  (e.g. coastal vs city, tourist, ethnic mix, size profile).
- Assign which options each cluster gets: A stores full range, C stores core only;
  climate-sensitive lines by region.
- Use cluster-specific size curves where materially different (some regions sell
  more large sizes).

## Gotchas
- Last year's sales reflect last year's range: if you didn't stock it, the data
  can't show demand for it.
- Too many price points confuse customers and inflate options.
- Minimum order quantities (MOQs) per colour can force depth you don't want — negotiate
  or drop the colour.
- **Uncertain:** depth/presentation minimums vary widely by format; use your own fixture standards.

## Verify
- [ ] Options × depth reconciles to planned units and sales.
- [ ] Each price tier has a clear reason to step up and a planned share.
- [ ] Option plan totals match the financial plan; colour/fabric balance checked.
- [ ] Size curves built from full-price, in-stock sales and rounded to shippable packs.
- [ ] Each store cluster has an assigned range and depth.
