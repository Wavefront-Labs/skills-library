# Live chat and messaging support

**Goal:** fast, human-sounding text conversations — several at once — that solve the
issue in one sitting and, where it fits, help the customer buy.

## 1. Live chat vs messaging
- **Live chat** (website widget): synchronous; the customer is waiting now. Response
  time in seconds to a minute matters.
- **Messaging** (WhatsApp, Messenger, SMS, in-app): often asynchronous; customers reply
  hours later. Conversations stay open; context must survive across agents.
Set expectations accordingly ("We usually reply within an hour").

## 2. Managing concurrency
- Typical concurrency is 2–4 live chats per agent (depends on complexity; billing or
  tech issues need lower). Don't accept more than you can track.
- Use the platform's visual cues (colour/timer per chat) and sort by waiting time.
- Acknowledge every new chat within your target (e.g. under 30–60 s): greet by name,
  show you've read their first message.
- When you need time: say so with an estimate ("Checking your order now — about 2
  minutes"). Silence over a minute feels like abandonment.
- Close finished chats promptly to free a slot; don't keep "just in case" chats open.

## 3. Canned responses — use, then personalise
- Build saved replies for frequent answers (order status steps, return instructions,
  password reset), each short and scannable.
- **Always edit**: insert their name, their specific detail, and remove irrelevant parts.
  A pasted wall of text with the wrong product name destroys trust.
- Keep a personal snippets file for phrasing you use often.

## 4. Writing tone in text
- Short paragraphs, one idea each; numbered steps for instructions.
- Mirror the customer's formality. Emoji only if they use them and brand voice allows.
- Avoid ALL CAPS, exclamation-mark strings, and blunt one-word replies ("No.").
- Re-read before sending — the message is the whole experience.
- Confirm understanding before solving: "Just to check — the discount code is
  showing as expired at checkout?"
- Use links and screenshots/GIFs to show, not describe, UI steps.

## 5. Bot handoffs
If a chatbot answers first: read the bot transcript fully before typing; never ask
the customer to repeat what they told the bot. Open with "I can see you've asked about
X — I'll take it from here."

## 6. Chat-to-sale
On pre-sale chats (product questions, sizing, shipping costs):
1. Answer the question precisely.
2. Ask one qualifying question ("What will you mostly use it for?").
3. Recommend one option with a reason; send the product link.
4. Remove the last obstacle (shipping time, returns policy, discount if policy allows).
5. Ask: "Would you like me to add that to your cart / send a checkout link?"
Track chat conversion (orders within e.g. 24h of a chat) where the platform supports it.

## 7. Wrap-up
Summarise what was done and what happens next, ask "Is there anything else?", then close
with a thank-you. Tag the conversation (reason, outcome) and update the customer record.

## Gotchas
- Typing indicators that run for minutes and then a short reply look bad — draft offline for long answers.
- Sharing personal data (full card numbers, passwords) in chat: never request it; redact if sent.
- Messaging-platform rules (e.g. WhatsApp Business template and reply-window rules)
  limit what you can send after a period of inactivity — check current platform policy.

## Verify
- [ ] Every new chat acknowledged within target time.
- [ ] Concurrency kept within the agreed limit; no chat silent over a minute without an update.
- [ ] Canned responses personalised (name, specifics) before sending.
- [ ] Bot transcripts read before taking over.
- [ ] Chats tagged with reason and outcome; pre-sale chats ended with a clear offer to buy.
