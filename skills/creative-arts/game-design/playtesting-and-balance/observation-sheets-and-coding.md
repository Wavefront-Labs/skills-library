# Observation sheets and coding

**Goal:** structured notes that can be compared across testers and sessions.

## Procedure
1. **Decide what you will watch** from the playtest questions: confusion, rules errors, decision points, engagement, emotional reactions, downtime.
2. **Create a code list** of 8-15 short codes, for example: C confusion, R rules question, E error (rules misplay), L laugh or visible enjoyment, B boredom or phone check, W wow moment, D long deliberation, H help requested. Add the player seat number.
3. **Lay out the sheet:** columns for time (or round/turn), player, code, and a free-note line; a header with build ID, tester IDs, date, observer.
4. **Pilot the codes** in a practice session and merge or define any that observers apply differently; write one-line definitions.
5. **Observe silently** and record a short factual note with each code. Use turn or round numbers when timestamps are impractical.
6. **Tally after the session:** counts per code, per phase and per player; mark clusters (several C codes at one rule).
7. **Combine with video or audio** if consented, to resolve disputed codes.

## Gotchas
- Too many codes slow you down and make you miss play; keep the list short.
- Two observers on the same session reveal coding differences; reconcile them.
- Do not interpret on the sheet; note facts and interpret later.

## Verify
- [ ] Code list defined with one-line meanings.
- [ ] Sheet records build, tester, and observer.
- [ ] Tallies produced and cross-checked against a second source.
