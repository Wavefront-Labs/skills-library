# Teaching a board game: script

**Goal:** a repeatable spoken teach that gets new players playing quickly and correctly,
for demos, conventions, playtests and the rulebook's quick-start.

## Script order (a common structure used by experienced demoers)
1. **Theme in one sentence:** who you are and what you're doing.
2. **How to win:** the goal and the end condition. Players need this to interpret
   everything else.
3. **The turn in one sentence:** "On your turn you take one action: build, trade or
   move."
4. **Components walk-through** only as they relate to the turn (point at them).
5. **Details in play order:** each action, briefly; one example each.
6. **Scoring / end game details.**
7. **"What you can ignore for now":** edge cases and rarely used rules, explained when
   they come up.
8. **Practice round or open-hand first turn** if the game allows.

## Writing the script
- Time target: aim for a short teach (minutes, not tens of minutes) for light/medium
  games; heavier games still benefit from "teach the first round, then the rest".
- Use the game's own terms consistently (same words as cards/rulebook).
- Write examples using actual components.
- List the 3 most common mistakes from playtests and address them explicitly.

## Testing
1. Teach it to new players with a stopwatch.
2. Note questions asked in the first rounds; each repeated question means a missing or
   unclear script line.
3. Watch for rule errors in the first game; fix the script to prevent them.
4. Iterate until the teach time and first-game error rate meet your targets.

## Gotchas
- Teaching every rule upfront overloads; defer edge cases.
- Strategy tips during the teach can feel like spoilers; offer one or two optional hints.
- A script that only the designer can deliver isn't finished; test with another teacher.

## Verify
- [ ] Script follows goal -> turn -> details order.
- [ ] Teach time measured with new players.
- [ ] Common first-game mistakes addressed in the script.
- [ ] Another person delivered it successfully.
