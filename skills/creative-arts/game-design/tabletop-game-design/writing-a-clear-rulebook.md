# Writing a clear rulebook — so the box teaches the game without you

**Goal:** a rulebook that lets a group who has never met you set up and play
correctly. Most tabletop games are first explained by a stranger reading your text
aloud; if they get it wrong, the game gets the blame.

## 1. Use the order players need
1. **Overview (one paragraph):** theme, number of players, play time, and *how you
   win*. The goal comes first because every later rule is read in its light.
2. **Components list** with counts and a small picture of each — players check the box
   against it.
3. **Setup:** numbered steps plus one labelled diagram of a 2- or 4-player table.
   Note what changes with player count.
4. **Turn structure:** the sequence of phases/actions as a short numbered list. Then
   expand each step in that same order.
5. **End of game and scoring:** trigger, final scoring, tiebreaker (always include one).
6. **Advanced/variant rules**, then **glossary/index**, then **FAQ** for edge cases.
Put a one-page **turn summary / player aid** on the back cover or a separate card.

## 2. Language rules
- **Define keywords once and use them exactly.** If "discard" means face-up to the
  discard pile, never also write "throw away" or "remove". Bold keywords at definition.
- Separate similar verbs that differ in effect: *discard* vs *remove from game*,
  *draw* vs *take*, *may* (optional) vs *must*.
- One rule per sentence where possible. Write in second person, present tense:
  "You draw two cards."
- State **timing** explicitly: when an effect happens, how long it lasts, and what
  happens on conflict. Include a golden rule such as "if a card contradicts the
  rulebook, the card wins" if that's how your game works.
- Number rules sections so FAQs and cards can reference them.

## 3. Examples are not optional
After each non-trivial rule, add a short **example** with a picture: "Ana has 3 wood
and plays the Mill…". Examples catch ambiguity in your own wording — if the example is
hard to write, the rule is unclear.

## 4. Blind playtest the rulebook (the real test)
- Give the rules and components to a group who hasn't played. **Say nothing.** Watch
  and take notes; don't answer questions — write them down.
- Every question asked, every rule played wrong, every page flipped back and forth
  marks a fix. Repeat with a new group after each major revision.
- Also test reading aloud: one person teaches the others straight from the book.

## Gotchas
- **Designer blindness:** you no longer see the assumptions you've stopped noticing.
  Only blind tests reveal them.
- **Iconography without a key** — every icon needs a legend in the book and ideally on
  a player aid.
- **Last-minute card text changes** get out of sync with the rulebook. Keep one
  source-of-truth spreadsheet for card text, generated into both.
- **Edge cases on the BGG forums** after release usually trace to one undefined timing
  window; ask "what if two things trigger at once?" for every reactive card.
- This method reflects common practice among tabletop publishers and reviewers; page
  layout conventions vary by publisher.

## Verify
- [ ] Section order: overview with win condition → components → setup → turn → end.
- [ ] Every keyword defined once, bolded, and used consistently (search the text).
- [ ] Setup diagram and a turn-summary player aid exist.
- [ ] Each complex rule has a worked example.
- [ ] At least two blind playtests completed, questions logged and resolved in text.
- [ ] A tiebreaker is stated.
