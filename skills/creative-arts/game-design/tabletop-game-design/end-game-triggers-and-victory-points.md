# End-game triggers and victory points

**Goal:** games end at a satisfying time, the winner is clear, and the last turns are
tense rather than procedural.

*Building Blocks* devotes a chapter to game end and victory: how games end (round
limit, resource exhaustion, race to a threshold, elimination) and how winners are
determined.

## End triggers
| Trigger | Pros | Cons |
|---|---|---|
| Fixed rounds | predictable length, planning | can end before climax or drag |
| Player-triggered threshold (first to X) | race tension, pace control by players | leader may rush; trailing players can't stop it |
| Resource/supply exhaustion | organic | length varies |
| Sudden death condition | drama | can feel abrupt |
| Track-based (doom track) | co-op tension | needs tuning |

## Victory point design
1. **List VP sources** and estimate their share of a winning score; diverse sources
   enable different strategies ("point salad" if too many trivial sources).
2. **Make VP conversion a decision:** VP that compete with engine growth (Dominion's
   victory cards clog the deck) create tension between building and scoring.
3. **Hidden vs open scoring:** open lets players target the leader; hidden reduces
   leader-bashing but can make the end anticlimactic. Partially hidden (end-game bonus
   cards) is common.
4. **End-game bonuses** (majority awards, set completion) create late-game swings; keep
   them visible so players can plan.

## Final round fairness
- If a player triggers the end, finish the round so everyone has equal turns (common
  convention), or state otherwise.
- Last-turn "nothing to do" problems: ensure final actions still matter.

## Tie-breakers
Always specify: e.g. most remaining resources, then shared victory. Untested
tie-breakers cause real table arguments.

## Verify
- [ ] End trigger chosen and game length distribution measured.
- [ ] VP source share estimated and checked in playtests (multiple winning strategies).
- [ ] Final round rule and tie-breakers written in the rulebook.
