# Project templates

**Goal:** start every new book (or every book in a series) with your preferred
structure and settings already in place. Scrivener ships templates (Blank, Novel, Short
Story, Screenplay, Non-Fiction...) chosen at **File > New Project**; you can make your own.

## Build the starter project
1. Start from Blank or a built-in template.
2. **Binder skeleton:** Draft (with an example chapter folder and scene), Characters,
   Places, Research, Notes, Cut Material, Front Matter, Templates folder.
3. **Document templates** (see `document-templates`).
4. **Metadata:** Label (renamed, e.g., POV), Status values, keyword list, custom metadata
   fields (see `labels-and-status`, `custom-metadata-fields`).
5. **Section types** and default types by structure (Project Settings).
6. **Compile:** a saved compile format for your usual output (Shunn manuscript, EPUB)
   — formats saved as "My Formats" are available in all projects; project-specific settings travel with the template.
7. **Targets:** typical draft target and options.
8. **Project Properties:** author name, contact details used by placeholders.
9. Remove placeholder text you don't want to inherit.

## Save as template
- **File > Save As Template**: give it a title, category (e.g., Fiction), description and
  icon. It appears in the template chooser.
- Manage or delete templates via the template chooser's Options/settings.
- To share between computers, export the template file from the chooser and import it on
  the other machine.

## Series variant
For a series, make a template that includes the **series bible** documents
(characters, world, timeline) so each new book starts with them — or keep the bible in
one separate project and link to it.

## Gotchas
- Saving a project with a real draft as a template — every new project then carries it.
- Updating the template doesn't change projects already created from it.

## Verify
- [ ] Template appears in File > New Project under your category.
- [ ] New project from it has binder skeleton, metadata, section types and compile format.
- [ ] No leftover draft text.
