# Automatic backups and restoring

**Goal:** never lose a manuscript to a corrupt project, a bad edit or a failed disk. Menu names below follow Scrivener 3; shortcuts and exact labels differ between the Mac and Windows editions and by version, so confirm in the app's Help or the official user guide.

## Set up
1. Open Scrivener's **Preferences > Backup** (on Windows it is under File or Tools > Options > Backup).
2. Turn on **Back up automatically on project close**; consider also backing up on manual save, if offered.
3. Choose **number of backups kept** (a rolling limit) and whether to **zip** them (smaller, one file each).
4. Choose a **backup folder outside the project and outside the cloud-synced folder you use for the project itself**. Prefer a different drive or a cloud-sync folder for the backups only.
5. **Back up now**: File > Back Up > Back Up Now (manual) before heavy editing, merging, or major compile changes.

## Restore
1. Close the open project.
2. Locate the backup (File > Back Up > Manage Backups, if your edition has it, or browse to the backup folder). Backups are timestamped.
3. If zipped, unzip to a new folder. **Do not overwrite** the live project with the backup; open the restored copy and inspect it.
4. If it is the version you want, rename it and use it as the live project; keep the old one until you are sure.
5. Check word counts, the binder and a few scenes.

## Policy
- Keep multiple generations; corruption may only be noticed later.
- Add an **external** copy (separate drive, offsite or cloud) in addition to Scrivener's backups.
- Test a restore once, before you need one.

## Gotchas
- Backups made only on close do not protect a long session; back up manually or rely on separate file history.
- Never run two machines on one project file in a sync folder; see `creative-arts.literary-writing.scrivener.syncing-ios-and-external-folders`.

## Verify
- [ ] Backup location and number are set and confirmed in preferences.
- [ ] A test restore opens and shows current-looking content.
- [ ] A copy exists off the machine.
