# Line editing while preserving voice

**Goal:** sentences that read better while still sounding like the author. Line editing
(EFA: attention to style, flow, word choice and clarity at the sentence and paragraph
level) is where editors most easily impose their own voice.

## Before editing: profile the voice
Read the first 20-30 pages without marking. Note:
- Sentence length and rhythm habits; fragments as style?
- Diction level, slang, profanity, dialect.
- Punctuation habits (dashes, semicolons, comma splices used deliberately?).
- Humour, irony, lyricism.
Write a short voice note; edit *toward* that voice, not toward yours.

## Classify every potential change
| Type | Action |
|---|---|
| Error (grammar, unintended ambiguity, continuity) | Fix, explain if not obvious |
| Clarity problem (reader will misread) | Fix or query |
| Rhythm/flow problem against the author's own norm | Suggest an alternative, in their style |
| Your preference only | **Leave it** |

## Technique
- **Minimal intervention:** the smallest change that solves the problem — reorder,
  cut, or replace one word before rewriting a sentence.
- Use the author's own vocabulary and constructions for replacements.
- For repeated problems, fix two or three instances and add a comment ("This pattern
  recurs; I've adjusted a few — you may want to apply it elsewhere") rather than silently
  rewriting all.
- Offer options in comments for important passages ("Option A... / Option B...").
- Leave deliberate rule-breaking in dialogue and voice-driven narration.

## Communication
- Explain *why* in comments for any non-obvious change; authors accept changes they understand.
- Invite rejection: Track Changes lets authors accept or reject each change; say so in
  the cover note and mean it.

## Gotchas
- "Correcting" stylistic fragments and run-ons that are the voice.
- Homogenising all characters' dialogue into standard English.
- Rewriting whole paragraphs — that's ghostwriting, not line editing, unless agreed.

## Verify
- [ ] Voice note written before editing.
- [ ] Each change is an error fix, clarity fix, or voice-consistent suggestion.
- [ ] Comments explain non-obvious changes.
- [ ] A sample page reads like the author, not the editor.
