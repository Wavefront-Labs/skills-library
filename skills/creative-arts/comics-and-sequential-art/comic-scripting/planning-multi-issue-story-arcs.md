# Planning multi-issue story arcs

**Goal:** an arc whose issues each satisfy, that also reads as one book in the trade
collection, with subplots that pay off on time.

## Arc length
Arcs are commonly 4-6 issues because collected editions (trade paperbacks) gather
roughly 100-150 pages. Ask the editor the planned collection size before plotting.

## Build the spine first
1. **Arc question** (one line): what changes for the lead by the end?
2. **Issue turns**: one line per issue saying what this issue's turn is.
   ```
   #1  Mara takes the job (inciting)           -> ends: the client is dead
   #2  Suspects; Teo lies to her               -> ends: Teo's badge revealed
   #3  Midpoint: the cops are the gang          -> ends: Mara arrested
   #4  Low point and escape                     -> ends: ledger found
   #5  Climax at the harbour; status quo changed
   ```
3. **Escalation check**: each issue's stakes are bigger or more personal than the last.
4. The midpoint issue changes the nature of the conflict, not just its size.

## Subplots
- Track in a grid: rows = subplots, columns = issues; each cell = the beat (or blank).
- A subplot needs at least 3 touches (set up, develop, pay off) or cut it.
- Seed the next arc in the last 1-2 issues with a small, unresolved beat.

## Trade readability
- Avoid recaps that will read repetitively in sequence; keep them to one caption or
  the recap page that the trade can drop.
- Make issue-ending hooks resolve quickly at the start of the next issue; in a trade
  they are read back to back.
- Covers become chapter breaks; consider that rhythm.

## Gotchas
- A first issue that is only setup loses monthly readers; the inciting turn should be
  in #1.
- Midpoint sag in #3 of 5 is the most common failure.
- Crossover/event tie-ins can impose issue beats; get them from the editor early.

## Verify
- [ ] One-line turn for every issue, escalating.
- [ ] Subplot grid shows set-up, development and pay-off.
- [ ] Arc length matches planned collection.
