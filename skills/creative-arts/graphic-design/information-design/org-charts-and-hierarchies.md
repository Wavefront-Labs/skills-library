# Org charts and hierarchies

**Goal:** an accurate, scannable diagram of who reports to whom, maintainable as the organisation changes.

## 1. Gather the data
Keep a table: person, role, manager, team, status (vacant, interim). Build the chart from it so updates are changes to data, not layout.

## 2. Pick a layout by size
- **Top-down tree:** classic; works to about 3-4 levels and a limited width.
- **Left-to-right tree:** gives long titles more horizontal room and fits wide pages.
- **Stacked/vertical lists under a manager:** compresses large teams of peers.
- **Pages or drill-down:** for large organisations show top levels on one page and detail on others; keep consistent templates.
- **Radial or sunburst:** attractive but harder to read; use only for exploration.

## 3. Conventions
- **Solid line** = direct (line) reporting; **dotted line** = indirect or matrix; state this in a key.
- Same box size for same level; level rank expressed by vertical position, not box size.
- Order peers consistently (by function, then alphabetical).
- Mark vacancies and interim holders visibly but quietly (outline box, "Vacant").
- Use colour for function or location sparingly with a legend; do not rely on colour alone.

## 4. Typography and spacing
- Name in a heavier weight, role in regular, both short; truncate titles in the chart and keep full titles in the data.
- Use equal spacing, orthogonal connectors (right angles), and align siblings on a common baseline. Avoid crossing lines.

## 5. Production
- Diagram tools (for example a dedicated charting application) auto-layout from data; export to SVG or PDF and refine in Illustrator or InDesign only when needed. If edited by hand, record that the file is detached from the data.
- Add the **as-of date** and an owner.

## Failure modes
- Hand-built charts that drift out of date.
- Overlapping connectors at wide levels.
- Implying seniority by box size.
