# Schedule reports: DOOD, one-liner and revisions

**Goal:** the reports that drive cast deals, budgets and every department's planning -
accurate, readable, and reissued cleanly when the schedule changes.

## 1. Day Out of Days (DOOD)
A grid of elements (cast first; also background, vehicles, animals, equipment) by
shooting day, with codes:
| Code | Meaning |
|---|---|
| SW | Start work (first day) |
| W | Work |
| WF | Work finish (last day) |
| SWF | Start and finish same day |
| H | Hold (paid, not working - between work days) |
| T | Travel |
| R / F | Rehearsal / Fitting |
| D / PU | Drop / Pick up |
Totals per actor: work, hold, travel, holidays - the **paid days**. Under SAG-AFTRA
rules an actor is paid consecutively from start to finish unless a **drop/pick-up**
is allowed (once per actor, with a gap of more than 10 days, under the Basic Agreement
- check current terms). Producers use the DOOD to negotiate deals and budget cast;
schedulers reorder strips to reduce holds.
In MMS: *Reports > Day Out of Days*; choose categories, date range and options (drop/
pick-up threshold).

## 2. One-liner and shooting schedule
- **One-line schedule**: one line per scene (scene #, I/E, set, D/N, description, pages,
  cast IDs) grouped by day with day-break totals. The crew's daily map.
- **Shooting schedule** (full): every scene with all breakdown elements listed - for
  departments.
- **Advance schedule** on call sheets (next 2-3 days) pulls from the same board.
Header with production title, schedule version/colour and date.

## 3. Revising the schedule
- Save a **copy** of the board before changes (MMS: save as new file or board
  version).
- Make changes; re-run one-liner and DOOD; compare cast totals (cost impact).
- Issue as a **revised schedule** with version label (colour or "Rev 3 - date"), a
  cover note listing changes, to all departments; the call sheet's advance schedule
  updates the same day.
- Notify cast agents of changed work dates (contract implications).

## Gotchas
- DOOD with unnecessary holds because two scenes for a day-player are a week apart.
- Publishing reports from an un-saved or wrong board version.
- Changing the schedule without telling locations and cast agents.
- One-liners without version/date on them.

## Verify
- [ ] DOOD run for cast and key elements; holds minimised; drop/pick-ups valid.
- [ ] One-liner and full schedule produced with version and date.
- [ ] Board copy saved before every revision; change memo issued.
- [ ] Cast work-date changes reported to agents and producers.
