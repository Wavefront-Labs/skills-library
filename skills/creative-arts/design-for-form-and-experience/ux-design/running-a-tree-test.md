# Tree testing

A tree test evaluates the findability of a text-only hierarchy: participants are given tasks and navigate a collapsed tree of labels to where they would look. It isolates the IA from visual design and search.

## Prepare
1. **Build the tree** exactly as proposed (all levels or the parts you are testing), text only, with the real labels.
2. **Write tasks;** each describes a goal in the user's words without using terms that give away the answer, for example "You want to change your delivery address" and not "find Delivery Settings".
3. **Mark correct answers:** one or more acceptable destinations per task.
4. **Recruit** representative users: a qualitative test needs only a few participants, a quantitative one a larger sample.
5. **Pilot** with at least a few moderated sessions before collecting the bulk of the data.

## Read results
- **Task success rate:** reached a correct item.
- **Directness:** found it without backtracking.
- **Time and path:** how long each find took and where people went wrong; if they clicked several categories you can see which they tried first.
- A new tree is quick to test by editing the spreadsheet, so iterate.

## Act
Rename labels that attract wrong clicks; move items; retest changed parts.

## Verify
- [ ] Task wording avoids label keywords.
- [ ] Failed tasks are explained by path analysis.
- [ ] A revised tree is retested.
