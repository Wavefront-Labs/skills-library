# Future-state journey map

A future-state (to-be) journey map shows how the experience should work after changes. Start from a current-state map (see `...ux-design.mapping-a-current-state-customer-journey`).

## Steps
1. **Review pain points and opportunities** on the current map; choose a focus (a stage, a persona).
2. **Set the vision:** use the experience vision (see `...ux-design.writing-an-experience-vision`) and principles to judge ideas.
3. **Ideate fixes** for each stage (workshop, how-might-we questions; see `...ux-design.writing-insight-statements-and-how-might-we-questions`).
4. **Redraw the map** with the same lanes as the current one: stages, actions, thoughts, emotions, touchpoints and channels, plus a **backstage lane** (staff actions, systems, policies) for what must change in the organisation (see `...ux-design.drawing-a-service-blueprint`).
5. **Mark the changes:** new, changed, removed steps; the expected emotional curve.
6. **Prioritise** with impact and effort (see `...ux-design.building-a-ux-roadmap-with-impact-effort-prioritisation`).
7. **Test:** storyboard or roleplay it, then prototype key moments with users.

## Gotchas
- A pretty to-be map with no backstage owner is a wish.
- Do not drop pain points that are costly to fix without saying so.

## Verify
- [ ] Every change links to a pain point or opportunity on the current map.
- [ ] Each new touchpoint has an owner and a feasibility note.
- [ ] A test plan exists for the riskiest moment.
