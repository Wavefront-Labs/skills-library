# Thematic analysis and coding

Braun and Clarke describe thematic analysis as identifying, analysing and reporting patterns (themes) in qualitative data, in six phases. UX teams use a lighter version.

## Phases
1. **Familiarise:** read or listen to all transcripts and notes; jot first impressions.
2. **Generate initial codes:** label small chunks of data (a code is a short description such as "avoids typing on mobile"). Code inductively (from the data) rather than from your hypotheses; allow more than one code per chunk.
3. **Search for themes:** group related codes into candidate themes; draw thematic maps or use sticky notes or a board (see `...ux-design.affinity-diagramming-research-notes`).
4. **Review themes:** check each theme against the coded extracts and against the full dataset; split, merge or drop.
5. **Define and name themes:** write a sentence for each that states what it captures; avoid topic labels like "navigation" in favour of findings like "users distrust the menu labels".
6. **Report:** a few themes with quotes and clips, linking to design implications.

## Practice tips
- A second coder on a sample, then discuss differences, improves trustworthiness (formal inter-rater statistics are optional for UX work).
- Keep a codebook (code, definition, example) and keep data traceable to participant IDs.
- Counts such as "5 of 8 participants" are fine for description, not for generalisation to a population.

## Verify
- [ ] Each theme has at least two supporting participants and quotes.
- [ ] The codebook is up to date.
- [ ] Negative or contradicting cases are reported.
