# Reference library organisation

A library is useful only if you can find an image when you need it. Keep the system simple enough to maintain.

## Schema
1. **Top-level folders by use, not by date:** Materials, Colour, Form, Interfaces, Environments, Typography, People and context, Competitors.
2. **Tags for cross-cutting qualities:** mood words, colours, era, source type, project, licence status (cleared, internal-only, unknown).
3. **File naming:** `topic_descriptor_source_year.ext` and avoid spaces and special characters; do not rename originals you cite from a URL without keeping the URL.
4. **Metadata:** embed or record creator, source URL, licence and date saved (a spreadsheet, or fields in your tool).

## Tools (choose one and stick to it)
- Local asset managers (Eagle, Adobe Bridge, or similar) for tagging and search.
- PureRef for infinite-canvas boards of local images.
- Are.na, Pinterest, Milanote or Notion for linked, shareable collections.
- A shared drive with a README for team libraries.

## Routine
- **Triage weekly:** process the inbox: keep, tag, or delete.
- **Deduplicate** and remove low-resolution copies.
- **Back up** the library (and the metadata).
- **Review licences** before reuse.
- **Share carefully:** share cleared and internal-only sets separately.

## Verify
- [ ] You can find three images for a given mood in under two minutes.
- [ ] Every image has a source and licence status.
- [ ] A backup exists and has been restored once.
