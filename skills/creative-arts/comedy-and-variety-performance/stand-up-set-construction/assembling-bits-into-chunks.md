# Assembling bits into chunks

**Goal:** a set built from modules rather than a single fragile sequence.

## What a chunk is
A group of two to five bits on one subject or one comic stance, with its own start, build and strongest closing line. A chunk can usually stand alone for 2-4 minutes.

## Procedure
1. List your bits on index cards (one bit, one card, a one-line title).
2. Group by subject or by the attitude they share.
3. Within a group, order from the strongest accessible opener to the biggest closer; see `building-a-bit-arc-from-premise-to-peak`.
4. Write the transition line into the next chunk; see `writing-segues-between-bits`.
5. Time each chunk and note its runtime on the card.

## Using chunks
- Cut a set to length by dropping whole chunks, not by trimming each bit.
- Reorder per room: the safest strong chunk first for a hard room, a riskier one for an attentive crowd.
- Build to a longer slot by adding chunks. See `building-a-set-to-5-10-20-and-40-minutes`.

## Gotchas
- Chunks that depend on each other's setup cannot be reordered: break the dependency or keep them as one chunk.
- Weakest chunk placed second often looks like a dip; place it where a callback can rescue it.

## Verify
- [ ] Each chunk runs standalone with its own closer.
- [ ] You can drop any single chunk without leaving a dangling reference.
