# Mapping an argument — see the structure, then test it

**Goal:** turn a paragraph, op-ed or debate into a diagram where every claim is one box
and every arrow is one inferential step, so you can see which step is weak instead of
reacting to the whole thing at once.

## 1. Find the main conclusion first
Ask "what is this person ultimately trying to get me to accept?" Write it as one
complete, declarative sentence at the top of the page. If you cannot state it in one
sentence, you have two arguments — map them separately.

## 2. One claim per box, full sentences
- Each box holds exactly one claim, written so it could be true or false on its own.
  "Because of costs" is not a claim; "The scheme costs more than it saves" is.
- Strip rhetoric ("obviously", "as everyone knows") — note it separately as a flag.
- Paraphrase charitably: the strongest reasonable version of what was said.

## 3. Linked vs convergent — the step most people get wrong
- **Linked (co-premises):** the reasons only support the conclusion *together*.
  "All mammals breathe air" + "Whales are mammals" → join them in one bracket with a
  single arrow. Remove either and the support collapses.
- **Convergent (independent reasons):** each reason supports the conclusion *on its own*,
  so each gets its own arrow. Knocking one out leaves the others standing.
- Test: "If I deleted this box, would the other box still give *any* reason?" If yes,
  convergent; if no, linked.

## 4. Supply the hidden premise
Most arrows hide a co-premise that makes the step work. "It's natural, so it's healthy"
needs "Whatever is natural is healthy". Add it as a dashed box. Hidden premises are where
weak arguments usually fail, and making them explicit is half the value of mapping.
(See mind-self.critical-thinking-and-argumentation.informal-logic.reconstructing-hidden-premises.)

## 5. Add objections and rebuttals
- An **objection** attacks either a premise (is it true?) or an arrow (does it follow?).
  Mark it in a different colour or with a "but" label, pointing at what it attacks.
- A **rebuttal** answers an objection, so it points at the objection box.
- Keep depth honest: stop at 3–4 levels unless the decision really needs more.

## 6. Evaluate, box by box and arrow by arrow
For each box: acceptable? (common knowledge, cited, or itself argued for below).
For each arrow: if the premises were true, how much would they raise confidence in the
claim above — strong, weak, none? The conclusion is only as strong as its weakest
*linked* chain, but a convergent conclusion survives the loss of one branch.

## Tools
Paper or a whiteboard is fine and fastest. Software options (check current versions
yourself): Argdown (plain-text syntax that renders maps), Kialo (pro/con debate trees),
general diagram tools such as draw.io or Miro. Rationale/bCisive were classic dedicated
tools; their current availability is unconfirmed.

## Gotchas
- **Boxes holding two claims** ("X is costly and unpopular") hide a convergent structure —
  split them.
- **Mapping the speaker, not the argument:** "She's biased" is not a box on this map; it is
  at most an objection about source reliability.
- **Over-mapping:** a 40-box map for a dinner-table disagreement is procrastination. Map
  the main line and the one contested step.
- **Assuming the map proves anything:** it shows structure; truth of premises is a
  separate check (see source-evaluation).

## Verify
- [ ] The main conclusion is one sentence at the top.
- [ ] Every box is a single claim that could be true or false on its own.
- [ ] Linked premises share one arrow; independent reasons have their own.
- [ ] At least one hidden premise has been made explicit (there almost always is one).
- [ ] Each objection points at a specific box or arrow.
- [ ] You can name the weakest box or arrow and say why.
